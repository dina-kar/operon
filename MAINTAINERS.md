# Maintainers

Loams has a **flat maintainer structure**: every maintainer has the same role, the same rights and the same vote. There is no project lead, no tie-breaker and no senior tier.

## How maintainers work

- **Decisions are made by maintainer consensus.** Discuss on the issue or pull request; if maintainers disagree, they keep talking until they agree, and a change that one maintainer objects to does not land. The [decision log](docs/design/13-decision-log.md) records design decisions.
- **Any maintainer can merge `dev` into `main`** (the release branch), once the required checks pass.
- **Any maintainer can add trusted people** to the `committers` and `maintainers` teams. Use that to recognize sustained, high-quality work; tell the other maintainers when you do.
- **Any maintainer can review and merge** pull requests to `dev`, except their own (get another maintainer or committer to review).
- Maintainers follow the [Code of Conduct](CODE_OF_CONDUCT.md) like everyone else.

[GOVERNANCE.md](GOVERNANCE.md) describes the wider model and the contributor ladder.

## Reaching the maintainers

- **Questions, ideas and partnerships:** [GitHub Discussions](https://github.com/ostrium-labs/loams/discussions). Use the Ecosystem & Partners category for anything about building on Loams ([ECOSYSTEM.md](ECOSYSTEM.md)).
- **Bugs and RFCs:** [issues](https://github.com/ostrium-labs/loams/issues).
- **Security issues:** a private Security Advisory, as described in [SECURITY.md](SECURITY.md). Don't use Discussions for these.
