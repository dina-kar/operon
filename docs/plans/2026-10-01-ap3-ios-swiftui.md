# AP3 — Loams for iOS (SwiftUI, connect-swift) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (identifiers, categories, payload fields), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Planned** (2026-10-01). **Slot: track AP, after AP0 Task 6 and in parallel with AP2.** Repository **`ostrium-labs/loams-mobile`**, directory `ios/` (§37 §9, D439). Branches `ap3-t<N>`, stacked. Tasks 1–9 run against `loams-apps-mock`; a real server needs the unified auth plan (D111), AP4 and the push gateway; Task 10 needs the Apple Developer Program membership (Q420). Builds need macOS runners (GitHub-hosted `macos-15` or later); nothing in this plan runs on the Linux development machine except the `LoamsCore` tests through Swift on Linux (Ruling 6).

**Goal:** Ship **Loams for iOS**, the SwiftUI counterpart of AP2 with the same screens and the same guarantees: pairing by QR, typed code or `ASWebAuthenticationSession`, approvals decided with a Secure Enclave key behind Face ID or Touch ID, operations, jobs and runs, an inbox, and end-to-end-sealed APNs notifications decrypted in a Notification Service Extension. Every call is Connect-RPC through **connect-swift**, generated from the shared protos (D128, D438). No web view, no KMP (D433).

**Architecture (Swift packages inside `ios/`):**
- **`LoamsCore`** (pure Swift, Foundation and CryptoKit only): models, the pairing payload parser, `DecisionClaims` canonicalization, the watch-resume state machine, the HPKE unsealer, error reasons. Same behaviour as AP2's `:core`; the golden fixtures are shared.
- **`LoamsProto`**: SwiftProtobuf messages and connect-swift clients generated by `buf` from the pinned loams ref with `buf.gen.swift.yaml` (AP0 Task 6), `Visibility=Public`, `GenerateAsyncMethods=true`, `GenerateCallbackMethods=false`.
- **`LoamsData`**: `ProtocolClient` construction (`URLSessionHTTPClient`, Connect protocol, binary codec), trust (a `URLSessionDelegate` that evaluates pins), keychain and Secure Enclave keys, the token store, the SwiftData cache, repositories exposing `AsyncSequence`s and `@Observable` models.
- **App target `Loams`**: SwiftUI, `NavigationStack`, one `@Observable` view model per screen.
- **Extension `LoamsNotificationService`** (`UNNotificationServiceExtension`): unseals, rewrites title and body, sets the category. Shares a keychain access group and an app group with the app.
- **Test targets:** `LoamsCoreTests` (swift-testing), `LoamsDataTests`, `LoamsUITests` (XCUITest), `LoamsConformance` (runs AP0's scenarios against `loams-apps-mock` on the macOS host, no simulator needed for the network layer).

**Tech Stack:** Xcode current stable (Task 0 pins it), Swift 6 language mode with strict concurrency, **iOS 17 minimum** (CryptoKit HPKE and the Observation framework need iOS 17; Q431); **connect-swift 1.2.x** (1.2.3, 2026-05-21, stable) with `Connect` (URLSession) only, not `ConnectNIO` (no gRPC needed); swift-protobuf; SwiftData; CryptoKit (Secure Enclave P-256, HPKE); LocalAuthentication; AuthenticationServices; VisionKit `DataScannerViewController` for QR (iOS 16+, first-party); UserNotifications. No third-party dependency beyond connect-swift and swift-protobuf.

## Global Constraints

- **Native only.** SwiftUI; the only browser surface is `ASWebAuthenticationSession` for sign-in.
- **ATS on, no exceptions** except `NSAllowsLocalNetworking` in the Debug configuration for the mock. Pinned instances are evaluated in the delegate; system trust is never relaxed for other hosts.
- **Keychain items** use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` (refresh tokens, HPKE private keys) so the NSE can read them while the phone is locked after first unlock; nothing is synchronizable to iCloud Keychain; nothing goes in `UserDefaults` except non-secret settings.
- **No secret in logs** (`os_log` with `.private` for every dynamic value), no crash reporter by default (Q433), approval and pairing screens hide content in the app switcher snapshot.
- **Commit areas:** `ios`, `ci`, `docs`.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **Identifiers:** bundle id `dev.loams.app`, extension `dev.loams.app.notification-service`, app group `group.dev.loams.app`, keychain access group `<TEAM>.dev.loams.app.shared`, notification categories `APPROVAL` (action `REVIEW`, foreground, `.authenticationRequired`), `OPERATION`, `JOB`, `SECURITY` | Matches AP2's identifiers; categories mirror Android's channels | Bundle ids are permanent once on the store |
| 2 | **Two Secure Enclave keys per paired instance**, P-256 (the only curve the Secure Enclave offers, so DPoP and the decision proof use ES256, which AP0 Ruling 7 allows): `dpop` with access control `.privateKeyUsage` only (background refresh works), and `decide` with `[.privateKeyUsage, .biometryCurrentSet]` (or `.userPresence` when the user has no biometry, so the passcode works), signing `DecisionClaims` only | A stolen refresh token cannot approve; re-enrolling Face ID voids the decision key | Devices without a Secure Enclave do not exist at iOS 17 |
| 3 | **Trust:** as AP2 Ruling 3. Pins are evaluated in `urlSession(_:didReceive:completionHandler:)` with `SecTrustEvaluateWithError` for the hostname and the SPKI hash comparison; `jkt` is pinned at the application layer | Same guarantees on both platforms | None |
| 4 | **Background:** no persistent stream in the background. APNs wakes the NSE, which only unseals and displays; a `BGAppRefreshTask` syncs the inbox opportunistically; streams run only while a screen is visible | iOS forbids long-lived background sockets for this kind of app | Without push permission, approvals arrive only when the app is opened; the UI says so |
| 5 | **Approve from a notification:** the `REVIEW` action opens the app on the approval sheet, and the decision signs with the `decide` key (Face ID prompt); no background approve. Same as AP2 Ruling 6 | The decision needs the user present | One extra tap |
| 6 | **`LoamsCore` builds on Linux** (Foundation and swift-crypto shims behind `#if canImport(CryptoKit)`), so its tests and the shared golden fixtures run in the monorepo's or the mobile repo's Linux CI too | Faster feedback; one source of truth for canonical bytes with AP2 and the mock | swift-crypto's HPKE API must match CryptoKit's; Task 2 checks it |
| 7 | **No offline decisions** (AP2 Ruling 7) | Same reason | None |

## Review Focus

1. **The decision key really needs the user.** Tests: Task 6 (`decide_key_requires_biometry_access_control`, `biometry_change_invalidates_decide_key` on device).
2. **Pins cannot be bypassed.** Tests: Task 3 (`pin_mismatch_is_hard_stop`, `hostname_checked_with_pin`).
3. **The NSE leaks nothing and fails closed.** Tests: Task 8 (`nse_unseal_round_trip`, `nse_failure_shows_generic_text`).
4. **The canonical bytes match AP2's and the mock's.** Tests: Task 6 (`decision_claims_golden_bytes`).

### Task 3: `LoamsData` — transport and trust

**Produces:**

```swift
public final class Clients: Sendable { public let instance: Loams_Instance_V1_InstanceServiceClientInterface; public let devices: …; public let approvals: …; public let operations: …; public let notifications: …
  public init(instance: InstanceRecord, tokens: TokenSource, trust: TrustPolicy) }
public enum TrustPolicy: Sendable { case system; case pinned(spki: Set<String>, host: String) }
```

**Semantics:** `ProtocolClient(httpClient: URLSessionHTTPClient(configuration:), config: ProtocolClientConfig(host:, networkProtocol: .connect, codec: ProtoCodec(), interceptors: [Auth, DPoP, AcceptLanguage]))`; a dedicated `URLSession` per instance with the trust delegate; `waitsForConnectivity = true` for unary calls, not for streams; the delegate's `willPerformHTTPRedirection` refuses every redirect (§37 §6.4's rule).

**Tests:** the AP2 Task 3 cases against the mock over TLS with a self-signed certificate.

**Commit:** `ios: add Connect clients and the trust policy`.

### Task 4: Keys, tokens and pairing

**Semantics:** Rulings 2–3; §37 §7.2. QR scanning with `DataScannerViewController` (`.barcode(symbologies: [.qr])`); typed-code pairing with the 6-word fingerprint; browser sign-in at the instance's **Authentik** with `ASWebAuthenticationSession` (`prefersEphemeralWebBrowserSession = false`, so Authentik's session cookies work), then an RFC 8693 exchange at the Loams gateway with a DPoP proof; Authentik's device-code flow (RFC 8628) as in AP2 Task 4 and the universal link `https://loams.dev/app/auth/callback` (`apple-app-site-association`, Q281), falling back to the `loams` custom scheme callback. Keys from `SecureEnclave.P256.Signing.PrivateKey(accessControl:)`; their `dataRepresentation` is stored in the keychain. App Attest (`DCAppAttestService`) assertion is sent at pairing when available (the server may ignore it; Q-row).

**Tests:** `qr_pairing_round_trip_with_mock`; `typed_pairing_shows_fingerprint_words`; `pairing_code_reuse_is_pairing_used`; `tokens_are_this_device_only` (keychain attributes); `revoked_device_clears_keys_and_tokens`.

**Commit:** `ios: pair by QR, typed code or browser sign-in`.

### Task 8: Push and the Notification Service Extension

**Semantics:** §37 §7.4. Request authorization (`.alert, .sound, .badge`; `.timeSensitive` for approvals when the user allows it), register for remote notifications, generate an X25519 HPKE key per instance (keychain, shared access group), call `RegisterPushTarget` with provider `APNS`, the device token, the bundle id, `environment` (sandbox for Debug, production for Release), and the HPKE public key. The APNs payload is `{"aps":{"alert":{"title":"Loams","body":"New activity"},"mutable-content":1,"category":"APPROVAL"|…,"thread-id":"<instance_id>"},"v":1,"i":"<instance_id>","n":"<notification_id>","s":"<base64 sealed>"}`; the NSE unseals within its time budget and replaces the alert, or leaves the generic text on any failure.

**Tests:** `nse_unseal_round_trip`; `nse_failure_shows_generic_text`; `apns_payload_has_no_plaintext_fields` (the mock's push log); `approval_category_has_review_action`.

**Commit:** `ios: receive sealed push notifications`.
