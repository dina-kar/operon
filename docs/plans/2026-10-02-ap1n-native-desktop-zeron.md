**Goal:** A native Loams Desktop on zeron's engine and GPUI UI that (1) signs in at Authentik, (2) talks Connect to a local or remote loams server, (3) manages local stacks through the `loams` CLI, (4) puts **Loams Bot** (and the **Loams Software Factory** loop it drives) in zeron's chat, with native panels for approvals, collaboration objects and runs, and (5) ships signed, with an upstream-tracking routine that keeps the fork cheap.

**Architecture** (§37 §18.3):
- **Three seams, no embedding.** Supervise the `loams` CLI (JSON contract, D283); call the server with generated Connect clients; spawn Loams Bot as an ACP agent from zeron's own engine. Zeron's engine and the loams engine never share a process.
- **All Loams logic in crates without GPUI** (`loams-brand`, `loams-link`) so it tests in seconds on three operating systems. GPUI appears only in `loams-panels` (Tasks 6 and 8).
- **Additive or one-line.** Inherited files change only through marked hooks and compiler-demanded match arms, each with a row in `LOAMS.md`'s ledger.
- **Fail closed.** No contact with zeron's backend, no installation of zeron's binaries, no Loams token in any agent subprocess or browser.

**Tech Stack:** Rust (zeron's `rust-toolchain.toml`, stable; edition 2024) and GPUI as pinned by zeron (`zeronsh/zui`); `connectrpc` 0.9.1 and `buffa` 0.9.2 with the `buf` CLI and `protoc-gen-buffa`, `protoc-gen-buffa-packaging` and `connectrpc-codegen` 0.9.0; `keyring` 4.2; `webbrowser` 1; `reqwest` (zeron's rustls build); `rcgen` for TLS tests (Task 4); `ed25519-dalek` for manifest signatures (Task 9); wasmtime only in the deferred Task 11.

## Global Constraints

Same as the M1 overview §8 where it applies to Rust, plus:
- **Repository and branches.** Work in `~/Documents/loams-desktop` (worktrees in `~/Documents/loams-desktop-wt/<name>`). PRs target `main` of `ostrium-labs/loams-desktop`. `git commit -s` (DCO) everywhere. Commit areas: `brand`, `link`, `auth`, `bot`, `panels`, `stacks`, `update`, `ci`, `docs`.
- **Build machine.** The shared target directory in `~/Documents/.cargo/config.toml` (never `CARGO_TARGET_DIR`, never `/tmp`), `jobs = 6`, `df -h /mnt/Projects` shows more than 15 GB free before a GPUI build. One heavy build at a time. Prefer `cargo test -p loams-link` and `cargo check -p zeron-ui` over full builds; leave the rest to CI.
- **The ledger rule.** Any change to a file that exists in upstream's tree gets a `// loams:` marker (or `<!-- loams -->` in Markdown) and a row in `LOAMS.md`. New files under `crates/loams-*`, `dist/loams`, `scripts/loams` need none. A change that does not fit "one line or a match arm" is discussed first and, where generic, sent upstream.
- **No GPUI in `loams-link` or `loams-brand`.** A `cargo tree -p loams-link | grep gpui` that prints anything fails CI.
- **No secrets, no telemetry.** Tokens in memory and the OS keychain only; never in logs (`Debug` redacts), never in an environment variable of a child process, never in a URL except the single authorization-code redirect. Nothing phones home (D284).
- **Never contact zeron's services.** A test sets `ZERON_EDGE_URL` to a dead port and asserts nothing connects elsewhere; the default host must stay unresolvable until Task 9.
- **Names.** `Loams Desktop`, `Loams Bot`, `Loams Software Factory` verbatim in UI strings. The binary stays `zeron` and the data directory `~/.zeron` until Q489 and Q490 are answered.
- **Licences.** `cargo deny check licenses` passes (Task 1); any new bundled asset is listed in `NOTICE` or `THIRD_PARTY_NOTICES.md`.

### Task 3: Stack supervision through the `loams` CLI

**Files:** `crates/loams-link/src/stacks.rs`, `tests/fake_loams.rs` plus a `tests/fixtures/fake-loams` script, `cli.rs` (`zeron loams stacks …`).

**Semantics:**
- `Stacks` runs `loams stack list|start|stop|restart|upgrade|logs --output json` as a child with no TTY, `LOAMS_NO_UPDATE_CHECK=1`, a timeout, its own process group (Unix) or job object (Windows), and parses D283's contract: one JSON document on stdout, one error object on stderr, the exit code classified (0 ok through 9 integrity, 130 interrupted).
- `LOAMS_HOME` is shared (default `~/.loams`). `stack create` and `stack delete` are returned as exact commands to copy (D488), never run.
- The `keep_running` restart policy: a stack reported `crashed` restarts with backoff 1 s, 2 s, 4 s … 30 s, at most five times in ten minutes, then stays `crashed` with its log tail. A pure state machine with an injected clock.
- Locating the binary: `PATH`, `~/.loams/bin/loams`, or `LOAMS_BIN`; Q428 and Q488 decide bundling and are not assumed.
- **Windows is remote-only** (Q437): `Stacks::available()` is false there and the verbs say so.
- A native Stacks panel is Task 8; this task ends at the library and the CLI verbs.

**Tests (against a fake `loams` script, no real stack):** `list_parses_the_json_contract`; `exit_code_classes_map_to_errors`; `child_has_no_tty_and_the_update_check_off`; `timeout_kills_the_process_group`; `restart_backoff_is_1_2_4_to_30_and_caps_at_five_per_ten_minutes` (property test over the state machine); `create_and_delete_are_commands_not_actions`; `windows_reports_unavailable` (cfg).

**Commit:** `stacks: supervise the loams CLI from the desktop`.

### Task 4: TLS and pinning for remote instances

**Files:** `crates/loams-link/Cargo.toml` (connectrpc `client-tls`), `src/tls.rs`, `src/client.rs`.

**Semantics:**
- `LoamsClient::connect` accepts `https://`. System roots by default; for an environment that came from a pairing or declares `tls_pins` in `GetInstance`, a verifier that accepts only a certificate whose SPKI SHA-256 is in the pin set, with the hostname still checked (§37 §7.2.3). `tls_pins` is a compact JWS signed by the instance key; the thumbprint (`jkt`) anchors identity.
- Provider selection for rustls is explicit (no process-wide default) so zeron's `reqwest` rustls and connect-rust's do not fight.
- A pin set that no longer matches is a hard failure with a message naming the environment, never a silent downgrade.

**Tests (`rcgen`-generated certificates on loopback):** `https_with_system_roots_refuses_self_signed`; `pinned_spki_accepts_the_matching_cert`; `pinned_spki_refuses_a_different_cert_for_the_same_name`; `hostname_is_checked_even_when_pinned`; `rotation_announcement_must_be_signed_by_the_old_key`.

**Commit:** `link: TLS with SPKI pinning for remote instances`.

### Task 5: Loams Bot over `loams.bot.v1`, in zeron's chat

**Depends on:** SF3 Task 0 (the proto), SF2 Task 0 (A2A shapes verified, Q466). Until they land, this task builds against the mock's `bot` scenario.

**Files:** `crates/loams-link/src/bot.rs`, `src/acp.rs`, `crates/harness/src/acp/loams_bot.rs`, `crates/ui` (artifact renderers, behind the `loams` feature of `zeron-ui` if upstream's code has none; each hook marked).

**Semantics:**
- The ACP agent's backend becomes a trait with two implementations: the Connect `loams.bot.v1` client (`Send`, `Watch` with resume cursor, `Cancel`) and the A2A stub, chosen by whether the environment's `api_versions` lists `loams.bot.v1` (or `LOAMS_BOT_URL` is set).
- Task state to ACP: as §37 §18.4's table. `INPUT_REQUIRED` of kind question becomes an ACP input request, which zeron's engine already bridges to its question panel; **the answer returns to Loams Bot as a message in the same task, written by the person**. Kind approval becomes a card with a link to the approvals panel; the shim never calls `DecideApproval`.
- Artifact cards (`issue`, `pull_request`, `error`, `metric`, `run`, `approval`) are rendered by a small native renderer registry keyed by kind, falling back to text.
- The agent process is started with an environment that has no Loams token and is given no other way to obtain one: any call it needs to make to Loams is made by `loams-link` on its behalf (through the credential broker, §39 §6) and only the result is returned, so a prompt-injected tool call has no token to read or exfiltrate.
- First-run default harness follows Q484's answer.
- Persistence: the thread id is the zeron session id; on a second device the server's thread is the truth (Q496), shown read-only until the server answers.

**Tests:** the scaffold's ACP tests, plus `bot_env_has_no_loams_token`; `input_required_is_never_auto_answered`; `question_answer_is_a_user_message_in_the_same_task`; `approval_card_never_decides`; `watch_resumes_from_cursor_after_drop` (against the mock's `stream-drop-and-resume` scenario); `unknown_artifact_kind_falls_back_to_text`; a headless GPUI test for the card renderer.

**Commit:** `bot: Loams Bot over loams.bot.v1 with question and approval cards`.

### Task 6: Approvals panel, notifications and step-up

**Files:** new crate `crates/loams-panels` (GPUI; features `approvals`, later others), one marked hook in `crates/ui` to register panels, `crates/loams-link/src/approvals.rs`.

**Semantics:**
- `loams.approvals.v1` client: `ListApprovals`, `GetApproval`, `WatchApprovals` (snapshot, changes, heartbeat, cursor), `DecideApproval` with a decision proof (§37 §7.3). A panel lists pending approvals with the server-rendered `summary` and `detail_lines`; a detail view decides.

- Upstream: an "ask" mode for third-party agents' permission requests (Q485) is proposed upstream first and carried as a patch only if it is declined.
