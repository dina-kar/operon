# M1.5 — Elasticsearch API Phase A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, formats, constants), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Planned** (2026-09-24).

**Goal:** Ship `operon-es`, an Elasticsearch 8 REST gateway on port 9200 over `CollectionService`, covering design §06 §7 Phase A as D48 defines it: what the LangChain and LlamaIndex Elasticsearch suites and the M1.7 BEIR and differential harnesses send, and nothing else:
- document APIs: `_doc` index/create/get/delete/HEAD, `_create`, `_update` (partial `doc`, `doc_as_upsert`, `upsert`), `_bulk` (NDJSON: index, create, update, delete, with per-item results), `_mget`, `_source`;
- search: `_search` (GET/POST), `_count` and `_mget` (the LangChain caches, C44), `_msearch` (the BEIR harness sends its queries through it, C47), `from`/`size`, `sort`, `search_after` without a point in time (LangChain chat history, C35), `_source` filtering, `track_total_hits`;
- the Query DSL: `match`, `match_phrase`, `multi_match`, `bool`, `term(s)`, `range`, `exists`, `prefix`, `wildcard`, `fuzzy`, `ids`, simple `query_string`, `constant_score`, `knn` (top level and as a query), hybrid query + `knn` (ES score sum) and RRF (`retriever.rrf` and legacy `rank.rrf`), and the fixed `script_score` vector scripts of elasticsearch-py's `helpers.vectorstore` strategies, through which LangChain builds its requests;
- minimal index admin: create/delete/HEAD/GET index (concrete names and comma lists; wildcard and `_all` deletes are refused, Ruling 21), mappings get/put, settings at creation, aliases (including `_aliases` actions; an alias may name several indices, at most one of them its write index, D57; the LangChain caches manage their index through one on two indices, C49), a synthetic `_cluster/health`, a `_refresh` no-op, and `GET /`;
- `_delete_by_query` (pulled forward from Phase B, Ruling 6), because the LlamaIndex vector store, LangChain chat history and the LangChain caches delete through it.

Everything else in design §06 §7 Phase A, and the elasticsearch-py client-suite gate, is Phase B (D48); the list is in "Moved to Phase B (D48)". The Python `elasticsearch` 8.19 client runs against `operon dev` in CI (Task 11). Every endpoint, parameter and DSL construct that the LangChain and LlamaIndex suites and the BEIR and differential harnesses send is mapped to a task and a test (see "Conformance surface"). The full framework gate is M1.7.

**Architecture:**
- `operon-es` (new crate, behind the `operon` binary's `es` feature, on by default): an axum 0.8 router. It holds an `Arc<CollectionService>` and never touches storage or meta (overview §8).
- Every request goes through the same pipeline:
  1. media-type negotiation and the `X-Elastic-Product` header;
  2. namespace resolution (`Operon-Namespace` header, else the configured namespace; overview §6.9);
  3. index-expression resolution (`a,b`, `*`, `_all`, aliases);
  4. query-parameter validation (unknown parameters are rejected, as ES does);
  5. the handler;
  6. the ES error envelope.
- Mappings are stored in the collection schema: `FieldSpec`/`VectorSpec` for what the engine needs, and per-field and settings annotations for what only ES clients see, such as declared type names like `float` versus `double` (`CollectionSchema.annotations`, overview A1).
- **Writes** compile to `DocOp`s through one write engine shared by `_doc`, `_create`, `_update`, `DELETE` and `_bulk`. The engine:
  - validates ids;
  - moves `dense_vector` values out of `_source` into `Document.vectors` (overview A9);
  - proposes dynamic mappings before appending (R17);
  - pre-reads documents that updates and creates need;
  - simulates the request in order, so repeated ids in one request behave as in ES;
  - maps `OpResult`s and per-op positions (`WriteResult.positions`) to ES `result`, `_version` and `_seq_no`.
- **Searches** compile to a `SearchPlan`:
  - a single `SearchRequest` covers query-only, knn-only and RRF;
  - a gateway-side merge of one text and N vector searches covers the ES score sum of `query` + `knn`;
  - an exact vector `SearchRequest` with a metric override covers the recognised `script_score` scripts (`AnnParams.distance`, overview A7).
- The gateway converts engine scores to ES scores per similarity. Multi-index searches fan out per index and merge with the R10 tie-break.
- **Aliases** (D57, Ruling 9): an alias names a set of collections, with at most one write target (`is_write_index`). Reads through it (`_search`, `_count`, `_msearch`, `_delete_by_query`, `GET _mapping`) fan out over every member as a multi-index request does (Ruling 15); writes go to the write target, and without one they fail as in ES. The catalog change is Task 0a: a new metastore command appended after `UpdateAliases`, a new alias map beside the M1.1 one, and new `MetaStore` and `CollectionService` methods; M1.1's log entries and snapshots decode unchanged (Ruling 22).
- `_delete_by_query` reads a pinned view, `ReadConsistency::Pinned { manifest_version, token }` (overview A6): nothing is held anywhere, and the manifest's retention (A21) keeps it readable while the deletes run.
- The ES query DSL parser is Operon's own and emits the search IR (§6.6). Quickwit's `elastic_query_dsl` and `elasticsearch_api` are the reference for shapes; generic helpers are copied with their headers (Ruling 1).

Checked against "Conformance surface" and the langchain-elastic and LlamaIndex sources at the M1.7 pins, these items are sent only by elasticsearch-py's own test suite, or by nothing gated, and leave this plan:
- **the elasticsearch-py client-suite gate** (formerly part of M1.7 Task 4) and the endpoints its `wipe_cluster` fixture calls: `GET /_snapshot[/{repository}]`, `DELETE /_data_stream/{name}`, `DELETE /_template/{name}`, `DELETE /_index_template/{name}`, `GET /_cluster/settings`, `GET /_cluster/pending_tasks` (formerly Task 3 rule 7 and row C46);

## Global Constraints

Same as the M1 overview §8, plus:
- Every HTTP response from the gateway, including errors, `HEAD` and 404s, carries `X-Elastic-Product: Elasticsearch`.
  - elasticsearch-py 8 raises `UnsupportedProductError` on the first 2xx response without it (`elasticsearch/_sync/client/_base.py:355-366`).
  - elastic-transport-js does the same (`src/middleware/ProductCheck.ts:20-30`).
- The gateway never blocks on a write becoming visible. Reads are `Strong` by default (R11), so `refresh` and `wait_for` are accepted no-ops.
- No Elastic code, spec tests or resources are vendored (R14).
  - elasticsearch-py is Apache-2.0 but is used only as a CI test dependency.
  - Quickwit files copied into `operon-es` keep their `// Copyright 2021-Present Datadog, Inc.` headers. They are covered by the Quickwit entry M1.1 adds to `NOTICE`.
- Request bodies are limited to 100 MiB (`http.max_content_length`; elasticsearch-py's `helpers.bulk` chunks at `max_chunk_bytes = 100 MiB`, `helpers/actions.py:419`); a larger body gets 413 with the ES envelope.
- Commit areas used: `meta` (Task 0a: `operon-common`, `operon-meta`, `operon-meta-conformance`), `query` (Task 0a: `CollectionService`), `es`, `operon`, `ci`, `conformance`, `docs`.

## Review Focus

1. **Repeated ids and races inside one write request.** For example, `_bulk` with `index a`, `update a`, `create a`, `delete a`, `update a`, or two concurrent `_create`s of one id. **Semantics:**

1. **ES type → schema** (`plan_create` / `plan_put_mapping`). Walk `properties` recursively; a field's path is the dot-joined key path.

   | ES `type` | FieldSpec / VectorSpec | Notes |
   |---|---|---|

   | `keyword` | `Keyword`, `indexed = index`, `fast = doc_values (default true)` | `ignore_above` recorded only (Ruling 16); `normalizer` → unsupported |

   | `boolean` | `Bool` | |

   | `flattened` | `Json` | |

   | `nested` | — | `mapper_parsing_exception` "Operon does not support field type [nested] (declared on field [<f>]) in Elasticsearch API Phase A" |
   | `dense_vector` | `VectorSpec { name: path, dim: dims, distance, element: F32, index, hnsw, quantization }` | See item 2 |

   - Parameters accepted and ignored: `store`, `eager_global_ordinals`, `boost`.
   - Refused as Phase B: `copy_to`, `null_value`, `norms: false`, `index_options`, `term_vector`, `fielddata: true`.

2. **`dense_vector`.**
   - `dims` must be 1..=4096, else "The number of dimensions should be in the range [1, 4096] but was [<n>]". A missing `dims` records the path in `pending_vectors`; the first document sets it (Task 4).
   - `element_type` `float` only; `index` default `true`.
   - `similarity` (default `cosine` when indexed): `cosine` → `Cosine`, `dot_product` → `Dot`, `l2_norm` → `Euclid`, `max_inner_product` → `Dot`. The value is recorded in `es.similarity.<path>`. An unknown value gives "Unknown vector similarity [<s>]".
   - `index: false` → `VectorIndexSpec::None`, distance `Cosine` unless `similarity` is given. An indexed field without `index_options` → `VectorIndexSpec::Auto`, `HnswParams::default()`.
   - `index_options.type`:
     - `hnsw` → `VectorIndexSpec::Auto` and `HnswParams { m (default 16), ef_construct (ef_construction, default 100), ..HnswParams::default() }`;
     - `int8_hnsw` → the same plus `Quantization::Scalar { quantile_ppm: None, always_ram: false }`;
     - `flat` → `VectorIndexSpec::None`;
     - `int8_flat` → `None` + the same `Scalar`;
     - `int4_hnsw`, `int4_flat`, `bbq_hnsw`, `bbq_flat` → unsupported.
3. **Settings.**
   - `normalize_settings` flattens nested objects and prefixes keys with `index.` if absent. Values are stringified; numbers and booleans are written as JSON text.
   - Accepted at create:
     - `index.number_of_shards` (1..=1024 → `partitions`);
     - `index.number_of_replicas`, `index.refresh_interval` (stored);
     - `index.max_result_window` (≥ 1);
     - `index.mapping.total_fields.limit` (→ `max_fields`; default 1000);
     - `index.similarity.<name>.type` = `BM25` with optional `k1` = `1.2`, `b` = `0.75`, `discount_overlaps` = `true` (other values → `illegal_argument_exception` "Operon supports BM25 with k1=1.2 and b=0.75 only (Phase A)");
     - `index.default_pipeline` (stored; Ruling 18).
   - `index.analysis.*` is unsupported.
   - Any other key gives `illegal_argument_exception` "unknown setting [<key>] please check that any required plugins are installed, or check the breaking changes documentation for removed settings".
   - Settings are fixed after creation in Phase A: `PUT /{index}/_settings` is Phase B ("Moved to Phase B (D48)").
   - `ANN_SETTINGS` stores everything except `number_of_shards`.
4. **`plan_put_mapping`** returns only additions. For an existing path, the declared JSON must equal the stored annotation, or both must derive to the same kind; otherwise `illegal_argument_exception` "mapper [<f>] cannot be changed from type [<old>] to [<new>]".
5. **`render_mappings`.**
   - Build a tree from FieldSpecs. A spec whose `name` is `<source_path>.<sub>` goes under its parent's `fields.<sub>`.
   - A node with annotation `es.field.<path>` renders that JSON. Without one:
     - `Text` renders `{"type": "text"}` (plus `analyzer` if not `standard`);
     - `Keyword` renders `{"type": "keyword"}`, plus `"ignore_above": 256` when it is a subfield named `keyword` of an unannotated Text parent;
     - `I64` → `long`, `F64` → `float`, `Bool` → `boolean`, `Date` → `date`, `Uuid` → `keyword`, `Json` → `flattened`;
     - a vector renders `{"type": "dense_vector", "dims", "index", "similarity"}`.
   - Objects render `{"properties": {…}}`, with `"type": "object"` only when annotated. The root adds `"dynamic": "strict"` or `"false"` for `Strict` or `Ignore`.
6. **`render_settings`.**

   ```json
   {"index": {"number_of_shards": "<partitions>", "number_of_replicas": "<stored or 1>", "uuid": index_uuid(id), "creation_date": "<created_at_ms>",
              "provided_name": name, "version": {"created": "8190099"}, …stored settings nested by dots}}
   ```

   All values are strings.
7. **`dynamic_plan`** calls `unmapped_paths` (with `Strict`, a non-empty result is the strict error for its first path) and, with `Map`, `propose_dynamic_fields(schema, &[source])`; with `Ignore` it proposes nothing. Errors map as follows:
   - strict with an unmapped `path` → 400 `strict_dynamic_mapping_exception` "[dynamic] set to [strict], dynamic introduction of [<last segment>] within [<parent path or _doc>] is not allowed".
   - `DynamicMappingError::TooManyFields { limit }` → 400 `illegal_argument_exception` "Limit of total fields [<limit>] has been exceeded while adding new fields [<n>]".

   Paths of pending or declared vectors and of `enabled: false` objects are removed from the source before the call.

1. **Create index.**
   1. `validate_index_name`.
   2. `plan_create`.
   3. `create_collection(ns, name, CollectionSchema { version: 1, fields, vectors, sparse_vectors: vec![], dynamic, max_fields, annotations }, partitions)`. `AlreadyExists` gives 400 `resource_already_exists_exception` with the existing index's uuid.

2. **Delete index** (Ruling 21). `_all`, `*` and any element containing `*` give 400 `illegal_argument_exception` "Wildcard expressions or all indices are not allowed" and delete nothing (ES 8's default `action.destructive_requires_name: true`). `expand_wildcards` is accepted and has no effect. A deleted index leaves every alias it was a member of (Task 0a rule 3: an alias left with one unset member makes it the write index; an alias left empty is gone), as in ES.
3. **PUT mapping.** `plan_put_mapping` → `add_fields(ns, name, fields, vectors, annotations)`. A concurrent schema update surfaces as `ServiceError::InvalidArgument`/`SchemaViolation` from `add_fields`; re-read the collection and re-plan once, then report. Through an alias or a list, every resolved index is planned first, and any planning error fails the request before any `add_fields`; then each index is updated in name order (with `write_index_only=true`, only the write index, or 400 as in `resolve_write` when there is none). A concurrent schema change after planning can leave earlier indices updated and a later one failed; the error names that index (ES applies the mapping in one cluster-state update).
4. **Aliases** (Ruling 9, D57).
   - Every alias request compiles to one `update_alias_targets` call, so it is atomic:
     - `POST /_aliases`: `add {index | indices, alias | aliases, is_write_index?}` → one `Add` per (index, alias) pair; `remove {index | indices, alias | aliases}` → one `Remove` per pair; the actions keep their request order. `index`/`indices` elements are concrete names or wildcards resolved with `resolve` (an alias there → 400 `illegal_argument_exception`, as in ES; verify).
     - `PUT|POST /{index}/_alias/{name}` → `Add` per resolved index, with the body's `is_write_index` (absent → unset).
     - `DELETE /{index}/_alias/{name}` (`index` may be a comma list, `name` a comma list or `*`) → a `Remove` per (index, alias) pair where the index is a member.
   - An `add` of an existing pair replaces its setting (Ruling 9), so `put_alias(test_index2, test_alias, is_write_index=False)` turns off the write index and a later plain `put_alias` unsets it.
   - Before sending, the gateway applies the actions to the aliases' current members (`resolve_name`) to answer ES's errors: a result with two members set to true → `illegal_state_exception` "alias [<a>] has more than one write index [<i1>,<i2>]" (ES 8.19 answers this with status 500; verify against the oracle and use its status); an alias name equal to an index → 400 `invalid_alias_name_exception` "Invalid alias name [<a>]: an index or data stream exists with the same name as the alias"; an `add` naming a missing index → 404 `index_not_found_exception`.    - Refused as Phase B: `filter`, `routing`, `index_routing`, `search_routing`, `is_hidden`, `must_exist`; `remove_index` gives unsupported.
   - `DELETE /a,b/_alias/x` removes `x` from each listed index that is a member, and gives 404 `aliases_not_found_exception` "aliases [x] missing" when none is.
   - `GET /_alias…` renders `list_aliases` filtered by the path's index and alias expressions; `HEAD` answers 200 when anything matches, else 404.
5. **`_refresh`.** It resolves the expression (404 for a missing concrete name) and writes nothing; reads are strong (R11). `total` and `successful` = the number of indices.

Routes:

| Method | Path | Params accepted |
|---|---|---|
| PUT/POST | `/{index}/_doc/{id}` | `op_type` (`index`\|`create`), `refresh`, `routing`, `timeout`, `wait_for_active_shards`, `require_alias`, `pipeline`, `include_source_on_error`, `if_seq_no`, `if_primary_term`, `version`, `version_type` |
| POST | `/{index}/_doc` | the same without `op_type` |
| PUT/POST | `/{index}/_create/{id}` | the same without `op_type` |
| POST | `/{index}/_update/{id}` | `refresh`, `routing`, `timeout`, `wait_for_active_shards`, `require_alias`, `retry_on_conflict`, `_source`, `_source_includes`, `_source_excludes`, `lang`, `include_source_on_error`, `if_seq_no`, `if_primary_term` |
| DELETE | `/{index}/_doc/{id}` | `refresh`, `routing`, `timeout`, `wait_for_active_shards`, `if_seq_no`, `if_primary_term`, `version`, `version_type` |

`if_seq_no`, `if_primary_term`, `version` and `version_type` present → 400 `illegal_argument_exception` "optimistic concurrency control (if_seq_no, if_primary_term, version) is not supported by Operon (Phase B)".

**Semantics** (`execute`, one resolved index, items in request order):

1. **Resolve.**
   - `resolve_write` the index (Ruling 9): an alias writes to its write index, and an alias without one fails every op-bearing item with the "no write index is defined for alias [<a>]…" error (400). A name that is an alias is never auto-created. The success body's `_index` is the concrete write index, as in ES.
   - `require_alias=true` and the name is not an alias → every item 404 `index_not_found_exception` "no such index [<x>] and [require_alias] request flag is [true] and [<x>] is not an alias".
   - A missing index is created (auto-create) with `plan_create(None, None)` when any item is an `Index`, or an `Update` whose body has `upsert` or `doc_as_upsert: true`. `AlreadyExists` from a racing creator is ignored. Otherwise items get 404 `index_not_found_exception`.
2. **Ids.**
   - `Index { id: None }` gets `generator.generate()` as a ULID string (Ruling 5).
   - `validate_id`: empty → 400 `illegal_argument_exception` "if _id is specified it must not be empty"; more than 512 bytes → "id [<id…>] is too long, must be no longer than 512 bytes but was: <n>".
   - PK = `PrimaryKey::Str(id)`.
3. **Pipelines.** If `pipeline` or the index's `default_pipeline` is set, every `Index`/`Update` item fails 400 `illegal_argument_exception` "pipeline with id [<p>] does not exist" (Ruling 18).
4. **Documents** (`to_document`).
   - A source that is not a JSON object → 400 `document_parsing_exception` "[1:1] failed to parse: source is not an object".
   - A top-level key in `METADATA_FIELDS` → 400 `document_parsing_exception` "[1:<col>] failed to parse field [<k>] of type [<k>] in document with id '<id>'. Preview of field's value: '<v>'", preceded by the ES text "Field [<k>] is a metadata field and cannot be added inside a document. Use the index API request parameters." as `caused_by`.
   - For each named vector and each `pending_vectors` path, remove the value at the path from the source:
     - `null` → no vector;
     - an array of finite numbers → `vectors[path]`;
     - anything else → 400 `document_parsing_exception` "failed to parse field [<p>] of type [dense_vector] in document with id '<id>'";
     - a length different from `dim` → "The number of dimensions for field [<p>] should be [<dim>] but found [<n>]";
     - `dot_product` with `|Σv² − 1| > 1e-4` → "The [dot_product] similarity can only be used with unit-length vectors.";
     - cosine with `Σv² == 0` → "The [cosine] similarity does not support vectors with zero magnitude.".
   - A pending path gets a `VectorSpec` with `dim = n` through `add_fields` in step 5.
   - A value at a `binary` path (Task 2) must be a string that decodes as standard base64 (`base64::engine::general_purpose::STANDARD`) or `null`; otherwise 400 `document_parsing_exception` "failed to parse field [<p>] of type [binary] in document with id '<id>'" (verify the wording against the oracle).
5. **Dynamic mapping** (R17, Review Focus 5).
   - With the index's `IndexView`, fold `dynamic_plan` over every Index source, Update `doc` and Update `upsert` in order. Each call sees the schema plus the fields already proposed, so a field is proposed once.
   - Strict and field-limit errors fail only their item.
   - If the union is non-empty, call `add_fields(ns, name, fields, pending_vector_specs, {})`.
   - On `SchemaViolation` or `InvalidArgument` (a racing writer mapped the same path differently), `get_collection`, rebuild the view and re-fold once. Items that still fail validation in step 6 get their per-item error.
   - Two writers proposing the identical field both succeed: `add_fields` is additive and retry-safe per overview §6.1 `UpdateCollectionSchema`.
6. **Validate.** `check_document(schema, &doc)` per item. `DocRejection::Violations([Violation { field, message }, ..])` (the first) → 400 `document_parsing_exception` "[1:1] failed to parse field [<field>] of type [<es type>] in document with id '<id>'. Preview of field's value: '<first 64 chars>'", with `caused_by.reason = message`.
7. **Pre-read** (Ruling 8). Collect the PKs of every `Update` and every `create: true` Index. If any, `get(ns, name, pks, Projection { source: All, vectors: all named vectors, fields: [] }, Strong)`. Seed `overlay: HashMap<PrimaryKey, Option<(Map, BTreeMap<String, Vec<f32>>, u64 /* seq_no */)>>`.
8. **Simulate in order** and build `ops: Vec<DocOp>` with `kinds: Vec<(item index, OpKind)>`:
   - `Index { create: false }` → `DocOp::Upsert(doc)`; overlay = `Some(doc)`.
   - `Index { create: true }`:
     - overlay says the key exists → 409 `version_conflict_engine_exception` "[<id>]: version conflict, document already exists (current version [<seq_no + 1>])", extra `index_uuid`, `shard: "0"`, `index`; no op.
     - otherwise → `DocOp::Patch { pk, mode: MergeDeep, source: {}, delete_keys: [], vectors: {}, upsert: Some(doc) }` (Ruling 7); overlay = `Some(doc)`.
   - `Update { body }`. The body keys allowed are `doc`, `upsert`, `doc_as_upsert` (default false), `detect_noop` (default true) and `_source`.
     - `script` or `scripted_upsert` → 400 `illegal_argument_exception` "Operon does not support scripted updates (Elasticsearch API Phase A)".
     - Neither `doc` nor `script` → 400 `action_request_validation_exception` "Validation Failed: 1: script or doc is missing;".
     - `doc` is split like step 4 into `(doc_source, doc_vectors)`; a `null` vector value becomes `None` (delete).
     - Missing key:
       - with `doc_as_upsert`, upsert = `doc`;
       - else with `upsert`, upsert = `to_document(upsert)`;
       - else → 404 `document_missing_exception` "[<id>]: document missing", extra `index_uuid`, `shard: "0"`, `index`; no op.

       With an upsert → `DocOp::Patch { pk, MergeDeep, source: doc_source, delete_keys: [], vectors: doc_vectors, upsert: Some(upsert_doc) }`; overlay = upsert.
     - Present key: `merged = cur.clone(); merge_deep(&mut merged, doc_source)`, with vectors applied (`Some` replaces, `None` removes).
       - `detect_noop` and `merged == cur` → result `noop` (status 200, `_shards` all 0, `_seq_no`/`_version` from `cur.seq_no`); no op.
       - Otherwise → `DocOp::Patch { …, upsert: None unless doc_as_upsert or upsert given }`; overlay = merged.
   - `Delete` → `DocOp::Delete(pk)`; overlay = `None`.
9. **`merge_deep`** (ES partial-document semantics):
   - for every key in the patch, if both values are objects, recurse;
   - otherwise replace, with `null` stored as `null` (not a delete);
   - arrays are replaced whole.

   `PatchMode::MergeDeep` in M1.1 must have the same semantics; Task 0 records any difference.
10. **Append.** If `ops` is non-empty, `write(ns, name, ops, WriteOptions { report_existence: true, ..Default::default() })` (not `atomic`: ES reports per item). Then map each op:

    | Op | `OpResult` | Item |
    |---|---|---|
    | Upsert | Created / Updated / Noop | 201 `created` / 200 `updated` / 200 `updated` (ES re-indexes an identical document as `updated`) |
    | Create patch | Created | 201 `created` |
    | Create patch | Updated / Noop | 409 as in step 8 (race lost: the key existed) |
    | Update patch | Updated / Created / Noop / NotFound | 200 `updated` / 201 `created` / 200 `noop` / 404 `document_missing_exception` (the document vanished after the pre-read: a patch of a missing key without `upsert` is `NotFound`, M1.2 Ruling 10) |
    | Delete | Deleted / NotFound | 200 `deleted` / 404 with result `not_found` |
    | any | Rejected(e) | `EsError::from_service(e, Write)` for that item |

    A whole-call `ServiceError` gives every op-bearing item `EsError::from_service(e, Write)`. Items with an earlier error keep theirs.
11. **`_seq_no`** (Ruling 4) = `positions[i].seq_no`, the partition offset of op *i*'s record (M1.2 `OpPosition`); `_version = _seq_no + 1` and `_primary_term = 1`. A `noop` item decided by the pre-read (no op appended) reports the pre-read document's `seq_no`.
12. **Success body.** `{"_index": <concrete>, "_id", "_version", "result", "_shards": {"total": 1, "successful": 1, "failed": 0}, "_seq_no", "_primary_term"}`, plus `"forced_refresh": true` when `refresh` is `true` or `""`. `_update` with `_source` params adds `"get": {"_seq_no", "_primary_term", "found": true, "_source": filtered merged source with vectors restored}`. A write response sets the `Operon-Consistency-Token` header to `token.to_string()`.
13. **Single-document endpoints** call `execute` with one item and answer with its status and body. Error items use the envelope.

**Produces:**

```rust
pub struct BulkLine { pub action: BulkAction, pub index: Option<String>, pub id: Option<String>, pub require_alias: Option<bool>,
                      pub pipeline: Option<String>, pub source: Option<Result<serde_json::Value, String /* parse error */>>, pub line_no: usize }
```

Routes: `POST|PUT /_bulk` and `POST|PUT /{index}/_bulk`. Params: `refresh`, `routing`, `timeout`, `wait_for_active_shards`, `require_alias`, `require_data_stream`, `pipeline`, `_source`, `_source_includes`, `_source_excludes`, `include_source_on_error`, `list_executed_pipelines`.

**Semantics:**

1. **Parsing.**
   - The body must end with `\n`, else 400 `illegal_argument_exception` "The bulk request must be terminated by a newline [\\n]".
   - Split on `\n`, strip one trailing `\r` per line, and skip empty lines.
   - An action line is a JSON object with exactly one key: `index`, `create`, `update` or `delete`. Otherwise the whole request fails 400 `illegal_argument_exception` "Malformed action/metadata line [<n>], expected field [create], [delete], [index] or [update] but found [<k>]". A non-object gives "…expected START_OBJECT but found [<token>]".
   - Metadata keys allowed: `_index`, `_id`, `require_alias`, `pipeline`, `routing`, `op_type` (for `index`: `create` turns it into Create), `retry_on_conflict` (update; ignored), `_source` (update), `dynamic_templates`.
   - `if_seq_no`, `if_primary_term`, `version` and `version_type` fail that item with the Phase B reason.
   - An unknown key fails the whole request 400 `illegal_argument_exception` "Action/metadata line [<n>] contains an unknown parameter [<k>]".
   - `index`, `create` and `update` take the next line as the source. A missing source line fails the whole request: "Validation Failed: 1: source is missing;". A source that is not valid JSON is kept as `Err` and fails only that item: 400 `document_parsing_exception` "[1:<col>] failed to parse: <serde error>".
   - An item with no `_index` and no path index fails the whole request 400 `action_request_validation_exception` "Validation Failed: 1: index is missing;".
2. **Execution.**
   - Group items by their `_index` value (the path index is the default), keeping request order within a group. Each group's name goes through `resolve_write` (Ruling 9): an alias writes to its write index, and an alias without one fails every item of the group with the Ruling 9 error (item status 400), as ES fails each item.
   - Groups execute sequentially in order of first appearance. Each group is one `execute` call, so one `write` per index: atomic per index, as ES is per shard. A group with more than 10,000 op-bearing items (M1.1 `MAX_WRITE_OPS`, which `CollectionService::write` enforces) is split into consecutive `write` calls of at most 10,000 ops, in request order.
   - Results are placed back at their original positions.
   - `refresh` applies to all items. `require_alias` and `pipeline` from the query string apply unless an item overrides them.
3. **Response.**

   ```json
   {"took": ms, "errors": any_status_not_2xx, "items": [{"<action>": {…ItemOutcome.body, "status": s}}]}
   ```

   `<action>` is `index`, `create`, `update` or `delete` as sent, with `op_type=create` reported as `create`. Error items are `{"_index", "_id", "status", "error": {"type", "reason", …}}`.
   - HTTP status is 200 even when items failed.
   - The `Operon-Consistency-Token` header holds the per-partition maximum over all groups' tokens (tokens of different collections are concatenated).

### Task 6: Document reads: `GET`/`HEAD` `_doc`, `_source`, `_mget` and `_source` filtering

**Files:** `crates/operon-es/src/{read.rs, doc.rs}`, `crates/operon-es/tests/source_filter.rs`, `crates/operon/tests/es_docs.rs`.

**Consumes:** Task 4 (`restore_vectors`, `id_of`), `CollectionService::get`, `Projection`, `IrSourceFilter`, `StoredDoc` (A11).

**Produces:**

```rust
pub struct SourceFilter { pub enabled: bool, pub includes: Vec<String>, pub excludes: Vec<String> }
impl SourceFilter {
    pub fn from_params(p: &Params) -> Result<Option<SourceFilter>, EsError>;             // _source, _source_includes, _source_excludes
    pub fn from_body(v: &serde_json::Value) -> Result<SourceFilter, EsError>;           // true | false | "p" | ["p"] | {includes|include, excludes|exclude}
    pub fn keeps_path(&self, path: &str) -> bool;                                       // for deciding which vectors to fetch
    pub fn apply(&self, source: serde_json::Map<String, serde_json::Value>) -> serde_json::Map<String, serde_json::Value>;
}
pub fn glob_match(pattern: &str, path: &str) -> bool;          // '*' matches any sequence including '.'
pub fn glob_prefix_alive(pattern: &str, prefix: &str) -> bool; // some suffix t exists with glob_match(pattern, prefix + t)
```

Routes:

| Method | Path | Params accepted |
|---|---|---|
| GET/HEAD | `/{index}/_doc/{id}` | `_source`, `_source_includes`, `_source_excludes`, `realtime`, `refresh`, `routing`, `preference`, `stored_fields` (only `_none_`), `version`, `version_type` (Phase B) |
| GET/HEAD | `/{index}/_source/{id}` | the same minus `stored_fields` |
| GET/POST | `/_mget`, `/{index}/_mget` | `_source`, `_source_includes`, `_source_excludes`, `realtime`, `refresh`, `routing`, `preference`, `stored_fields` |

**Semantics:**

1. **`apply`** (ES `XContentMapValues.filter`).
   - Walk the source keeping the dot-joined path of each key. Arrays keep the same path for each element; objects inside arrays are filtered like objects.
   - A key with path `P` whose value is not an object is kept iff:
     - `includes` is empty, or some include `I` satisfies `glob_match(I, P)`, or `I` names an ancestor (`glob_match(I, Q)` for a proper prefix path `Q` of `P`); and
     - no exclude `E` satisfies `glob_match(E, P)` or `glob_match(E, Q)` for an ancestor `Q`.
   - An object at path `O`:
     - is kept whole (subject to excludes) if an include matches `O` itself;
     - is descended into if `includes` is empty or some include satisfies `glob_prefix_alive(I, O + ".")`;
     - is emitted only if it keeps at least one key, or it matched an include itself.

     - `cosineSimilarity(params.query_vector, '<f>') + 1.0` → `CosinePlusOne`;
     - `cosineSimilarity(params.query_vector, doc['<f>']) + 1.0` → `CosinePlusOne`;
     - `1 / (1 + l2norm(params.query_vector, '<f>'))` and the `doc['<f>']` form → `InverseOnePlusL2`;
     - `double value = dotProduct(params.query_vector, '<f>'); return sigmoid(1, Math.E, -value);` → `SigmoidDot`;

7. **`parse_date_math`.** Grammar: `anchor (op)*`, where `anchor = "now" | <date>"||"` and `op = ("+"|"-") <int> <unit> | "/" <unit>`, with units `y M w d h H m s`.

   - **No query, no knn, no retriever** → `Text { MatchAll, k: window }`.
   - **Query only** → `Single { retrievers: [Text { query: q.query, k: window }] }`, score `Bm25`.
   - **knn only, one entry** → `Single { retrievers: [Vector { field, query, k, params: AnnParams { exact: false, ef: Some(num_candidates), .. }, filter }], limit: min(size, k) }`, score `Knn(sim)`. `knn.similarity` → `score_threshold` in engine space:
     - Cosine/Dot: `t`;
     - l2_norm: `−t` (a maximum distance);
     - `max_inner_product`: the raw threshold `t`.
   - **Several knn, no query** → `HybridSum { text: None, vectors }`.
   - **Query + knn, no rank** → `HybridSum { text: Some((Text { q, k: window + Σk }, 1.0)), vectors: each (Vector { k }, sim, boost) }`, with `count_filter = Bool { should: [q.query, Ids(…) filled at execution] }` (Ruling 3). `knn.similarity` or `min_score` here → unsupported (Ruling 12).

     - a child `knn` → `Vector { k: min(knn.k, rank_window_size) }`;
     - a nested `rrf` → `Retriever::Fused`;
     - the rrf `filter` is added to every child.
     - `rank_constant < 1` → 400 "[rank_constant] must be greater or equal to [1]"; `window > rank_window_size` → 400 `illegal_argument_exception` "[rank_window_size] must be greater than or equal to [from + size]".

6. **`search_after`** (Review Focus 4).
   - Needs `from == 0`, else 400 `illegal_argument_exception` "[from] parameter must be set to 0 when [search_after] is used".
   - There is no point in time in Phase A (Ruling 10). The length must equal `user_sort_len` (a mismatch → 400 "search_after has <n> value(s) but sort has <m>"), and every key must be a field. A `_score` key → 400 `illegal_argument_exception` "Operon does not support [search_after on _score] (Elasticsearch API Phase A)".
     - The gateway adds the lexicographic filter `OR_i (AND_{j<i} key_j == v_j) AND key_i > v_i`, with `>`/`<` flipped for desc.
     - Missing values (`missing: _last`, the default): for an asc key, "`key_i > v_i`" is `Range(key_i, gt: v_i) OR must_not Exists(key_i)` (missing documents sort after every value); a `null` `v_i` (the client echoed a missing value) makes the clause "`key_i` missing and the remaining keys greater", i.e. `must_not Exists(key_i)` AND the next key's clause, and for the last key it matches nothing. With `missing: _first` the roles of present and missing are swapped. For desc keys `gt` becomes `lt`.

**Produces:**

```rust
pub fn render_hit(index: &str, hit: &Hit, spec: &RenderSpec, es_score: Option<f32>, seq_no: Option<u64>) -> serde_json::Value;
```

Routes:
- `GET|POST /_search`, `GET|POST /{index}/_search` (params `SEARCH_PARAMS`);
- `GET|POST /_count`, `GET|POST /{index}/_count` (params `q`, `df`, `default_operator`, `analyzer`, `lenient`, `ignore_unavailable`, `allow_no_indices`, `expand_wildcards`, `preference`, `routing`, `min_score` (Phase B), `terminate_after` (Phase B));

**Semantics:**

1. **`to_es_score`** (engine convention per overview §6.6):
   - `Bm25` → `s`;
   - `Knn(Cosine)` → `(1 + s) / 2`;
   - `Knn(DotProduct)` → `(1 + s) / 2`;
   - `Knn(L2Norm)` → `1 / (1 + s²)` (engine `s = −d`);
   - `Knn(MaxInnerProduct)` → `s < 0 ? 1 / (1 − s) : s + 1`;
   - `Knn(L1Norm)` → `1 / (1 − s)`;
   - `Script(CosinePlusOne)` → `s + 1`;
   - `Script(InverseOnePlusL2)` → `1 / (1 − s)`;
   - `Script(SigmoidDot)` → `1 / (1 + e^(−s))`;
   - `Rrf` and `Sum` → `s`.

   Boosts multiply the converted score.
2. **Single.**
   - One `search` call with the index name, then convert scores and render.
   - For multi-index (Ruling 15; a comma list, a wildcard or an alias with several members; only `Bm25`, `Knn` and field-sorted plans), run one search per index with `offset 0, limit from + size` (knn: `k`). Merge by the ES score desc (or sort values), then PK canonical bytes asc, then index name asc. Take `[from, from + size)` (knn: the first `k` before paging).
   - `total` = the sum; `relation` is `gte` if any part is not exact, or if a per-index `UpTo` limit was hit.
3. **HybridSum.**
   1. Run the text request (`Strong`, or the request's consistency) → `T` (hits with sources and `read_token`).
   2. Run each vector request with `AtLeast(read_token)` (Ruling 3).
   3. Union by PK: `score = text_boost × bm25 + Σ boost_i × to_es_score(Knn(sim_i), v_i)`; a missing part contributes 0.
   4. Sort by score desc, then PK asc; page `[from, from + size)`.
   5. A hit's source comes from whichever part returned it.
   6. `total` = `count(count_filter with Ids(knn PKs))` when tracking, capped by `UpTo`.
4. **ScriptScore.** One exact `search` with `score_threshold` set, scores converted and boosted. `total` = `count(count_filter)` capped by `UpTo`.
5. **Rendering.**

   ```json
   {"took": ms, "timed_out": false, "_shards": {"total": n_indices, "successful": n_indices, "skipped": 0, "failed": 0},
    "hits": {"total": {"value": v, "relation": "eq"|"gte"}, "max_score": f|null, "hits": [...]}}
   ```

   - `total` is omitted when `track_total_hits: false`, and is an integer when `rest_total_hits_as_int`.
   - A hit renders, in this key order: `_index` (concrete), `_id` (`id_of`), `_score` (null unless `scores_visible`), `_version`/`_seq_no`/`_primary_term` when flagged (values from one `get` of the page's PKs with `IrSourceFilter::None`), `_source` (filtered, vectors restored), `sort`.
   - `sort` = the user sort values. Date values are epoch millis (i64), `_score` values are f32, missing values are `null`.
   - `max_score` = the max ES score of the returned page, or `null` when scores are hidden. f32 values use the shortest representation.
6. **`_count`.** Body `{query}` only (other keys → `parsing_exception`), or `q`. knn/script → 400 `illegal_argument_exception` "[knn] is not supported by the count API". One `count` per index, summed. Response `{"count": n, "_shards": {"total": k, "successful": k, "skipped": 0, "failed": 0}}`.
7. **`_msearch`** (the BEIR harness, C47).
   - The body is NDJSON header/body pairs; header keys: `index` (string or array), `preference`, `routing`, `search_type`, `request_cache`, `ignore_unavailable`, `allow_no_indices`, `expand_wildcards`. `search_type` (`query_then_fetch` or `dfs_query_then_fetch`) is accepted and ignored: BM25 statistics are always global (R6), which is what `dfs_query_then_fetch` asks for.
   - An empty header `{}` uses the path index.
   - Searches run with at most `min(max_concurrent_searches, msearch_concurrency)` in flight.
   - Response `{"took", "responses": [ {…search response, "status": 200} | {"error": {…}, "status": s} ]}` in request order. A malformed pair gives that entry's error.
8. **Errors.**
   - A service error during search on one index → `search_phase` envelope for that index.
   - A missing index → 404 `index_not_found_exception`, unless `ignore_unavailable`.
   - Response header `Operon-Consistency-Token` = `read_token`.
