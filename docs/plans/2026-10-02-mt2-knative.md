# MT2 — Knative Serving and Eventing for Self-Hosted Loams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, labels, annotations, metric names, defaults), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Planned** (2026-10-02). **Track MT** (design [§38](../design/38-knative-authentik-gitops.md) §3, D441–D446; amends [§24](../design/24-cpu-time-runtime.md) §4 and §11 and [§27](../design/27-usage-hooks.md) §3.2). Depends on RN1 Task 3 (the `Runner` trait, `RunnerHost` and `InvocationObserver`; RN1 Tasks 1 and 2 moved to `loam-platform`) and on `loams-operator` (D185) existing with its `Function` CRD; Task 0 records what has merged. **No metering** (D444): nothing here writes host reports, aggregates usage or rates it. Branches `mt2-t<N>`, stacked; PRs target `main`. MT2 adds crates only; nothing is linked into `loams`'s default build.

**Goal:**
- `loams-runner-knative`: `KnativeRunner`, the `Runner` (D375) for the `http-port` contract over Knative Serving (D441).
- Per-namespace tenancy for Knative in `loams-operator`: Kubernetes namespaces, `NetworkPolicy`, `ResourceQuota`, `LimitRange` (D443).
- The gateway routes function traffic to Kourier's internal service (D442).
- `loams-knative-source`: Loams streams to any Knative sink; and Loams's events endpoint documented and tested as a Knative sink (D445).
- A usage-hooks conformance test proving Knative pods carry §27 §3.2's labels and that no meter runs (D444).

**Architecture:**
- **The runner is thin.** `KnativeRunner` server-side-applies a Knative `Service` and calls it; routing, authentication, authorization and rate limits stay in the gateway (§24 §5).
- **The operator owns tenancy.** The runner never creates namespaces or policies; it fails with `RunnerError::NotProvisioned` if `loams-ns-<namespace>` does not exist.
- **Eventing is an adapter.** `loams-knative-source` is a separate binary that reads streams through the public consumer API and POSTs CloudEvents; it needs no engine internals.

**Tech Stack:** Rust 1.97.1, edition 2024, workspace lints. Workspace crates: `kube` 3 and `k8s-openapi` 0.27 (as the operator fork uses), `hyper` 1, `http` 1, `tokio`, `serde`, `serde_json`, `tracing`, `async-trait`, `thiserror`, `proptest`. Knative types: hand-written `kube::CustomResource` structs for the fields used (`Service.spec.template`, `status.conditions`, `status.url`), not a generated crate. Test tools: k3d with `--disable traefik`, the Knative Operator knative-v1.23.1 and Serving/Eventing knative-v1.23.0 with Kourier, gVisor `runsc` on the k3d node image (as F2 sets it up), pinned by digest. Task 0 checks versions, licences and that the k3d cluster with Knative fits the CI runner.

## Global Constraints

Same as the M1 overview §8, plus:
- **No meter (D444; integrity, D541).** `KnativeRunner::invoke` returns `usage: None`. No task writes a billing-grade record or emits usage events; the runner reports only to `InvocationObserver` (§27 §3.7), with no CPU figure it did not measure. A test in Task 4 enforces it, and `scripts/ci/no-metering.sh` (MT4 Task 8) backs it.
- **No public Knative route.** Every `Service` gets the label `networking.knative.dev/visibility: cluster-local`; a test asserts no `Ingress` with an external host is created.
- **Off by default.** The chart's `knative.enabled` is `false`; with it off, nothing in MT2 is deployed.
- **The build machine.** One cargo build at a time, the shared target, `-j 6`, lld. The k3d job runs only in CI, never alongside a cargo build on the build machine.
- **Commit areas:** `runner`, `operator`, `gateway`, `eventing`, `ci`, `docs`.

| 2 | **Annotations on every revision template**: `autoscaling.knative.dev/min-scale: "0"`, `autoscaling.knative.dev/max-scale: "<limit>"` (from the namespace's limits, default 10), `autoscaling.knative.dev/target: "<containerConcurrency × 0.7>"`, `features.knative.dev/http-full-duplex: "Enabled"` | Scale to zero by default; WebSocket and streaming need full duplex | Defaults are values in the operator's config |
| 3 | **Pod spec**: `runtimeClassName: gvisor` (unless Q444 makes it optional), `automountServiceAccountToken: false`, `securityContext.runAsNonRoot: true`, `readOnlyRootFilesystem: true`, `seccompProfile: RuntimeDefault`, one container listening on `$PORT` (Knative sets it), `resources.requests` and `limits` from the manifest within the `LimitRange` | §24's T2 isolation; §19 P6 (no long-lived secrets) | A tenant image that writes to `/` fails; documented, with an `emptyDir` at `/tmp` |
| 4 | **Invoke path, encrypted on every hop**: HTTP/2 over TLS to Kourier's internal TLS listener, with Knative's `cluster-local-domain-tls: enabled` and `system-internal-tls: enabled` (activator and queue-proxy) and certificates from cert-manager; the runner verifies the certificate. There is **no cleartext fallback**: `KnativeRunner::health` fails and the gateway refuses to dispatch if TLS is off, because the Biscuit in `x-loams-sandbox-token` is a bearer token (D361: h2c only on loopback). Target `kourier-internal.kourier-system.svc.cluster.local:443` with `Host: fn-<id>.loams-ns-<ns>.svc.cluster.local`; headers `traceparent`, `x-loams-sandbox-token` (the per-invocation Biscuit, D182), `x-loams-invocation-id`; timeouts from the manifest (default 30 s, max 900 s) | One address for all functions; Kourier routes by `Host` | Q446 may replace Kourier with `net-gateway-api` |
| 5 | **Idempotent deploy**: the `Service` carries the annotation `loams.dev/artifact-digest`; `deploy` with the same digest and the same resolved spec is a no-op that returns the existing `Deployment`; a changed digest creates a new revision and routes 100% to it after it is `Ready` | D375: idempotent by digest | None |
| 6 | **`NetworkPolicy`** per `loams-ns-*`: deny all; allow ingress from pods labelled `app=3scale-kourier-gateway` in `kourier-system` and from Knative's activator in `knative-serving`; allow egress to the gateway and `loams-dapr` services, to kube-dns on 53/UDP and TCP, and to CIDRs in the namespace's egress allow-list (default empty) | §38 §3.3 | A self-hoster on a CNI without `NetworkPolicy` gets none; the operator logs a warning once |
| 7 | **`loams-knative-source`**: one `Deployment` per `LoamsSource` (`sources.loams.dev/v1alpha1`) with `spec.namespace`, `spec.stream`, `spec.consumerGroup`, `spec.sink` (a Knative `Destination`: `ref` or `uri`), `spec.ceOverrides`; delivery is binary mode with `ce-*` headers rebuilt from the record (§02 §7.4); retry with exponential backoff (100 ms to 30 s) on 429, 5xx and timeouts; offsets committed after each 2xx batch; a record that fails 10 times goes to the stream `<stream>.dlq` | Knative sources' usual contract; at least once | Exactly-once is the sink's job (dedupe on `source` + `id`) |

**Files:** `deploy/helm/loams-stack/charts/knative/`, `scripts/k3d/knative-up.sh`, CI job `knative`.

### Task 2: Per-namespace tenancy in the operator

**Files:** the operator's namespace controller.

**Produces:** on a Loams namespace's creation, `loams-ns-<namespace>` (Ruling 1) with labels, Ruling 6's `NetworkPolicy`, a `ResourceQuota` (`requests.cpu`, `requests.memory`, `limits.cpu`, `limits.memory`, `pods`, `count/services.serving.knative.dev`) and a `LimitRange` from the namespace's limits record; deletion through a finalizer that waits for the namespace's `Service`s to go.

**Tests:** `namespace_created_with_policy_quota_limitrange`; `long_names_are_hashed_stably`; `policy_denies_cross_namespace` (a pod in one tenant namespace cannot reach a function in another); `function_pod_has_no_sa_token`; `quota_blocks_extra_pods`; `finalizer_waits_for_services`.

**Commit:** `operator: Kubernetes tenancy per Loams namespace for Knative`.
