**Goal:** Ship:
- `operon-client`, a Python SDK (sync and async) for the native REST API: namespaces, streams (produce/fetch), collections, documents (dense and sparse vectors), the hybrid query IR (sparse retrievers included, overview A29) through a typed builder, SQL, consistency tokens, typed errors and retries, with an optional `flight` extra that returns Arrow tables over Flight SQL and bulk-loads Arrow data into collections and streams through Flight SQL ingest (D49), `to_arrow()` and `to_polars()` on query and SQL results through the Arrow PyCapsule interface (optional extras `arrow` and `polars`, D54), and a thin `scan_plan()` over M1.2's scan-plan route (D53);
- `@operon/client`, a TypeScript SDK with the same REST surface (`scanPlan()` included), `fetch`-based, zero runtime dependencies, ESM with types, for Node ≥ 22 and browsers; it has no Arrow results in M1 (Ruling 17);
- `operon-mcp`, the W0 MCP server (design §15 §10.1, §13 row W0): five tools (`search`, `sql`, `memory_write`, `list_collections`, `get_documents`) on MCP 2026-07-28, stateless, mounted at `/mcp` on the native REST listener, so Claude Code, Codex and opencode can use Operon as a tool server;
- a shared wire-fixture corpus that the server and both SDKs test against, so the three stay in step.

**Architecture:**
- The SDKs speak only the native REST API (overview §6.8). Each SDK has exactly one module that knows the wire JSON (`operon/_wire.py`, `src/wire.ts`); everything else works on the SDK's own types. Task 0 reconciles that module with the as-built M1.2 API; the corpus in `sdks/fixtures/` pins it (Task 1).
- Python: `httpx` for the sync and async transports, frozen `dataclasses` for every value type, one pure encoder/decoder shared by `Client` and `AsyncClient`. Flight SQL queries and ingest (`adbc_ingest`) go through ADBC (`adbc-driver-flightsql`), imported only by `operon.flight`. Arrow and Polars conversions live in `operon.arrow`, imported only when `to_arrow()`, `to_polars()` or `__arrow_c_stream__` is called.
- TypeScript: global `fetch` and `AbortSignal`, lossless u64 ids through `JSON.parse` source-text access and `JSON.rawJSON`, compiled by `tsc` to `dist/` (ESM + `.d.ts`); tests with `node:test` against the built output.
- `operon-mcp`: an `rmcp` 3.4.1 `ServerHandler` over `CollectionService` (gateways never reach storage: overview §8). It is served by `StreamableHttpService` with `NeverSessionManager`, `legacy_session_mode(false)` and `json_response(true)`, and nested into the `operon` binary's axum router with `nest_service("/mcp", …)` behind the `mcp` cargo feature (on by default).
- CI: one job builds the `operon` debug binary once; `sdk-python` and `sdk-typescript` download it and run their suites against a spawned `operon dev`.

## Global Constraints

Same as the M1 overview §8, plus:
- Python SDK: pure Python, no compiled extensions, Python ≥ 3.10; runtime dependencies are exactly `httpx` and `anyio` (plus the optional extras: `flight`'s three, `arrow`'s `pyarrow`, `polars`'s `polars` and `pyarrow`). `import operon` imports none of the extras' packages. `ruff check`, `ruff format --check`, `mypy --strict src tests` and `pytest` pass after every Python task.
- TypeScript SDK: zero runtime dependencies; nothing under `src/` imports a Node built-in or uses `process`, `Buffer` or `require`, so the build runs in browsers. `biome check`, `tsc` (build and test configs) and `node --test` pass after every TypeScript task.
- Both SDKs: every wire-format fact lives in the one wire module; JSON is never produced with a non-finite number (checked before sending); u64 ids never lose precision.
- SDK tests reach no network except the `operon dev` child they spawn on `127.0.0.1:0`.
- `operon-mcp` opens no listener of its own: it is served only through the native listener. It never calls a storage, meta or log API directly: only `CollectionService`.
- Commit areas used by this plan: `sdk`, `mcp`, `operon`, `ci`, `docs`, and `query` only for Task 4's Flight token commit (O-M16-2; Task 8's conditional `ensure_namespace` commit is dropped by E18).

## Assumed native wire contract

Derived from overview §6.5–§6.8 and the M0 API as built (`crates/operon/src/api/`, a directory since M1.2). Rules: JSON bodies are the serde form of the IR types with `snake_case` field names and `snake_case` enum variants, externally tagged (unit variants are strings, struct variants are single-key objects); `Option::None` is `null`. **Every row is an assumption for Task 0 to diff** except those marked "M0".

**Ids (`PrimaryKey`)**: a JSON integer in `0..=18446744073709551615` is `U64`; a JSON string is `Str`; `{"uuid": "<8-4-4-4-12 lowercase hex>"}` is `Uuid`. **Consistency token**: the §6.5 text form, e.g. `"v1:s7/p3@918274,s7/p4@12"`; grammar `v1:` then zero or more items `s<dec>/p<dec>@<dec>` joined by `,`, `<dec>` = `0` or a non-zero digit followed by digits. **Error body** (M0): `{"error": code, "message": text, …extra}`.

Tests: Task 2 `test_long_poll_longer_than_the_client_timeout_does_not_time_out`; Task 5 `a long poll longer than timeoutMs does not time out`, `an aborted request is not retried`.

3. **Errors.** A non-2xx response whose body parses as a JSON object with a string `error` is mapped by `error` code (table in the wire contract); an unknown code is mapped by status (400 → `InvalidArgumentError`, 404 → `NotFoundError`, 409 → `ConflictError`, 416 → `OffsetOutOfRangeError` when the three extras are present, else `OperonError`, 503 → `UnavailableError`, 504 → `OperonTimeoutError`, other 5xx → `InternalError`, else `OperonError`), keeping `code` as sent. 4. **Retries (Ruling 5).** Attempt `n` (1-based) of a retry sleeps `min(backoff_max, backoff_base * 2 ** (n - 1)) * (0.5 + 0.5 * random())`; when the response has `Retry-After` as an integer number of seconds `s`, it sleeps `max(that, s)`, and `s > 30` stops retrying. Produce (W4) is `idempotent = False`; every other request is `True`. After the last attempt the mapped error (or `TransportError` from the httpx error) is raised.
5. **Timeouts.** Each attempt uses `timeout`; a fetch with `max_wait_ms = w` uses `timeout + w / 1000` for that request.
6. **Tokens.** `ConsistencyToken.parse` accepts exactly the grammar in the wire contract, with stream and offset ≤ 2^64 − 1 and partition ≤ 2^32 − 1, and rejects duplicate (stream, partition) pairs. **Semantics:**
1. Encoding follows the wire contract's encoder rules exactly. `datetime.datetime` field values are encoded as RFC 3339 (`isoformat()`, a naive datetime raises `ValueError`); `datetime.date` as `YYYY-MM-DD`.
2. `q.text(str, fields=())` → `QueryString(query, default_fields=[])`; one field → `Match(field, query)`; several → `MultiMatch([(f, 1.0) for f in fields], query)`.
3. `SearchBuilder.build()`: when there are two or more retrievers and no `fuse()`, the fusion is `Rrf(60)`; with one or zero, `None` unless set. `limit` must be ≥ 1, `offset` ≥ 0, every `k` ≥ 1, otherwise `ValueError`.
4. Vectors: a `VectorLike` with `.tolist()` is converted with it; every element must be an `int` or `float` (not `bool`) and finite (`math.isfinite`), otherwise `ValueError` naming the vector; ints are sent as floats. A `SparseVector` is checked when constructed (equal lengths, unique non-negative indices below 2^32, finite values; otherwise `ValueError`) and sent in the given order: the server sorts it (overview A27).
5. Consistency (Ruling 6): `"strong"` sends nothing; `"eventual"` adds `"consistency": "eventual"` to W11/W13 bodies and `"consistency": "eventual"` in the SearchRequest; a token (or `str`, parsed) sets header `Operon-Consistency-Token` and, in W12, `"consistency": {"at_least": "<token>"}`; a `Pin` sends `"consistency": {"pinned": {"manifest_version": n, "token": "<token>"}}` in the W11, W12 and W13 bodies and no header (a pinned body wins on the server, M1.2 Task 11 rule 1). W12 bodies always carry `consistency` (`"strong"` by default).
6. `Collection.upsert/patch/delete` are `write` with one op per item; `write` sends one W10 request (atomic across partitions, §6.2), `idempotent = True`. An empty `ops` sequence raises `ValueError` without a request.
7. Decoding: `Hit.id` from `pk`; `SearchResponse.read_token` parsed; `CollectionInfo.raw` keeps the full object.
8. **`scan_plan`** (Ruling 18): one W15 request, `idempotent = True`. `at` encodes as `"current"`, `{"manifest_version": n}` (an `int` ≥ 0; `bool` → `TypeError`) or `{"token": "<text>"}` (a `ConsistencyToken`, or any other `str` parsed as one: `ValueError` if it does not parse). Decoding keeps every key in `raw`; `ScanFragment.files` are the file paths, `deletion_file` its path or `None`; `lance.version` is a Python `int` (a detached id exceeds 2^63). `ScanPlan.pin` is the plan's `pin` as a `Pin`. The SDK does not open Lance and does not interpret fragments: M2 builds readers on this (D54).
9. `README.md`: install (`pip install operon-client`, `pip install "operon-client[flight]"`, `[arrow]`, `[polars]` — from a checkout with `uv pip install -e sdks/python` until publication), a quickstart (namespace, collection, upsert, hybrid search, SQL), consistency tokens, the retry policy and the produce caveat (Ruling 5), error classes, sync vs async, the ids rule (int/str/UUID), and a "Scan plans" section: what a plan is (D53), `tail` and reading the same state with `consistency=plan.pin`, `expires_at_ms − planned_at_ms` as the time left, that the plan carries no credentials (M1 readers bring their own), and a pylance snippet (`lance.dataset(plan.lance.uri, version=plan.lance.version)`, or the opener M1.2 Task 0 step 5 recorded), with the note that Ray, Polars and torch readers arrive in M2.
