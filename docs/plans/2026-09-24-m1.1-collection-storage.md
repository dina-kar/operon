# M1.1 — Collection Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, formats, constants), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Done** (2026-09-25). Tasks 1–14 are committed on `m1.1-collection-storage`. The rulings made during execution and the deviations that change documented behaviour are in "Rulings made during execution"; the design documents (§01 §6, §03 §3–§7, §06 §2, §5, §9, §11, §13 decision log) record the as-built formats.

**Goal:** Build the durable collection: a collection catalog in the metastore (collections with an implicit stream and link, aliases, additive schema evolution, drop), the `DocOp` record format, atomic multi-partition appends, and a Lance dataset plus Tantivy splits under one collection manifest. Commits use a fenced, freshness-checked CAS. Upserts, patches and deletes resolve through the PK index and delete bitmaps. Documents carry named dense and named sparse vectors (sparse: a Lance column plus postings inside the split, overview A26–A28, R22). Ship the `collection` link target, vector and scalar index builds, collection GC roots, a minimal read API for M1.2, and the M0 gates extended to collections. It closes the M0 items the overview §9 carries into M1.1.

**Architecture:**
- `operon-common` gains `CollectionId` and the schema types (`schema` module). The metastore's commands must carry them, and `operon-meta` cannot depend on `operon-collection` (Ruling 6).
- `operon-meta`:
  - adds the collection catalog: `CreateCollection` creates the collection, its implicit stream and its link in one command; `DropCollection` frees the name at once and retires the collection's prefixes;
  - adds `UpdateCollectionSchema` (additive) and `UpdateAliases`;
  - reserves `_` names, moves to snapshot format v5, and extends `check_invariants`.
- `operon-log` gains `LogWriter::append_many`, which puts every partition's batch of one request in one WAL object and one `CommitWal`. Its GC learns about retired prefixes and gets two new `GcRoots` hooks.
- `operon-quickwit` holds Quickwit files vendored from `af0591a3`, adapted to tantivy 0.26.2, behind a small shim:
  - split bundle and footer, hotcache, async directories and warmup;
  - ES DSL → `QueryAst` → Tantivy;
  - the doc-mapper query builder and its warmup types;
  - aggregation merge glue and `StableLogMergePolicy`.
- `operon-text`:
  - analyzers;
  - the Tantivy schema mapping;
  - the split writer and reader, over a Quickwit `Storage` implemented on `operon-store` and `operon-cache`;
  - the delete-bitmap format.
- `operon-collection`:
  - `PrimaryKey`, `partition_of`, `SparseVector`, `DocOp` and the record codec;
  - value extraction and validation, and the dynamic-mapping function;
  - `CollectionWriter` and `ConsistencyToken`;
  - the Lance integration (object store provider, Arrow schema, detached commits: Ruling 1);
  - the manifest codec;
  - `CollectionSnapshot` (the read API M1.2 builds on);
  - `CollectionTarget: LinkTarget` and the index-build task source;
  - `CollectionGcRoots` and `PkGcRoots`.
- `operon-link` replaces the hard-wired `CounterTable` with a `TargetRegistry` of `LinkTargetFactory`s keyed by `TargetRef.kind`.
- `operon` registers the collection target, the index-build source and the new GC roots, and validates every freshness deadline against GC's grace at startup. The crash gate, the fault matrix and the simulation cover the collection commit path.

## Global Constraints

Same as the M1 overview §8, plus:
- **Lance lineage:** after a dataset's creation commit, no code path may call a Lance API that commits to the mainline history. This includes `Dataset::append`, `delete`, `add_columns`, `create_index`, `optimize_indices`, `commit_compaction`, `CommitBuilder::execute` without `with_detached(true)`, and `cleanup_*`. Every Lance commit goes through `LanceCommitter::commit` (Task 7). A test (Task 7) fails if a mainline version other than 1 ever appears.
- Lance is always opened through `LanceEnv` (Task 7). It gets the Operon object-store provider, `ConditionalPutCommitHandler`, file format `V2_1`, stable row ids and `skip_auto_cleanup = true`. `WriteParams.auto_cleanup` is always `None`.
- `LinkTarget::load` has no side effects: it never opens a writer, never writes, and never fences anyone. (The HTTP link description calls it while a task runs.)
- The workspace must never enable `serde_json/preserve_order`, because vendored Quickwit code relies on sorted maps. A canary test (Task 2) fails if feature unification turns it on. **Amended by M1.3 (row E58):** `qdrant-edge` needs `preserve_order`, so the workspace enables it for every build; the vendored Quickwit tests pass with it, and the canary now fails if the feature is dropped.
- The PK index is written only by the collection link-apply task of its collection, and only after a successful manifest CAS.
- Commit areas used here: `common`, `collection`, `text`, `meta`, `log`, `link`, `store`, `sim`, `operon`, `ci`, `docs`, plus `quickwit` for `operon-quickwit` (overview §8, A25).

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **The R7 mechanism is Lance detached versions.**<ul><li>Each dataset has exactly one mainline version, version 1: an empty dataset with the four system columns, made by the first commit.</li><li>Every later Lance commit is `CommitBuilder::new(Arc<Dataset>).with_detached(true).execute(txn)` on a `Dataset` checked out at the parent manifest's `lance_version`. Lance then builds the new manifest from exactly that dataset's manifest (`do_commit_detached_transaction`, `lance-12.0.0/src/io/commit.rs:1113`, no rebase). It writes it create-only at `_versions/d<random u64 with bit 63 set>.manifest`.</li><li>The collection manifest's `lance_version` holds that detached id. The Operon CAS is the only linearization point.</li></ul> | Lance's mainline commit loads every newer version and rebases onto it before its **first** attempt, even with `num_retries = 0` (`commit_transaction`, `io/commit.rs:1391-1471`). A zombie's or crashed writer's version N+1 would be absorbed, and version numbers are deterministic paths, so an orphan at N+1 would block every commit based on N forever. Detached versions have unique paths and never rebase. Lance documents this use: "secondary datasets whose lineage is tracked elsewhere" (`dataset/write/commit.rs:190`). Rejected alternatives: `ConditionalPutCommitHandler` on the mainline (it rebases, and orphans block); `ExternalManifestCommitHandler` over meta (still rebases onto the external store's latest, and still copies to deterministic final paths); restore-then-commit (a zombie can land between the two). | <ul><li>Detached version ids are random, so Lance code that compares versions numerically is meaningless on our datasets: frag-reuse remapping, data overlays, the conflict resolver. We never use those, so M1.3 compaction must use stable-row-id compaction without deferred remap.</li><li>External Lance tools see only the empty version 1 unless given a detached id.</li></ul> |
| 2 | **Lance's cleanup is never called.** `CollectionGcRoots` computes Lance reachability itself, from the Lance manifests of the retained chain (Ruling 12, Task 12). This amends R19 ("via `cleanup_with_policy(versions(..))`"); adopted as overview A15. | Lance cleanup lists only mainline manifests (`cleanup.rs:527-541`; detached ones are skipped at `lance-table/src/io/commit.rs:583`). It would treat every file referenced only by detached manifests as unverified and delete it once it is 7 days old (`cleanup.rs:1-33`, `:720-723`). | Our GC must know Lance's file classes (`data/`, `_deletions/`, `_transactions/`, `_indices/<uuid>/`, `_versions/d*.manifest`). | 4 | **Typed fields are not Lance columns.** The Lance schema is `_pk`, `_source`, `_ingest_partition`, `_ingest_offset` (the partition and offset of the record that last wrote the document, returned as `StoredDoc.seq_no`), one `_vector_<i>` column per `VectorSpec` and one `_sparse_<j>` column per `SparseVectorSpec` (Task 7). Typed fields live in Tantivy (indexed and fast fields) and are always re-derivable from `_source`. | R4/R5: Tantivy filters, sorts and aggregates. A field may be single- or multi-valued per document (ES), which has no natural Arrow type. Schema evolution of fields then never touches Lance. | M1.2's SQL projects typed fields from `_source` (a JSON UDF) or fast fields, not from Lance columns. Lance scalar indexes exist only on `_pk`. |
| 5 | Vector columns (dense `_vector_<i>` and sparse `_sparse_<j>`) are added lazily. Version 1 has only the system columns. A commit whose collection schema has a vector that the parent Lance schema lacks first commits a detached `Operation::Merge` with that column all-null (metadata-only, `schema_evolution.rs:354-377`), then its data transaction on top. Only the data version is referenced. | Makes version 1 identical no matter who creates it, so a creation race is harmless. It also means adding a vector (`UpdateCollectionSchema`) needs no Lance step at update time. | One extra Lance manifest per vector addition. |

| 7 | **PK index = derived state with a watermark, repaired from per-commit delta objects.**<ul><li>Every link-apply commit that changes keys writes a `pkdelta/…pkd` object, referenced by the manifest.</li><li>The PK index stores `pk → row id` and, under the reserved key `0x00 "watermark"`, the `applied` map it reflects.</li><li>On repair, the task replays the deltas of the live manifest's chain newer than the watermark. If an ancestor is gone, it rebuilds from Lance.</li><li>A PK handle is reused across task runs only while its watermark equals the parent manifest's `applied`.</li></ul> | R8. The PK index can lag the pointer by at most one link-apply commit (the CAS happened, the PK write did not). The stream may be trimmed, so the deltas cannot be re-derived from it. | One small object per commit. |
| 8 | Split docs are written with `SingleSegmentIndexWriter`, so a split has one segment and doc id *i* is the *i*-th document added. ## Review Focus

1. **A zombie or crashed writer's Lance version** (R7). A task that committed a Lance version and then died or was fenced before its CAS, or a zombie that commits concurrently with the live task, must never have its fragments in any live manifest, and must never block the next commit. Tests: Task 7 (`a_detached_commit_ignores_a_sibling_version`, `mainline_never_moves_past_version_one`), Task 10 (`a_crash_after_the_lance_commit_applies_the_batch_once`, `a_zombie_lance_commit_never_reaches_the_live_manifest`, `an_orphan_lance_version_at_task_start_is_ignored`), Task 13 (crash-gate rows `collection.after_lance_commit`, `collection.after_manifest_put`).
2. **A crash between the manifest CAS and the PK index write**, and a SlateDB writer fenced mid-run. The next run must repair the PK index before resolving any key, or an upsert would not delete the old row (a duplicate), and a patch would miss it. Tests: Task 10 (`a_crash_after_the_cas_repairs_the_pk_index_before_the_next_batch`, `a_fenced_pk_writer_ends_the_task`, `a_cached_pk_handle_is_reopened_after_another_writer_committed`), Task 13 (row `collection.after_cas`).
3. **Several ops on one key in one batch, and patches of missing keys.** Upsert then delete; delete then upsert; patch after delete; patch with `upsert`; a patch whose result violates the schema. Latest-wins per key, in partition order, with exactly one live row per key. Tests: Task 5 (the fold property test), Task 10 (`one_batch_with_upsert_patch_delete_on_one_key_leaves_the_fold_result`, `a_patch_of_a_missing_key_is_a_noop`, `a_patch_with_upsert_inserts_when_missing`, `a_patch_that_breaks_the_schema_is_dead_lettered`), Task 13 (simulation model).
4. **Dropping a collection and re-creating its name at once**, with the old link task still running and readers holding the old snapshot. The old task's commits must be refused. The new collection must share no objects with the old one. The old prefixes must survive `grace`, then vanish. **Semantics:**
1. **Wire format** (overview §6.2). postcard cannot carry `serde_json::Value`, so the value encodes these private wire types with postcard, after the version byte `0x01`:
   ```rust
   #[derive(Serialize, Deserialize)] enum WireOp { Upsert(WireDoc), Delete(PrimaryKey),
       Patch { pk: PrimaryKey, mode: PatchMode, source: Vec<u8>, delete_keys: Vec<String>,
               vectors: BTreeMap<String, Option<Vec<f32>>>, sparse_vectors: BTreeMap<String, Option<SparseVector>>,
               upsert: Option<WireDoc> } }   // variant order and field order are the format
   #[derive(Serialize, Deserialize)] struct WireDoc { pk: PrimaryKey, source: Vec<u8> /* UTF-8 JSON object, serde_json::to_vec */, vectors: BTreeMap<String, Vec<f32>>,
                                                      sparse_vectors: BTreeMap<String, SparseVector> }
   ```
   A `SparseVector` is postcard-encoded through `RawSparseVector` (two sequences), and decoding goes through `SparseVector::new`, so a record can never carry a non-canonical sparse vector: unsorted input is sorted, and a length mismatch, a duplicate index or a non-finite value is `Malformed`.
   `decode` fails on:
   - no key, no value, a version byte other than `0x01`, or trailing bytes after the postcard body;
   - a `source` that is not a JSON object, or a non-finite vector value (`Malformed`);
   - `key != op.pk().canonical()` (`KeyMismatch`);
   - an invalid key.
2. **`apply_patch`**:
   - With `current = None`: return `upsert.clone()` (its pk must equal the patch pk, else `None`). A patch of a missing key without `upsert` therefore changes nothing, at apply time and in the tail; `CollectionService` reports it to the caller as `OpResult::NotFound`, computed at request time (M1.2 Ruling 10, overview A24).
   - Otherwise, start from `current.source` and:
     - `MergeDeep`: for each `(k, v)` of the patch source, if both the existing and new values are objects, merge them recursively; otherwise `v` replaces (arrays replace, `null` sets `null`);
     - `MergeTop`: each top-level key replaces;
     - `Replace`: the source becomes the patch source.
   - Then, for each `delete_keys` path split on `.`: walk objects and remove the final key; a missing path is a no-op; arrays are not descended.
   - Then vectors: `Some(v)` sets, `None` removes; the same for `sparse_vectors`.
   - The pk is unchanged.
3. **`fold`**:

   | op | state becomes |
   |---|---|
   | `Upsert(d)` | `Some(d)` |
   | `Delete` | `None` |
   | `Patch` | `apply_patch(state.as_ref(), op)` |

   The initial state is `current`.

**Semantics:**
1. **Extraction (`extract`).**
   - Split `path` on `.` into segments. To resolve segments `s[i..]` against an object `O`: for every `k` from `i+1` to `n`, if `O` has the literal key `s[i..k].join(".")`, continue with that value and `s[k..]`. All matches are collected, so `{"a.b":1}` and `{"a":{"b":1}}` both give `a.b`.
   - An array value is transparent at every step: each element is continued, and nested arrays are flattened.
   - At the end of the path, a non-array value is one result, and an array contributes its flattened elements.
   - `null` contributes nothing to typed fields.
   - `path == ""` yields the whole source as one object (Json fields only).
2. **Coercion (`coerce`),** ES-compatible:
   - `Text`, `Keyword`: strings; numbers and bools become their JSON text.
   - `I64`: JSON integers in range; floats with a zero fraction and in range; strings that parse as `i64`.
   - `F64`: finite numbers; strings that parse as finite `f64`.
   - `Bool`: `true`/`false`, the strings `"true"`/`"false"`.
   - `Date`: `parse_date`.
   - `Uuid`: strings accepted by `uuid::Uuid::parse_str`, stored as bytes.
   - `Json`: never coerced here (Task 8 indexes it).
   - Objects or arrays at a scalar leaf are malformed. A malformed value is a `Violation` unless `ignore_malformed`, in which case it is skipped.
3. **`parse_date`:**
   - JSON integers are epoch milliseconds.
   - Strings are, in order: all digits (epoch milliseconds); RFC 3339 (`2024-01-02T03:04:05Z`, `2024-01-02T03:04:05.123+02:00`); `yyyy-MM-dd'T'HH:mm:ss[.SSS]` without an offset (UTC); `yyyy-MM-dd`; `yyyy/MM/dd HH:mm:ss`; `yyyy/MM/dd` (ES `strict_date_optional_time||epoch_millis` plus the dynamic-detection formats).
   - Anything else is malformed.
4. **Unmapped paths.**
   - The leaf paths of a source are the key paths (joined by `.`, arrays transparent) of every non-object leaf, excluding `null` and empty arrays.
   - A path is covered if some field has `source_path == path`, or a `Json` field has `source_path == ""`, or `path` equals or starts with `<json source_path>.`.
   - For `Strict`, every uncovered path is `Violation { field: path, message: "strict dynamic mapping: <path> is not mapped" }`.
   - For `Ignore`, uncovered paths are allowed.
   - For `Map`, uncovered paths give `DynamicMappingRequired { paths }`.
5. **Vectors in `check_document`:**
   - every name must be in `schema.vectors`, else a violation with field `"vectors.<name>"`;
   - `len == dim`, else a violation (`"expected <dim> dimensions, got <n>"`);
   - every value finite;
   - a missing vector is allowed;
   - every `sparse_vectors` name must be in `schema.sparse_vectors`, else a violation with field `"sparse_vectors.<name>"` (`"unknown sparse vector"`); the vector itself is already canonical (Task 5), and an empty one is allowed.
6. **`check_patch`:**
   - the patch source is checked like a document source, but with its own paths only (a partial document);
   - `vectors: Some(v)` like document vectors; `sparse_vectors: Some(v)` like document sparse vectors;
   - `upsert`, if present, is checked with `check_document`;
   - a `delete_keys` path that is empty or has an empty segment gives `InvalidArgument` (reported through a `Violation` with field `"delete_keys"`).
7. **`propose_dynamic_fields`** (ES 8 defaults):
   - Walk the sources in order and their uncovered leaf paths in sorted order. The first non-null value seen for a path decides (for an array, its first non-null element).
   - A string that `parse_date` accepts in a non-digit format gives `Date`. Other strings give `Text { analyzer: "standard", positions: true }` named `<path>`, plus `Keyword` named `<path>.keyword` with the same `source_path`. The subfield is skipped if that name exists.
   - A JSON integer gives `I64`; another number gives `F64`; a bool gives `Bool`.
   - Every proposed field has `indexed: true` and `ignore_malformed: false`, and `fast: true` except for `Text`.
   - A path whose field name would be invalid under `validate` (starts with `_`, contains `..`, and so on) is not mapped and stays in `_source`.
   - If `fields + vectors + proposed > max_fields`, return `TooManyFields`.
   - The output is deterministic: the same input gives the same list in the same order.
8. **`CollectionWriter::write`:**
   1. `ops.len() > MAX_WRITE_OPS` → `TooManyOps`.
   2. `Local` read of the collection (`CollectionNotFound` if absent).
   3. Validate every op: the pk, then `check_document` or `check_patch` (`Delete` needs only the pk); encode. A rejection gives `OpResult::Rejected`, with `SchemaViolation` taking the first violation.
   4. If any op was rejected for a schema-dependent reason (a violation or `DynamicMappingRequired`), re-read the collection once with `Consistency::Linearizable`. If its schema version is newer, redo step 3 for every op.
   5. Group the accepted records by `partition_of(pk, collection.partitions)`, keeping input order within a partition.
   6. `append_many(collection.stream, batches)` (skipped when nothing was accepted).
   7. Op *j* in partition *p* at position *i* gets `offset = ack.base_offset + i`.
   8. The token has `(stream, p, ack.last_offset + 1)` for every written partition, normalized.

   A `LogError` fails the whole call (`WriteError::Log`; nothing was written unless `CommitUnknown`).

**Semantics:**
1. **Provider.**

   - The unique authority keeps different `Store`s in one process from sharing Lance caches.
2. **`write_params()`:**
   - `data_storage_version: Some(LanceFileVersion::V2_1)` (R18), `enable_stable_row_ids: true` (R8), `enable_v2_manifest_paths: true`;

3. **`ensure_created`:**
   1. Try `DatasetBuilder::from_uri(uri).with_version(1)…load()`. If found, check that its Arrow schema's first four fields equal `base_arrow_schema()` (else `Corrupt`) and return it.
   2. If not found: `CommitBuilder::new(uri).with_session(..).with_commit_handler(..).use_stable_row_ids(true).with_storage_format(V2_1).enable_v2_manifest_paths(true).with_skip_auto_cleanup(true).execute(Transaction::new(0, Operation::Overwrite { fragments: vec![], schema: lance::datatypes::Schema::try_from(&base_arrow_schema())?, config_upsert_values: None, initial_bases: None }, None))`.
   3. If that fails with a commit conflict (another creator), load version 1 as in step 1.

   Version 1 is the only mainline version a collection ever has (Ruling 1).
4. **`LanceCommitter::commit`:**
   - `txn = Transaction::new(parent.manifest.version, operation, None)`;
   - `CommitBuilder::new(parent.clone()).with_session(..).with_commit_handler(..).with_detached(true).with_skip_auto_cleanup(true).with_max_retries(20).execute(txn)`.

   The result's `manifest.version` must satisfy `is_detached_version`, else `Internal`. A detached commit writes `_versions/d<version>.manifest` create-only. On a conflict (only a random-id collision) Lance draws a new id. After an ambiguous error it reads back and returns `Ours` if the manifest landed (`do_commit_detached_transaction`).
5. **`ensure_vectors`:** for each `(i, v)` of `schema.vectors` with no `_vector_<i>` in `parent`, and each `(j, s)` of `schema.sparse_vectors` with no `_sparse_<j>`:
   1. collect the missing Arrow fields;
   2. `new_schema = parent.schema().merge(&ArrowSchema(missing))?`, then `new_schema.set_field_id(Some(parent.manifest.max_field_id()))`;
   3. commit `Operation::Merge { fragments: parent.manifest.fragments.to_vec(), schema: new_schema, preserves_nullability: true }` through `commit`.
6. **`write_fragments`:** `InsertBuilder::new(parent.clone()).with_params(&write_params()).execute_uncommitted(vec![batch])` must return `Operation::Append { fragments }` (else `Internal`); return the fragments.
7. **`delete_rows`:**
   1. `index = get_row_id_index(parent)?` (`None` → `Internal`: stable row ids are required).
   2. Every row id is resolved with `index.get(id)` to a `RowAddress`. A miss is `Corrupt("row id <id> is not in lance version <v>")`.
   3. Group by fragment. For each fragment `f`: `parent.get_fragment(f).extend_deletions(offsets)`. `Some(ff)` pushes `ff.metadata().clone()` to the updated fragments; `None` pushes `f` to the removed ids.
8. **`new_row_ids`:** scan `committed` with `with_fragments(fragments whose id is not in parent)`, `project(&["_pk"])`, `with_row_id()`; return `(_pk bytes, _rowid)` pairs. This joins on the key rather than trusting Lance's write order.
9. **`open`:** `DatasetBuilder::from_uri(uri).with_version(version).with_session(..).with_commit_handler(..).load()`. A missing version is `NotFound`.

**Semantics:**
1. **Analyzers** (Ruling 25). Each is registered in `tokenizer_manager()` under its name.

     - The possessive filter removes a trailing `'s`, `'S`, `’s`, `’S`, `＇s` or `＇S` (U+0027, U+2019, U+FF07), as Lucene's `EnglishPossessiveFilter` does.
     - Removed stop words leave position gaps.
   - `simple`: `LetterTokenizer` → `LowerCaser`.
   - `whitespace`: `UnicodeWhitespaceTokenizer`, no lowercasing.
   - `keyword`: tantivy `RawTokenizer`.

2. **Porter.**

   - Words of ≤ 2 chars are returned unchanged. Vowels are `a e i o u`, plus `y` preceded by a consonant. Any other `char` is a consonant.
   - `PorterStemFilter` applies it to every token, like Lucene's `PorterStemFilter`.

**Semantics:**
1. **Envelope** (Ruling 19): `b"OPCM" | u16 LE 1 | prost body | crc32c u32 LE` over all preceding bytes. `decode_manifest` rejects:
   - a wrong magic, an unknown version or a crc mismatch;
   - a `ulid` that is not 16 bytes;
   - a `footer_start > footer_end`;
   - `row_id_ranges` that are unsorted, overlapping or empty-ranged, or whose total length ≠ `doc_count`;
   - `kind == UNSPECIFIED`.

   Empty strings decode to `None`.
2. The manifest for pointer version *v* has `version == v`. The pointer `collection/<cid>` holds its full path, and its pointer version equals the manifest version.
3. **`RowLocator`:** the ranges of all splits form one sorted list. Two splits overlapping is `Corrupt`. `doc_base` is the doc id of the range's first row: the sum of the previous ranges' lengths in that split.
4. **`retained_chain`:**
   - Element 0 is `live`.
   - Walk the parents through `parent_manifest`. The ancestor at distance *d* (1-based) is included iff `d <= keep_manifests || child.created_at_ms + retention_ms > clock_ms`, where `child` is the manifest at distance *d* − 1, the one that superseded it (overview A21: retention runs from supersession, so a pin on a long-lived manifest does not expire the moment it is superseded).
   - The walk stops at the first ancestor that fails, at the root, or at a parent that no longer exists (`NotFound`).
   - The result is a prefix of the chain, so it only shrinks as the clock advances or new commits arrive (Ruling 12).
5. **`CollectionSnapshot::open`:**
   1. Read the collection and its pointer in one metastore read with `consistency`; a missing collection is `NotFound`.
   2. No pointer means `CollectionManifest::empty` and no dataset.
   3. Otherwise load the manifest (`ManifestCache`) and open the Lance dataset at `lance_version` (skipped when 0). Splits open lazily.
6. **`open_version(v)`:** the live manifest's `retained_chain` (clock from a `Linearizable` read of `clock_ms`) must contain version *v*, else `ManifestGone(v)`.
   **`at(..)`:** exactly step 3 of `open` for the given manifest (open the Lance dataset at `lance_version`, skipped when 0, and build the `RowLocator`); `open` and `open_version` are implemented on top of it.
7. **`take_rows`:**
   - `dataset.take_rows(ids, [_pk, _source, _ingest_partition, _ingest_offset, every _vector_<i> and _sparse_<j> present])`, mapped through `row_from_batch`;
   - `seq_no = _ingest_offset`; dense and sparse vectors that are null are absent;
   - a row id the version does not have gives `None`.
8. **`get_by_pk`:** a scan with `filter_expr(col("_pk").in_list([lit(ScalarValue::Binary(Some(canonical)))…], false))`, projected like `take_rows`, plus `with_row_id()`, and matched back to the input order. The BTREE index on `_pk` serves it when present (Task 11).
9. **`scan_all`:** a full scan (with row ids), sorted by canonical PK. Tests and small collections only; M1.2 streams.

**Semantics:**
1. **Registry dispatch.**
   - `LinkApplySource::candidates` proposes a task for every link whose `target.kind` has a factory, via `factory.open(meta, &link)`.
   - A link of an unregistered kind is recorded in `unregistered()` and logged once per link id with `tracing::warn!(link, kind, "no target is registered for this link kind; it is not applied")`.
   - `ApplyTask` is unchanged. The counter target is served by `CounterTargetFactory`, with the same behaviour as today.
2. **`CollectionTarget::load`** (side-effect free, M9):
   1. A `Local` read of `collection_for_link(link)`. None → `LinkError::NotFound("collection of link <id>")`, so a dropped collection's task stops (`TaskError::Failed`) and its link is no longer a candidate.
   2. `live_manifest(.., Local)`. Return `TargetState { version: manifest.version or 0, applied }` and remember `(path, manifest)` as the parent.
3. **`CollectionTarget::commit(expected_version, batch, fence)`**, in exactly this order:
   1. `started = meta.now_ms()`. The parent is the remembered manifest if its version == `expected_version`, else reload. A different version is `Conflict`.
   2. Read the collection (`Local`) for its schema *S* (current version) and stream. A dropped collection is `NotFound`.
   3. **PK handle** (Ruling 7):
      - reuse the cached handle iff its watermark's `applied == parent.applied`;
      - otherwise close it, `PkIndex::open(store, collection_pk_prefix(ns, cid), PkIndexConfig::default())` (this fences every other writer), and repair (rule 5).

      `PkError::Fenced` anywhere is `CommitError::Fenced`, and the cache is dropped.
   4. **Decode** every record:
      - `codec::decode` errors are dead letters with reason `"undecodable: <error>"`;
      - group the ops by key in batch order (the partition order per key, since a key lives in one partition).
   5. **Resolve**, in rounds of `max_lookup_batch` keys:
      - `PkIndex::get` every key → the old row id or none;
      - for keys where `needs_current(ops)` and an old row exists, `take_rows` from the parent dataset gives the current document;
      - `fold` each key.

      Apply-time validation of each Upsert document and each patch result uses `check_document` with the schema's `dynamic` treated as `Ignore`: unmapped paths never fail at apply time, since `dynamic` may have changed since the write. A failing op is a dead letter with reason `"schema: <field>: <message>"` and is skipped: the fold continues from the state before it.

      Outcome per key:
      - *upsert-row*: the final state is present and differs from the committed one, or no row exists;
      - *delete-row*: the final state is absent and an old row exists;
      - *unchanged* otherwise.

      An upsert-row with an old row also deletes the old row.
   6. **Lance**, only if some row is inserted or deleted:
      - the base is `LanceEnv::open(lance_version)`, or `ensure_created` when the parent's `lance_version == 0`;
      - `ensure_vectors(S)`;
      - new rows: `to_record_batch(S, rows)` in canonical-PK order, with `(partition, offset)` of the last op that wrote each document; `write_fragments`;
      - `delete_rows(old row ids)`;
      - commit `Operation::Update { removed_fragment_ids, updated_fragments, new_fragments, fields_modified: vec![], compacted_sstables: vec![], fields_for_preserving_frag_bitmap: vec![], update_mode: None, inserted_rows_filter: None, updated_fragment_offsets: None }`, or `Operation::Append { fragments }` when nothing is deleted, through `LanceCommitter::commit`.

      Then `failpoint!("collection.after_lance_commit")` and hook `AfterLanceCommit`.
   7. **Row ids:** `new_row_ids(committed, base)` → pk → row id for every inserted row; the count must equal the rows written (else `Internal`).
   8. **Split:**
      - Tantivy docs for the inserted rows in ascending row-id order (`tantivy_layout(S)`, `to_tantivy_doc`); `build_split`; `put_if_absent(split_path(ulid))`.
      - `SplitRef { doc_count, deleted_count: 0, size_bytes, footer_range, row_id_ranges: maximal runs, delete_bitmap: None, schema_version: S.version, created_at_ms: started, merge_ops: 0 }`.
      - **Delete bitmaps:** locate every deleted old row id with the parent's `RowLocator` (a miss is `Corrupt`). Per affected split, new bitmap = old bitmap (decoded from its current path) ∪ the new doc ids, written to `delete_bitmap_path(split, ulid)`; update `deleted_count` and `delete_bitmap`. A split whose `deleted_count == doc_count` is removed from the manifest.

      Then `failpoint!("collection.after_split_put")` and hook `AfterSplitPut`.
   9. **Side objects:**
      - the PK delta `[(pk, Some(new row id)) for upserts] ∪ [(pk, None) for deletes]`, sorted, if non-empty, at `pk_delta_path(v+1, ulid)`;
      - the dead letters, if any, at `dead_letters_path(v+1, ulid)`, each also logged at WARN.
   10. **Manifest** v+1:
       - `parent_version = v`, `parent_manifest = parent path`;
       - `lance_version` = the committed version (or the parent's, if Lance was not touched);
       - `splits` = the parent's, updated, plus the new split;
       - `vector_indexes` and `scalar_indexes` recomputed from the committed dataset's `load_indices()`: segments whose uuid the parent listed keep their `indexed_row_ids_upto`, others are dropped (the index builder adds them);
       - `applied` = the parent's, overlaid with `batch.applied_after`;
       - `live_doc_count = parent + inserted − deleted`;
       - `kind = LinkApply`, `schema_version = S.version`;
       - `dead_letters_total` and `skipped_offsets_total` = the parent's + this batch's (skipped = offsets in `(prev, applied_after)` with no record);
       - `created_at_ms = started`.

       `put_if_absent(manifest_path(v+1, ulid))`. An `AlreadyExists` on our own unique path is accepted only if the stored bytes are identical. Then `failpoint!("collection.after_manifest_put")` and hook `AfterManifestPut`.
   11. If `meta.now_ms() − started > max_commit_delay`: `Other(Blocked)`, and nothing is CAS'd (the objects are left to GC).
   12. **CAS:** `cas_pointer_fresh(ns, "collection/<cid>", expected = (v > 0).then_some(v), value = manifest path, fence = Some(fence), fresh = Some(Freshness { created_at_ms: started, max_age_ms: max_commit_delay }))`.
       - `VersionMismatch` whose `current == Pointer { version: v+1, value: our path }` is our lost acknowledgement: success.
       - Any other `VersionMismatch` → `Conflict`; `Fenced` → `Fenced`.
       - `StaleObject` → `log_stale_object`, then `Other(Blocked)`.
       - `CollectionNotFound` (dropped) → `Other(NotFound)`.

       Then `failpoint!("collection.after_cas")` and hook `AfterCas`. Remember the new manifest as the parent.
   13. **PK write:** one `PkIndex::write` of the delta entries plus `PK_WATERMARK_KEY → 0x01 ‖ postcard(PkWatermark { v+1, applied })`.
       - `Fenced` → drop the cache and return `CommitError::Fenced`. The commit landed; the next task repairs.
       - Another error → drop the cache, log, return `Ok(v+1)` (the next commit repairs).

       Then `failpoint!("collection.after_pk_write")` and hook `AfterPkWrite`.
   14. Return `Ok(v+1)`.

   If the batch changes nothing (no rows, only no-ops, dead letters or skipped offsets), steps 6–9 write nothing except the dead letters, and the manifest keeps the parent's Lance version and splits.
4. **Failpoint names:** `collection.after_lance_commit`, `collection.after_split_put`, `collection.after_manifest_put`, `collection.after_cas`, `collection.after_pk_write`. `operon-collection` gets a `failpoints` feature (`dep:fail`, `fail/failpoints`, and the same features of `operon-link`, `operon-log` and `operon-meta`) and the local `failpoint!` macro.
5. **PK repair** (a fresh handle, parent manifest *P*):
   1. Read the watermark *W* (absent → `PkWatermark::default()`). If `W.applied == P.applied`, done.
   2. Walk from *P* through `parent_manifest`, collecting manifests newest first, until one has `applied == W.applied`, or the root is passed with `W == default`.
   3. Apply the `pk_delta`s of the collected link-apply manifests, oldest first (last wins per key), plus the watermark `{P.version, P.applied}`, in one `write`.
   4. If the walk meets a missing manifest, or a manifest whose `pk_delta` object is gone, **rebuild** instead:
      1. scan `(_pk, _rowid)` of `P`'s Lance version;
      2. `scan_prefix` every key under `0x01`, `0x02` and `0x03`;
      3. write puts for the scan, deletes for keys absent from it, and the watermark last, in chunks of 10 000 entries.

      An interrupted rebuild keeps the old watermark and runs again.
6. **Lost acknowledgements:** every create-only PUT of our own unique path treats `AlreadyExists` as success if the bytes are identical. Lance's detached commit verifies its own outcome (Task 7).
7. **`api.rs`:**
   - `AppState` gains `registry: TargetRegistry`.
   - `GET /v1/namespaces/{ns}/links/{link}` adds `"version"` and `"applied"` for **every** registered kind, from `factory.open(..).load()`. The counter-only fields stay.
   - `LinkError::Target { retryable: true, .. }` → 503, `retryable: false` → 500.
   - In the fault matrix, `link_retryable` returns `retryable` for `Target`.
8. **`verify_collection` checks**, used by the gates. Each failure is one message.
   1. `scan_all` keys == `expected` keys.
   2. Per key: `source`, `vectors`, `sparse_vectors`, `partition` and `seq_no` equal `expected` (so each acknowledged op is reflected in its latest-wins result).
   3. Exactly one live Lance row per key.
   4. `Σ over splits (doc_count − deleted_count) == manifest.live_doc_count == expected.len()`.
   5. Every live split doc's `_rowid` is a live Lance row whose `_pk` equals the doc's `_pk`, and every live Lance row id is exactly one live split doc (exactly-once across both stores).
   6. If the PK watermark equals `manifest.applied`, the PK index (read with `PkReader`) maps each key to its live row id and has no other keys.

**Semantics:**
1. **GC pass 1 with retired prefixes** (Ruling 13). A due retired entry ending in `/` is a prefix:
   - `store.list(prefix)`; if the listing is empty, `forget_objects([prefix])`;
   - else delete up to the remaining `list_page` budget of the listed objects (with `confirm_lease`), and forget only after a later listing is empty.

   Other entries are unchanged.
2. **GC pass 3b:**
   1. Read the clock.
   2. Call `reachable`, then `kept_prefixes` (an error in either skips the prefix, with a warning).
   3. List `ns/<ns>/<prefix>` and delete the objects that are not reachable, not under a kept prefix, and whose `root.object_time_ms(info) + grace <= clock`.
3. **`CollectionGcRoots::reachable`:**
   1. One `Linearizable` read gives every collection of the namespace with its pointer value, and `clock_ms`.
   2. For each collection with a pointer: `chain = retained_chain(live, keep_manifests, time_travel_retention, clock)`. For each manifest of the chain, keep:
      - its own path;
      - every split path and delete-bitmap path;
      - its `pk_delta` and `dead_letters`.
   3. For each distinct non-zero `lance_version` of the chain, open the dataset and keep, under `lance_prefix`:
      - its manifest file (`manifest_location().path`);
      - `_transactions/<manifest.transaction_file>`, if set;
      - `data/<file.path>` for every data file of every fragment;
      - `_deletions/<relative_deletion_file_path(..)>` for every deletion file;
      - every object listed under `_indices/<uuid>/` for every index uuid it references.
   4. For every collection (with or without a pointer), list `lance_prefix` and keep every object outside the collectable classes (`data/`, `_deletions/`, `_transactions/`, `_indices/`, `_versions/d*.manifest`). This keeps the mainline version 1 and any file class Lance adds later (Ruling 2).
   5. Any read error fails the call, so the prefix is skipped this run.
4. **`CollectionGcRoots::kept_prefixes`:** the retired prefixes (from `retired()`) under `ns/<ns>/collections/`. They belong to pass 1 after their grace.
5. **`CollectionGcRoots::object_time_ms`:** `info.last_modified_ms` for paths containing `/lance/` (Lance names carry no ULID); otherwise the default.
6. **`PkGcRoots`:** `reachable` is empty. `kept_prefixes` = `collection_pk_prefix(ns, cid)` for every collection of the namespace, plus the retired `ns/<ns>/pk/…` prefixes. So a live PK index is never touched (SlateDB collects its own files), and an unknown id's objects go after `grace`.
7. **`CollectionTrimSource`:**
   - One task per collection, at most once per `trim_interval`. With `config.trim == false` the task returns `Idle`.
   - Run:
     1. `live_manifest(Linearizable)` and `clock_ms`;
     2. `chain = retained_chain(..)`; `oldest = chain.last()`;
     3. for each partition *p* of the implicit stream with `bound = oldest.applied[p]` (0 if absent) above the partition's log start: `trim_partition(stream, p, bound, Some(fence))`.

   Trimming below the oldest retained manifest keeps every pinned reader's tail (Ruling 12).

| # | As built | Why | Cost |

| X1 | **Strict creation of Lance version 1.** The creation commit is a strict overwrite (`with_max_retries(0)`). After *any* creation error, it loads version 1 (schema-checked) and uses it, or returns the original error if version 1 does not exist. `lance::Error::DatasetAlreadyExists` is retryable. Staging writes use `WriteMode::Append` | The plan's recipe can move the mainline to version 2 when another creator's version 1 lands between the probe and `CommitBuilder`'s own load. | X2 | **Detached siblings share row ids.** Two detached commits on the same parent allocate the same stable row ids. | X3 | **The upsert-row rule and `seq_no`** (P32). | X4 | **The commit reads the schema `Linearizable`**, not `Local` (Task 10 rule 3.2). `load` stays `Local` | A lagging local schema could permanently dead-letter records the writer validated against a newer schema | One leader read per commit |
| X5 | **The PK repair refuses a stale parent.** If the index's watermark is newer than the parent manifest, nothing is written and the commit returns `Conflict` (the task reloads).
