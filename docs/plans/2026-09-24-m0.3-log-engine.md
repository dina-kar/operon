# M0.3 — Log Engine Implementation Plan

> **For agentic workers:** execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. The code is not pre-written in this plan (see Ruling 1); where this plan gives exact values (formats, paths, constants, error mapping), use them verbatim.

**Goal:** Ship Operon's internal log on the `standard` WAL class: WAL object and segment formats, the leaderless write path, the fetch path with long-poll, the segmenter, retention, a native HTTP produce/fetch API, and the `operon dev` / `operon standalone` binary. Extend the metastore with the segment index swap, trimming, retention settings, WAL-commit pruning, retired-object tracking, an applied-index watch and a leader-following client.

**Architecture:**
- `operon-meta` gains the commands and queries the log needs, plus `MetaClient`, which follows the leader and retries (every command is retry-safe).
- New crate `operon-log`:
  - `batch` (Kafka `RecordBatch` v2 encoding);
  - `wal` and `segment` (object formats);
  - `writer` (`LogWriter`: buffer → one WAL object per flush → `CommitWal` → acknowledge with offsets);
  - `reader` (`LogReader`: offset index → range reads through `operon-cache`);
  - `segmenter` and `retention` (background loops, lease-fenced).
- New crate `operon` (library + binary): the native HTTP API (axum) and the `operon dev` / `operon standalone` commands wiring meta, log, cache and background loops in one process.

**Tech Stack:** Rust 1.97.1 (edition 2024); existing workspace deps; new: `kafka-protocol` 0.18 (records module only), `ulid` 3, `axum` 0.8, `clap` 4 (derive), `serde_json` 1, `base64` 0.22, `reqwest` (dev-dependency, rustls), `moka` (already in workspace) for footer caches.

## Global Constraints

- Toolchain Rust **1.97.1**, edition **2024**, `resolver = "3"`. License **Apache-2.0**; dependencies must pass `deny.toml` (permissive only). `unsafe_code = "forbid"`.
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked` and `cargo deny check` pass after every task. `unwrap()` only inside `#[test]` functions; helpers use `expect("reason")`.
- Object storage is the only durable source of truth. Log nodes keep no durable local state: a log node killed at any point loses only unacknowledged appends.
- `MetaState::apply` stays deterministic: no clock, randomness, I/O or `HashMap` iteration. Time enters only through command fields stamped by the proposing meta client from its `Clock`. A rejected command changes nothing, including the clock.
- Every new meta command is safe to retry after a lost acknowledgement; its doc comment says how.
- Every Operon-defined format starts with magic + version and ends with a trailer holding a crc32c (design §03 §6). Readers reject unknown versions and checksum mismatches with a `Corrupt` error; they never return partial garbage.
- An acknowledged append is durable: its WAL object was PUT successfully and its `CommitWal` was applied before the acknowledgement is sent.
- `/tmp` is a small tmpfs on the development machine: never place a cargo target directory there.
- Commits: `git commit -s`, `<area>: <summary>` (areas `meta`, `log`, `operon`, `docs`). Workspace crates are `0.0.1` with `version = "0.0.1"` on path deps.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | From M0.3, plans specify formats, interfaces, rulings and required tests; code is written test-first during execution and checked by an independent whole-branch review (M0.1/M0.2 plans pre-compiled every line) | The M0.2 plan took longer to prototype than to execute; formats and interfaces are what neighbouring tasks and later milestones depend on | More implementer judgment; mitigated by exact formats here, the review, and the fix round |
| 2 | Record encoding `kafka` = Kafka `RecordBatch` v2 (magic 2, no compression in M0.3), using `kafka-protocol` 0.18's `records` module; batches are written with `baseOffset = 0` and the reader or segmenter patches bytes 0..8 with the absolute offset | Design §02 §3/§5 keep RecordBatch bytes verbatim for zero re-encoding on Kafka fetch (M3). `baseOffset` and `partitionLeaderEpoch` are outside the batch CRC, so patching is free | If `kafka-protocol`'s API does not fit, write a small RecordBatch v2 codec and keep `kafka-protocol` as the test oracle |
| 3 | `encoding` byte reserved in chunk metadata and segment headers: `0 = kafka`, `1 = arrow` (reserved: readers return `UnsupportedEncoding`) | D20 | None |
| 4 | WAL objects live at the **cluster** level: `wal/<class>/<node_id>/<ulid>.wal`, not under `ns/<ns>/` as §01 §6 shows | One WAL object holds chunks from many namespaces (§02 §3 step 1); per-namespace objects would multiply PUTs by active namespaces (1M-namespace target) | Per-namespace client-side encryption (Phase B) will need per-namespace WAL objects or envelope keys per chunk |
| 5 | After segmenting, a partition's segment is **one** offset-index entry (`kind = Segment`) covering its data region; the segment footer holds the per-batch index | Keeps meta proportional to segments, not batches (§02 §5); WAL-backed entries stay per chunk | Readers pay one cached footer read per segment |
| 6 | `CommitWal` gains `created_at_ms` (from the WAL object's ULID). Meta rejects a commit older than `WAL_COMMIT_WINDOW_MS = 900_000` (15 min) relative to its clock, and prunes dedupe records older than twice the window. Writers stop retrying a commit well inside the window (`commit_retry_deadline`, default 60 s) | Bounded dedupe memory (M0.2 ruling 10) without ever re-committing a retried object as new offsets | A writer stalled > 15 min between PUT and commit gets `StaleCommit` and fails the appends (they were never acknowledged) |
| 7 | Meta tracks object lifecycles deterministically: `wal_live_chunks` per WAL object, and a `retired` set (object → retired_at_ms) for WAL objects with no live chunks and for trimmed segments. M0.4's GC deletes retired objects after a grace period and then removes them with `ForgetObjects` | Reachability GC (§03 §7) without listing the bucket for live objects | Meta memory proportional to retired-but-not-yet-collected objects (bounded by GC cadence) |
| 8 | The writer flushes strictly sequentially (one WAL object in flight per `LogWriter`) | Preserves per-partition submission order from one writer; simplest correct design | Throughput per writer ≈ one PUT + one commit per flush interval; pipelining is a later optimisation |
| 9 | Snapshot envelope format version 1 → **2** (new state fields); version-1 snapshots are rejected | Nothing is deployed; a migration would be dead code | None before the first release |
| 10 | The native API is HTTP/JSON with base64 `key`/`value`; streams and namespaces are addressed by **name** | Simplest thing clients (curl, tests, SDKs) can use; gRPC and Kafka come later | Binary-heavy clients pay base64 overhead until gRPC/Kafka |
| 11 | Reads use `Consistency::Local` on the reading node; in a cluster a follower may return fewer records than the leader has committed, and reports its own high watermark | Keeps fetch off the Raft read path (§02 §6: nodes serve from cached state) | Read-your-writes across nodes needs the consistency token wait (M1 tail work) |
| 12 | Idempotent producers, tail write-through cache, `express`/`quorum` classes, gRPC, Kafka protocol, GC deletion and the worker task framework are **out of scope** (M0.4 / M3 / M5) | Scope | Listed in "Out of scope" |

**Out of scope, planned later:** M0.4 — worker task framework (the segmenter and retention loops move onto it), GC of retired and orphan objects, metrics; M3 — Kafka protocol, idempotent producers, consumer groups, `express`; M5 — `quorum` journals, meta network transport.

## Review Focus

1. **A crash or lost response between the WAL PUT and `CommitWal`.** No acknowledged append may be lost and none may be duplicated; a retried commit returns the first commit's offsets; a commit that never lands leaves only an orphan object. Tests: Tasks 1, 4, 8.
2. **Fetch racing the segmenter and retention.** A fetch that planned against WAL entries while the segmenter swapped them, or against entries that retention then trimmed, must return correct records or `OffsetOutOfRange`, never wrong or partial records. Tests: Tasks 5, 6.
3. **Long-poll at the high watermark.** A fetch at `offset == high_watermark` must wake as soon as a commit lands and must return empty (not error) at `max_wait`. Tests: Task 5.
4. **A single record batch larger than `max_bytes`.** The fetch returns that batch anyway (Kafka semantics) so a consumer can never livelock. Tests: Task 5.
5. **Restart of `operon dev` on the same data directory.** Every acknowledged record is readable at the same offset after restart, including records still only in WAL objects. Tests: Task 7.

**Files:** `crates/operon-meta/src/{command.rs,types.rs,state/*.rs,state_machine.rs,node.rs,client.rs,lib.rs,error.rs}`, tests under `crates/operon-meta/tests/`.

**Produces (exact names):**

```rust

pub enum EntryKind { Wal, Segment }                       // IndexEntry gains `pub kind: EntryKind`
pub struct Retention { pub max_age_ms: Option<u64>, pub max_bytes: Option<u64> }   // Stream gains `pub retention: Retention` (default: both None)
impl PartitionState {
    pub fn log_start_offset(&self) -> u64;               // first readable offset
    pub fn high_watermark(&self) -> u64;                 // == next_offset() for standard

pub const WAL_COMMIT_WINDOW_MS: u64 = 900_000;

// node.rs / state_machine.rs
impl MetaNode { pub fn watch_applied(&self) -> tokio::sync::watch::Receiver<u64>; }  // last applied log index

// client.rs
pub struct MetaClientConfig { pub retry_deadline: Duration /* 10 s */, pub backoff: Duration /* 50 ms start, x2, cap 1 s */ }
#[derive(Clone)] pub struct MetaClient { .. }
impl MetaClient {
    pub fn new(local: MetaNode, peers: Vec<MetaNode>, clock: Arc<dyn Clock>, config: MetaClientConfig) -> Self; // peers may be empty (single node)
    pub async fn write(&self, command: Command) -> Result<Reply, MetaError>;  // follows NotLeader hints; retries NotLeader/Timeout/Unavailable until retry_deadline
    pub async fn read<T>(&self, consistency: Consistency, f: impl FnOnce(&MetaState) -> T) -> Result<T, MetaError>; // Local: local node; Linearizable: leader
    pub fn watch_applied(&self) -> watch::Receiver<u64>;                       // local node
    pub fn now_ms(&self) -> u64;

    pub async fn commit_wal(&self, object: &str, created_at_ms: u64, chunks: Vec<WalChunk>) -> Result<Vec<u64>, MetaError>;
    pub async fn swap_segment(&self, ..) -> Result<(), MetaError>;
    pub async fn trim_partition(&self, stream: StreamId, partition: u32, before_offset: u64) -> Result<u64, MetaError>;
    pub async fn set_retention(&self, stream: StreamId, retention: Retention) -> Result<(), MetaError>;
    pub async fn prune_wal_commits(&self) -> Result<u32, MetaError>;

```

**Semantics (exact):**
- `CommitWal`: dedupe by `object` first (return recorded offsets). Else reject with `StaleCommit` if `created_at_ms + WAL_COMMIT_WINDOW_MS < clock_ms`. On success record `WalCommitRecord { base_offsets, created_at_ms }`, set `wal_live_chunks[object] = chunks.len()`, and add `kind: Wal` entries. `created_at_ms` does **not** advance `clock_ms`.
- `SwapSegment`: idempotent if an entry exists with `base_offset == replaces[0].0`, `object == segment`, `end_offset == last replaced end` → `Ok(SegmentSwapped)`. Otherwise: fence check (as `CasPointer`); `replaces` non-empty, strictly contiguous, each equal to an existing `kind: Wal` entry (base and object) else `IndexMismatch`; `byte_range` non-empty. Replace them with one `kind: Segment` entry (`records` = total, `max_timestamp_ms` from the command). Decrement `wal_live_chunks` for each replaced chunk's object; an object reaching 0 is removed from `wal_live_chunks` and inserted into `retired` at `clock_ms` (after advancing it with `now_ms`).
- `TrimPartition`: `b = min(before_offset, next_offset)`. Remove entries with `end_offset <= b`; `log_start_offset = max(log_start_offset, b)`. Removed WAL chunks decrement live counts as above; removed segments go to `retired`. Returns the new `log_start_offset`. Idempotent (a retry is a no-op).
- `PruneWalCommits`: removes `wal_commits` records with `created_at_ms + 2 * WAL_COMMIT_WINDOW_MS < clock_ms`.
- `ForgetObjects`: removes the given paths from `retired`; unknown paths are ignored (retry-safe).
- `lookup`/`entries_from` never return entries wholly below `log_start_offset`.
- Snapshot envelope version 2.
- Tighten the `CasPointer` retry doc (M0.2 re-review N5): a matching current value means the write *may* be the caller's own; callers that must know use a unique value (e.g. a manifest path containing a ULID).

**Tests (must exist):**
- Unit (`MetaState`): commit dedupe after prune window; `StaleCommit`; swap happy path, idempotent retry, `IndexMismatch` (non-contiguous, wrong object, already trimmed), fenced swap; trim at entry boundary, mid-entry, beyond `next_offset`, idempotent; live-chunk → retired transitions for WAL and segment objects; prune; forget; rejected commands leave state (including clock) unchanged; property test: random sequences of commit/swap/trim keep `index` contiguous from `log_start_offset` to `next_offset` and `sum(wal_live_chunks)` equals the number of `kind: Wal` entries.
- `MetaClient`: 3-node in-process cluster — writes through a follower's client reach the leader; a write during leader isolation succeeds after re-election within `retry_deadline`; `watch_applied` advances after a commit.
- Snapshot round-trip includes the new fields; a version-1 envelope is rejected.

Commit: `meta: add segment swap, trimming, retention and object lifecycle to the sequencer`; `meta: add a leader-following MetaClient and an applied-index watch`.


**WAL object format v1 (exact, little-endian):**

```
header   36 B : magic b"OPNWAL\0\0" | version u16 = 1 | class u8 (0 standard, 1 express, 2 quorum) | reserved u8 = 0
                | node_id u64 | ulid [u8;16]
chunks        : chunk payloads back to back; push() order is grouped so each (stream, partition) is ONE contiguous chunk,
                chunks sorted by (stream, partition); a chunk's payload is its RecordBatch v2 bytes concatenated
index         : postcard(Vec<ChunkMeta>)          (ChunkMeta.offset is absolute within the object)
trailer  24 B : index_offset u64 | index_len u32 | index_crc32c u32 | magic b"OPNWALFT"
```

`WalChunk.byte_range` sent to meta is `offset..offset+len` of that chunk.

**Tests:** proptest round-trip (random records incl. empty key/value, headers, negative/zero timestamps → encode → decode equal, offsets `base..base+n`); `patch_base_offset` keeps the CRC valid (decode succeeds, offsets shift); decoding with `kafka-protocol` as oracle; WAL proptest round-trip for random chunk sets; every single-byte corruption in header, index or trailer and every chunk-payload corruption is detected (`Corrupt`), never a panic; truncated objects rejected; unknown version rejected; `Arrow` encoding in a chunk → `UnsupportedEncoding` on read.

Commit: `log: add record batches and the WAL object format`.

```rust
pub struct SegmentFooter { pub stream: StreamId, pub partition: u32, pub encoding: Encoding, pub base_offset: u64,
                           pub end_offset: u64, pub data: Range<u64>, pub batches: Vec<BatchIndexEntry> }
```

**Segment format v1 (exact, little-endian):**

```
header   40 B : magic b"OPNSEG\0\0" | version u16 = 1 | encoding u8 | reserved u8 = 0 | stream u64 | partition u32
                | base_offset u64 | end_offset u64 (exclusive)
data          : RecordBatch v2 bytes, absolute baseOffsets, contiguous offsets
index         : postcard(Vec<BatchIndexEntry>)
trailer  40 B : index_offset u64 | index_len u32 | index_crc32c u32 | data_crc32c u32 | header_crc32c u32
                | reserved u64 = 0 | magic b"OPNSEGFT"
```

The meta entry for a segment has `byte_range = data`. A reader loads the trailer (last 40 bytes) and index once per segment path (immutable → cache forever, bounded LRU).

**Tests:** proptest round-trip (random batch lists → segment → decode all records with correct absolute offsets); `position_for` for first/middle/last offsets and out-of-range; corruption detection as in Task 2; builder rejects non-contiguous offsets.

Commit: `log: add the segment format`.

### Task 4: `LogWriter` — the leaderless `standard` write path

**Files:** `crates/operon-log/src/writer.rs`, `tests/writer.rs`.

**Produces:**

```rust
pub struct LogConfig {
    pub node_id: u64,
    pub flush_interval: Duration,        // default 250 ms (design §02 §3)
    pub flush_bytes: usize,              // default 8 MiB
    pub max_buffered_bytes: usize,       // default 64 MiB; beyond this append() returns LogError::Backpressure
    pub commit_retry_deadline: Duration, // default 60 s (< WAL_COMMIT_WINDOW_MS)
    pub max_batch_records: usize,        // default 10_000 records per append
}
pub struct AppendAck { pub stream: StreamId, pub partition: u32, pub base_offset: u64, pub last_offset: u64 }
#[derive(Clone)] pub struct LogWriter { .. }
impl LogWriter {
    pub fn start(meta: MetaClient, store: Store, config: LogConfig) -> Self;
    pub async fn append(&self, stream: StreamId, partition: u32, records: Vec<Record>) -> Result<AppendAck, LogError>;
    pub async fn flush(&self) -> Result<(), LogError>;     // flushes whatever is buffered now
    pub async fn shutdown(&self) -> Result<(), LogError>;  // flush, then refuse new appends (LogError::Closed)
}
```

**Semantics:** validate stream/partition via a local meta read (`UnknownStream`/`UnknownPartition`), reject empty or oversized appends (`InvalidArgument`); records with `timestamp_ms < 0` get the writer's now. Each append becomes one RecordBatch in the buffer. A flush (interval, size or explicit) takes the whole buffer:
1. build one WAL object (ULID from now), `put_if_absent` at `paths::wal_object`; a PUT error fails every append in it with `LogError::Store` (nothing durable);
2. `MetaClient::commit_wal` with `created_at_ms` = ULID time, retried until `commit_retry_deadline`; each append's `base_offset` = its chunk's base + records before it in the chunk;
3. a commit that fails definitively fails its appends with `LogError::CommitUnknown` (the outcome is unknown to the writer: the records may be committed; documented) or `LogError::Meta(Rejected(..))` for rejections.

One flush in flight at a time (Ruling 8); appends arriving during a flush go to the next one.

**Tests:** ack offsets dense and ordered per partition across many concurrent appenders and partitions; a flush groups multiple streams/partitions into one object (assert one PUT via `FaultyStore::calls`); PUT failure → appends fail, nothing committed, next flush works; `CommitWal` acknowledgement lost (inject: meta write succeeds but the client sees Timeout — simulate with a test double or by isolating the leader after proposing) → retry returns the same offsets, no duplicates; backpressure; shutdown flushes buffered appends; append to unknown stream/partition.

Commit: `log: add the leaderless standard write path`.

### Task 5: `LogReader` — fetch and long-poll

**Files:** `crates/operon-log/src/reader.rs`, `tests/reader.rs`.

**Produces:**

```rust
pub struct FetchRequest { pub stream: StreamId, pub partition: u32, pub offset: u64, pub max_bytes: usize, pub max_wait: Duration }
pub struct FetchResponse { pub records: Vec<OffsetRecord>, pub next_offset: u64, pub high_watermark: u64, pub log_start_offset: u64 }
#[derive(Clone)] pub struct LogReader { .. }
impl LogReader {
    pub fn new(meta: MetaClient, cache: RangeCache) -> Self;
    pub async fn fetch(&self, request: FetchRequest) -> Result<FetchResponse, LogError>;

```

**Semantics:** local meta read (Ruling 11). `offset < log_start_offset` or `offset > high_watermark` → `OffsetOutOfRange { requested, log_start_offset, high_watermark }`. `offset == high_watermark` → wait on `watch_applied` until the watermark moves or `max_wait` elapses (then empty response). Otherwise walk `entries_from(offset)`: WAL entries read their byte range through the `RangeCache`; segment entries load the footer (cached) and read from `position_for(offset)`; decode, patch offsets, drop records `< offset`, stop at `max_bytes` but always include the first batch. If an entry's object is gone or the index moved under the read (segmenter swap or trim between plan and read), re-plan once from fresh meta state; a second miss → `OffsetOutOfRange` if now below `log_start_offset`, else the error.

**Tests:** fetch from WAL-only, segment-only and mixed indexes; mid-batch offsets; `max_bytes` smaller than one batch returns one batch; long-poll wakes on commit (assert latency < flush interval + 100 ms) and times out empty; out-of-range both sides; fetch during a concurrent swap and a concurrent trim returns correct records or `OffsetOutOfRange` (loop test); corrupt object → `Corrupt`.

Commit: `log: add the fetch path with long-poll`.

**Produces:**

```rust
pub struct SegmenterConfig { pub min_bytes: u64 /* 64 MiB */, pub target_bytes: u64 /* 256 MiB */, pub max_wal_age: Duration /* 10 min */,
                             pub interval: Duration /* 5 s */, pub lease_ttl: Duration /* 30 s */ }
pub struct Segmenter;  // new(meta, store, cache, owner: String, config); run_once(&self) -> Result<SegmenterReport, LogError>; spawn(self) -> BackgroundTask
pub struct RetentionConfig { pub interval: Duration /* 30 s */ }
pub struct Retention;  // new(meta, owner, config); run_once() -> Result<RetentionReport, LogError>; spawn(self) -> BackgroundTask
pub struct BackgroundTask;  // stop(self) -> awaits the loop
```

**Segmenter semantics:** for every partition (local read), take the run of leading `kind: Wal` entries (after any segment entries) up to `target_bytes`; segment it if its bytes ≥ `min_bytes` or its oldest `max_timestamp_ms` is older than `max_wal_age`. Acquire lease `segmenter/<stream>/<partition>` (owner = node id string); read each chunk (crc-checked), build the segment with absolute offsets, `put_if_absent` at `paths::segment`, then `swap_segment` with `fence = Some(lease, epoch)`. `IndexMismatch` → delete the new segment object and skip this round; `Fenced` → skip. WAL objects are **not** deleted (they become `retired`; M0.4 GC deletes them).

**Retention semantics:** for streams with `max_age_ms`: `before` = base of the first entry whose `max_timestamp_ms >= now - max_age_ms` (or `high_watermark` if none); with `max_bytes`: drop whole oldest entries while `bytes() > max_bytes`; issue `trim_partition(max(before_age, before_bytes))` when it exceeds `log_start_offset`. Each run also calls `prune_wal_commits`.

**Tests:** differential: for random append/segment/trim schedules, every fetch returns exactly the model's records (property test with a small in-memory store); segments contain contiguous offsets and correct footers; a zombie segmenter (lease taken over) is fenced and leaves no index change; `IndexMismatch` path cleans up its object; retention by age and by bytes; retired objects appear in `MetaState::retired` for both WAL objects and trimmed segments.

Commit: `log: add the segmenter and retention`.

## Rulings made during execution

Where this plan was silent, ambiguous or did not fit the code, the implementation made these rulings. Each is recorded in the code's doc comments too.

| # | Ruling | Why |
|---|---|---|
| E1 | The `kafka` RecordBatch v2 codec is Operon's own (`operon_log::batch`); `kafka-protocol` 0.18 (default features off) is a dev-dependency used as the test oracle in both directions | Ruling 2's fallback: `kafka-protocol`'s `Record::headers` is an `IndexMap`, so repeated header keys (legal in Kafka) would be merged; its errors are `anyhow`. Batches are written with `partitionLeaderEpoch = -1`, producer id/epoch/sequence `-1`, `baseTimestamp` = the first record's timestamp. Compressed batches are rejected as `Corrupt` |
| E2 | The WAL trailer's `index_crc32c` covers the 36-byte header followed by the index | The WAL format has no header checksum, so a flipped bit in `node_id` or the ULID would otherwise go undetected; the Task 2 test requires every single-byte corruption to be detected |
| E3 | `SwapSegment`'s retry check is: an entry exists at `replaces[0].0` with `kind == Segment` and `object == segment`. It runs before the fence check and changes nothing (not even the clock) | The command does not carry the replaced entries' record counts, so "end offset == last replaced end" cannot be computed after the swap; a segment path contains a ULID, so it names exactly one swap. A swap on an unknown stream or partition is `StreamNotFound` / `PartitionNotFound`; an empty segment path or a total over `u32::MAX` records is `InvalidArgument` |
| E4 | `PartitionState::lookup` returns `None` below the log start and `entries_from` clamps to it; the first entry may start below the log start after a mid-entry trim. `bytes()` is computed on the fly. Added `PartitionState::entries()` and `MetaState::all_streams()` | "Never return entries wholly below `log_start_offset`" plus readable offsets starting exactly at the log start |
| E5 | `MetaClient`: each attempt is bounded by the node's request timeout and the deadline bounds the retries (a zero deadline means one attempt); a linearizable read confirms leadership and then reads the leader's local state (the closure is `FnOnce`); `#[doc(hidden)] inject_lost_ack` makes the next successful write report `Timeout` | The Task 4 lost-acknowledgement test needs a deterministic "applied but not acknowledged" fault; "or a test double" allowed one |
| E6 | `MetaNode::commit_wal` takes `created_at_ms` too | It builds `CommitWal`, which gained the field |
| E7 | `LogError::Store` holds an `Arc<StoreError>`; a commit that fails with anything but a rejection, including a non-retryable metastore error, fails its appends with `CommitUnknown` | One failed WAL PUT fails every append in the flush with the same error; any non-rejection leaves the commit's outcome unknown to the writer |
| E8 | `LogWriter`: an append larger than `max_buffered_bytes` is `InvalidArgument` (it could never fit); a stream on a class other than `standard` is `InvalidArgument`; `flush` and `shutdown` return the flush's error; dropping the last handle flushes and stops; `buffered_appends()` reports the buffer for monitoring and tests; commit retries sleep at most until the deadline and keep retrying until it | Unspecified edge cases; tests must wait on state, not sleeps |
| E9 | `SegmentBuilder::push_batch` returns `Result` and rejects anything that is not exactly one well-formed batch of `records` records; added `segment::parse` (full-object check including the data checksum), `Trailer::index_range(object_len)`, and `SegmentFooter::{batch_index_for, batch_range, batch_end_offset}` | The builder patches base offsets itself, so a record-count mismatch or a multi-batch push is how offsets could become non-contiguous. The footer path (trailer, header, index) cannot verify the data checksum without reading all data; readers rely on each batch's CRC instead |
| E10 | The reader re-plans only on `NotFound` (object gone); a segment footer that disagrees with its index entry is `Corrupt`; a WAL chunk is read whole | In M0.3 nothing deletes a referenced object, so only GC (M0.4, simulated in tests) makes an index entry dangle |
| E11 | The segmenter keeps its partition lease between runs, deletes its new segment on `Fenced` as well as `IndexMismatch`, counts per-partition failures in `SegmenterReport::failed` instead of failing `run_once`, and reads WAL chunks through the range cache | A fenced swap is never applied (a retry of an applied swap succeeds before the fence check), so its segment is unreferenced; one failing partition must not stop the others |
| E12 | Retention takes the lease `retention` (TTL 3 × interval, clamped to 1 s..1 h) and skips the run when another owner holds it; trims are not fenced | Trims are idempotent and monotonic, so the lease only avoids duplicate work |
| E13 | `BackgroundTask` runs immediately, then every interval; `stop` waits for the current run | Simplest correct loop; a run is bounded by the metastore client's deadlines |
| E14 | HTTP: `offset` is required on fetch (400 without); `max_wait_ms` is capped at 60 s; the token's `stream` is the stream id and its `offset` is `last_offset`; the 416 body also carries the requested `offset`; retention is applied with `SetRetention` after `CreateStream`; object-store and cache errors are 503 | Unspecified details. A crash between the two creation commands leaves a stream without its retention; a repeated create answers 409 |
| E15 | `reqwest` is a dev-dependency with default features off (`json` only, no TLS); `tracing-subscriber` (MIT) logs for the binary | The tests use plain HTTP on 127.0.0.1, so no TLS stack is needed |
| E16 | `Server::shutdown` stops accepting HTTP requests first, then flushes the writer, stops the loops, waits up to 10 s for in-flight requests (long-polls), closes the cache and shuts the metastore down | No new appends can arrive after the final flush |

Known limitations carried forward: segmenting by age uses record timestamps (client-supplied), as this plan specifies; the retired set grows until M0.4's GC; the segmenter and retention scan every partition on each run; fetches read a whole WAL chunk even for a small range.
