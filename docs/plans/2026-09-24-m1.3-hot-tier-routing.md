# M1.3 — Hot Tier, Maintenance and Affinity Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, formats, constants), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Planned** (2026-09-24).

**Goal:** Make collections fast and keep them healthy, without ever changing a result. Ship:
- background maintenance: Tantivy split merges (Quickwit's `StableLogMergePolicy`) and Lance fragment compaction, both committed through the collection manifest CAS with rebase;
- `operon-hnsw`: an `HnswIndex` trait over `qdrant-edge` 0.8, and hot HNSW artifacts that workers build from a manifest version, publish under `hot/hnsw/`, and reference from the manifest;
- `operon-hot`: the `HotTier` that M1.2's query engine consults: artifacts loaded read-only from NVMe, an appendable delta HNSW for rows added since the artifact, pinned splits on NVMe, Lance fragments prefetched into the range cache, budgets, heat and demotion, pin and warm APIs, and hot status;
- the metastore over the network (openraft RPCs over HTTP), `operon cluster --roles …`, a node registry, rendezvous ownership of collections, and read forwarding to the owner with local fallback;
- the hot on/off differential harness that M1.7 runs at scale.

Sparse vectors (overview A26–A30, R22) get no hot artifact: they live in the splits, so a merge carries them, pinned split files serve them (reported as `splits`), and their results are identical with the hot tier on and off (Ruling 19).

**Architecture:**
- `operon-collection` (M1.1) gains `maintenance::{merge, compaction}`: two worker task sources (`SplitMergeSource`, `LanceCompactionSource`, `Priority::Compaction`). A merge re-indexes the live rows of its input splits from `_source` in row-id order (Ruling 4). A compaction runs Lance's own planner and rewriter and commits the resulting `Operation::Rewrite` detached through `LanceCommitter::commit` (Ruling 5). Both rebase on `Conflict`. `CollectionGcRoots` learns hot artifact prefixes, and `LanceEnv` can read through the range cache.
- `operon-hnsw` (new): `HnswEngine` / `HnswBuilder` / `HnswIndex` / `AppendableHnsw` traits, the `qdrant-edge` implementation (feature `qdrant`, the only code that names `qdrant-edge`), and an exact `FlatEngine` (tests, and the engine `default_engine()` returns without the `qdrant` feature).
- `operon-hot` (new):
  - `artifact` and `build`: the artifact format (descriptor, covered set, chunked files), artifact currency, and `HotBuildSource` (`Priority::HotBuild`);
  - `tier`, `live`, `view`, `delta`, `splits`, `prefetch`: `HotTierImpl: HotTier`, the loader, per-manifest views with a delta index, pinned splits and fragment prefetch;
  - `budget`, `heat` and `status`: budgets, the heat sketch, demotion, auto-promotion and the hot status;
  - `registry` and `placement`: node leases, rendezvous hashing, `PlacementImpl: Placement`;
  - `remote`: `RemoteReadsImpl: RemoteReads` over the internal HTTP route;
  - `differential` (feature `test-util`): the hot on/off harness.
- `operon-meta` gains `SetCollectionHot` (snapshot format 6), `leases_with_prefix`, an HTTP transport for openraft (`Transport::Http`), RPC handlers, and a networked `MetaClient`: every process runs a local replica (a voter on `meta` nodes, a non-voting learner elsewhere), so `Local` reads stay local, and writes and linearizable reads reach the leader over HTTP (Ruling 10). It is still the openraft `MetaClient`, so it implements M1.2a's `MetaStore` trait (D47) with the same code, keeps learners and forwarding inside the openraft implementation (M1.2a Ruling 4), and passes M1.2a's `metastore_conformance!` suite over HTTP. `operon cluster` hands it to every crate as `Arc<dyn MetaStore>`. `MetaStore` gains the three operations Task 4 adds (setting and reading the per-collection hot configuration, and listing leases by prefix), with conformance cases.
- `operon` gains `operon cluster`, role-based wiring, the internal routes (`/internal/v1/raft/*`, `/internal/v1/meta/*`, `/internal/v1/reads/*`, `/internal/v1/hot/*`), the hot routes (`PUT …/hot`, `POST …/warm`, hot status in `GET …/collections/{c}`), the flags `--hot`, `--hot-pin-all`, the `operon warm` subcommand, and multi-process cluster tests.

## Global Constraints

Same as the M1 overview §8, plus:
- **Maintenance never changes a query result**, except where the underlying engine defines it: a split merge that drops deleted documents changes BM25 document frequencies exactly as a Lucene merge does (Ruling 4). Lance compaction, hot artifact commits, pinned splits and fragment prefetch change nothing but latency. Every maintenance task has a test that compares full query results before and after.
- **Lance lineage (R7):** compaction commits only through `LanceCommitter::commit` (detached), never `commit_compaction`, `optimize_indices` or `reserve_fragment_ids`, which commit to the mainline. M1.1's `mainline_never_moves_past_version_one` test is extended to run after compactions.
- **Artifacts are derived:** deleting any object under `hot/`, any local NVMe file, or the whole hot tier at any moment changes only latency. A reader never trusts a hot structure without its source version (§04 §6 rule 2) and its descriptor checksum.
- **Every blocking call into `qdrant-edge`, Tantivy index building or Lance compaction runs on `tokio::task::spawn_blocking` or a dedicated rayon pool**, never on an async worker thread.
- **The metastore is reached through `Arc<dyn MetaStore>`** (M1.2a, D47) in every crate but `operon-meta`. Components call M1.2a's named trait methods (`now_ms`, `watch_changes`, `clock_ms`, `cas_pointer` with `fresh`, `acquire_lease`/`renew_lease`/`release_lease`, `lease`, `collection_heads`, `resolve_collection`, `pointer`) and the three Task 4 adds; where this plan says "a `Local` read of every collection", it means `collection_heads(Local, None)`. `MetaClient::read` closures over `MetaState` stay inside `operon-meta`.
- A node forwards a read at most once: a forwarded read is always executed where it lands.
- The internal routes (`/internal/v1/…`) are unauthenticated in M1, like every other listener (overview §6.9); cluster mode binds `--listen` as given and documents that it must be a private network.
- Commit areas used here: `collection`, `hot`, `meta`, `query`, `operon`, `sim`, `ci`, `docs`, plus `hnsw` for `operon-hnsw`.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **An HNSW artifact is keyed by stable row ids and is valid for every later manifest.** An artifact built from manifest *s* is **current** at manifest *v ≥ s* iff no manifest in *(s, v]* is a `LinkApply` commit with a `pk_delta` (M1.1 writes a PK delta exactly when a commit inserts or deletes rows). Compaction, split merges, index builds and hot commits never make it stale. The hot status reports the *effective* source version: *v* when the artifact is current at *v*, else *s* | R8: row ids survive compaction and merges, and a hot commit is itself a manifest version, so "`source_version == manifest_version`" would otherwise never hold (M1.7 Task 7 waits for exactly that) | One chain walk per status call and per view, cached per manifest version |
| 2 | **Queries against a manifest newer than the artifact use a view** (§06 §5.2 "appendable segment" model). The view for manifest *v* is: the artifact's points minus the rows deleted since *s* (searched with a `must_not has_id` filter), plus an **appendable delta index** of the live rows inserted since *s* (row id ≥ the artifact's `next_row_id`). `HotAnn::covered()` is the set of live rows of *v* that the artifact or the delta has scanned (all of them unless the delta is capped). `live(v)` is computed from the manifest alone: every split's `row_id_ranges` minus its delete bitmap, mapped to row ids (every live Lance row is exactly one live split doc, M1.1 Task 10 rule 8.5) | Row ids are allocated monotonically, so "inserted since *s*" is a row-id range, and deletes are already in the delete bitmaps: no Lance scan is needed per version | A view whose exclusions exceed `max_view_exclusions` (100 000) is not served (`ann` returns `None`; the durable path answers) until the rebuild lands |
| 3 | **Filters reach HNSW as `has_id` allow-lists** (R20), built from `allow ∩ covered`; M1.2 passes an allow-list only for selective filters (R5). Unless a vector's `HnswParams.payload_m == Some(0)`, the build copies the first `max_payload_fields` (8) non-JSON `Keyword`, `I64`, `Bool` and `Uuid` fields with `indexed = true` (schema order; this includes M1.4's Qdrant payload-index fields) into point payloads under the keys `f<field index>` and creates qdrant-edge payload indexes for them before `optimize`, so the build adds its per-value links as Qdrant does (`payload_m` defaults to `m`, `hnsw/build.rs:122-148`; M1.7 A11). Search never uses payload conditions | The hook M1.2 defines carries only an allow-list (`HotAnn::search`). Per-value links still keep the graph connected for filters that correlate with those fields, which is what Qdrant's filterable HNSW relies on | Filtered recall on other fields relies on the allow-list alone; M1.7's filtered recall gate measures it |
| 4 | **A split merge re-indexes, it does not merge Tantivy segments.** The merged split holds the live docs of its input splits, rebuilt from `_source` (Lance `take_rows`) with the input splits' own schema (the prefix of the current schema whose fields the split's Tantivy schema contains), in ascending row-id order, with `SingleSegmentIndexWriter` (M1.1 Ruling 8). Only splits with the same `schema_version` merge. The merged split drops deleted docs; its `row_id_ranges` are the maximal runs of the surviving row ids | M1.1's delete bitmaps are external to Tantivy, and a Tantivy segment merge concatenates segments, which would break the ascending row-id order that `SplitRef.row_id_ranges` and `RowLocator` require after a second-generation merge. Re-deriving with the split's own schema reproduces the same terms (no backfill, A4) | CPU of re-tokenizing merged docs (Quickwit avoids it); splits of different schema versions never merge, so heavy dynamic-mapping churn leaves more splits |
| 5 | **Lance compaction = Lance's planner and rewriter, our detached commit.** `plan_compaction` + `CompactionTask::execute` write the new data files (stable row ids are re-chunked, deleted rows dropped, nothing committed); the task assigns the new fragments real ids from `parent.manifest.max_fragment_id + 1` and commits `Operation::Rewrite { groups, rewritten_indices: vec![], frag_reuse_index: None }` through `LanceCommitter::commit`. Lance's manifest build then recalculates every row-id-domain index's fragment bitmap (`manifest_build.rs:802-848`), so vector and `_pk` indexes stay valid. On rebase a group is re-applied only if every old fragment equals the new parent's fragment of that id (`Fragment: PartialEq`), with fresh fragment ids | `commit_compaction` reserves fragment ids with a mainline commit (`optimize.rs:3053`, `reserve_fragment_ids`), which R7 forbids, and the detached path does no conflict resolution (`io/commit.rs:1114`), so a group whose fragment gained a deletion file would resurrect deleted rows | New fragments that miss the id assignment would leave index bitmaps pointing at fragment 0; a test pins it |
| 6 | **Artifact layout.** Under `ns/<ns>/collections/<cid>/hot/hnsw/<column>/<source_version:020>-<ulid>/`: `files/<relative path>.<chunk:06>` (every engine file, cut into 256 MiB pieces, each stored as one zstd frame), `covered.bin` (`OPHC`), and `descriptor.bin` (`OPHD`), written last. A loader trusts a prefix only through its descriptor, which carries every file's size and crc32c | `Store` has no multipart PUT and a single S3 PUT is capped at 5 GiB; qdrant-edge's payload page files are sparse (32 MiB apparent size, `blobstore/config.rs:12`), and zstd removes the zeros; a descriptor written last makes a half-uploaded artifact inert | One compression pass per build and per download |
| 7 | **Hot configuration is catalog state.** `SetCollectionHot` stores a `HotConfig { vectors, text, fragments }` per collection in a new `MetaState` map (not a field of `Collection`), snapshot format 6. **Auto-promotion is off by default**; when on, the owning node holds the metastore lease `hot-promote/<cid>` while the collection is hot (owner string = the promoted structures), and workers treat a held lease like a pin. Demotion lets the lease expire | Workers must see promotions to build artifacts; a lease expires by itself when heat drops, with no command to forget | Promotion state is visible only while the lease is held |
| 8 | `--hot-pin-all` is an in-process override (every collection's effective config is `{vectors, text, fragments: false}` on that process), not a metastore write | Gates and benchmarks start one process; an override leaves no state behind | In a cluster, every node that should honour it must get the flag |
| 9 | **Fragment prefetch warms H1, not H2.** `LanceEnv` reads through a caching `object_store` wrapper over the range cache (every Lance file is immutable); prefetching a pinned collection's data files fills that cache. It is not reported in `Operon-Hot-Used` and `Operon-Hot: off` does not bypass it (A13 allows H1) | Lance's dataset and session are shared across requests, so a per-request switch below Lance is impossible; H1 returns the same checksummed bytes | — (M1.7 Task 0 A1/A2 now treat fragments as H1 too, overview A19) |
| 10 | **The metastore over the network uses a local replica on every node.** `meta` nodes are voters; every other node runs a non-voting openraft **learner**. `Consistency::Local` reads the local replica; `Linearizable` asks the leader for a read index (`POST /internal/v1/meta/read-index`) and waits until the local replica has applied it; writes are forwarded to the leader (`POST /internal/v1/meta/write`), which returns the entry's log index, and the client waits (bounded) until its replica applied it. openraft's RPCs travel as postcard over HTTP on the node's `--listen` address | `MetaStore` (M1.2a) is semantic, so a pure RPC client would be possible, but many of its reads are `Local` (tail followers, catalog caches, the registry refresh) and its change notification feeds long-polls; a replica keeps those local and leaves `MetaClient`'s `MetaStore` implementation unchanged: a networked `MetaClient` differs only in how a write and a linearizable read reach the leader, which M1.2a Ruling 4 keeps inside the openraft implementation | Every node replicates the whole metastore log (fine at M1 scale; M6 shards meta). Stale learners must be evicted (Task 11) |
| 11 | **Bootstrap and join.** The meta peer with the smallest id in `--peers` calls `initialize` with every peer's address; every node then calls `join` (idempotent: a member with the same address is a no-op, a changed address is `SetNodes`, a new node is `add_learner(blocking)`). A learner leaves on graceful shutdown; a learner whose `node/<id>` lease has been expired for 10 min is removed by the `meta-membership` task. Adding or removing voters is M2 | One deterministic initializer; `initialize` on several nodes is never needed | The first bootstrap needs the lowest-id peer up |
| 12 | **Node registry = leases.** Each node holds `node/<node_id>` (TTL 10 s, renewed every 3 s) whose owner string is its descriptor `v1;<incarnation ulid>;<advertise addr>;<roles>;<zone>`. `MetaState::leases_with_prefix(prefix)` is a new read-only query (no snapshot change), exposed as a `MetaStore` operation (Task 4) | Liveness comes for free from lease expiry and fencing; no new command | A restarted node with the same id waits up to one TTL for its old lease to expire |
| 13 | **Rendezvous ownership.** `score = xxh3_64(ns u64 BE ‖ cid u64 BE ‖ node_id u64 BE)`; owners are the top *r* live `query` nodes by `(score desc, node_id asc)`, taking at most one node per zone until every zone is used (`r` default 1). A node that failed a forward is suspect for 5 s and skipped. `Placement::owner` is `Local` when this node is an owner, else the first owner | Minimal churn (only keys whose top node changes move), AZ spread for *r* > 1, deterministic | Auto-raising *r* for very hot objects (§04 §5) is later |
| 14 | Forwarded reads are JSON (`serde_json`), not postcard: the IR carries `serde_json::Value` (aggregations) and `Map` (sources), which postcard cannot encode. Raft and meta RPCs are postcard. A forwarded read is executed on the receiver through M1.2's `*_local` methods, which never forward; the sender's `CollectionService` falls back to local execution on `Unavailable` or `Timeout` (M1.2 Task 9 rule 1.3) | Correctness never depends on the owner (§04 §5) | A slow owner can make the gateway run the query twice |
| 15 | **`operon cluster`** takes flags, not a TOML file: `--roles`, `--node-id`, `--listen`, `--advertise`, `--peers`, `--bucket`, `--data-dir`, `--zone`, `--replication`, plus the hot flags. `gateway` implies `log` (a gateway appends the writes it receives; the WAL is leaderless). `dev` and `standalone` are unchanged single-node modes | §10 §2's file maps onto these flags one to one; a config file is an M2 operability item | Long command lines in deployment manifests |
| 16 | **Artifact rebuild policy.** A worker builds when a hot column has no artifact, or its artifact is stale (Ruling 1) and either the rows inserted since *s* reach `max(10 000, 20 % of the artifact's points)`, or it has been stale for `rebuild_max_staleness` (10 min; dev flag). One artifact per column is referenced by the live manifest | Every stale artifact is eventually rebuilt (M1.7's `rebuilt` phase waits for it), and a trickle of writes does not trigger constant rebuilds | Up to 10 min of views with deltas |
| 17 | The differential harness runs every query twice at the same `ReadConsistency::Pinned { manifest_version, token }`: through a `CollectionService` built with `HotTierImpl` and one built with `NoHotTier` over the same context, and a third pass that picks the service per request from the seed | Pinned reads make both executions see the same durable state and tail even while maintenance commits land between them | It exercises the hot switch at the service level; one HTTP test covers the header |
| 18 | **At most `max_loaded_artifacts` (32) artifacts are open per node.** `ReadOnlyEdgeShard::open_mmap` builds its own rayon pool of `num_cpus × 4` threads that cannot be configured (`read_only/lifecycle.rs:95-99`), so each open artifact costs threads, and the budget counts them | Hundreds of open artifacts would mean thousands of parked threads | Fewer hot vector columns per node than RAM and NVMe would allow; upstream a pool option |
| 19 | **Sparse vectors have no hot artifact in M1.** `HotBuildSource` builds HNSW artifacts for `schema.vectors` only; `SparseExec` (M1.2 Task 6) reads splits through `open_splits`, so a pinned split file (`HotConfig.text`) accelerates it and records `HotKind::Splits`, and `Operon-Hot: off` changes only where the same bytes come from. qdrant-edge can hold sparse vectors (`EdgeConfigBuilder::sparse_vector`, `qdrant-edge-0.8.0/src/edge/builders/edge_config.rs:53-62`), but its sparse search is exact over the same data, so an artifact would add a build, a publish and a second copy for no change in results | R12's exact class requires identical sparse results; the split path already gives them and pinning already makes them local | Sparse queries on unpinned collections pay the split's ranged reads; a Phase B hot sparse structure would slot in behind a new `HotTier` hook |

## Review Focus

1. **A hot artifact older than the manifest being read.** Rows were inserted, deleted and upserted since it was built, a compaction rewrote the fragments, and a merge replaced splits. The hot path must never return a row that is deleted at the read's manifest, must cover every live row it claims in `covered()`, and must stay usable across compaction. Tests: Task 6 (`a_view_never_returns_a_row_deleted_since_the_artifact`, `covered_is_every_live_row_the_view_has_scanned`, `an_artifact_survives_compaction_and_merges`, `a_view_with_too_many_exclusions_is_not_served`), Task 4 (`currency_rolls_the_source_version_forward_over_maintenance_commits`), Task 12 (phases `tail`, `applied`, `maintained`).
2. **A maintenance commit racing link apply.** A delete lands on an input split while a merge is being built; an upsert adds a deletion file to a fragment in a compaction group; a hot commit races both. The rebase must carry deletes into the merged split, drop a compaction group whose fragments changed, and never lose or resurrect a row. Tests: Task 1 (`a_delete_during_a_merge_is_carried_into_the_merged_split`, `a_merge_whose_input_vanished_is_abandoned`), Task 2 (`a_group_whose_fragment_gained_deletions_is_dropped_on_rebase`, `compaction_never_resurrects_a_deleted_row`), Task 5 (`an_artifact_commit_rebases_over_link_commits`), Task 13 (crash-gate rows).
3. **The metastore leader dies mid-request in a networked cluster.** A write forwarded to a leader that applied it and died before answering; a linearizable read on a learner during failover; a learner that restarts and rejoins. No acknowledged write may be lost, a retried write must not apply twice, and a learner must never serve a linearizable read older than the read index. Tests: Task 9 (`a_forwarded_write_with_a_lost_response_applies_once`, `a_learner_linearizable_read_sees_the_latest_write`, `a_learner_never_answers_linearizably_while_partitioned`), Task 11 (`killing_the_leader_loses_no_acknowledged_write`, `a_restarted_learner_rejoins_without_a_membership_change`).
4. **Ownership churn while reads are in flight.** The owner is killed mid-query; a new query node joins and takes over some collections; a forwarded read arrives at a node that is no longer the owner. Reads must succeed (by fallback), never loop between nodes, and return the same results as a local read. Tests: Task 10 (`a_forwarded_read_is_never_forwarded_again`, `reads_fall_back_when_the_owner_is_unreachable`, `adding_a_node_moves_only_its_keys`, `a_suspect_node_is_skipped_until_it_recovers`), Task 11 (`reads_route_to_the_owner_and_survive_its_death`).
5. **Budget pressure while queries hold hot structures.** An artifact or pinned split is demoted while a query is searching it, or a newer artifact replaces it. The query must finish on the structure it started with; local files are removed only after the last user drops it; a pinned structure that does not fit is reported, not half-loaded. Tests: Task 7 (`a_demoted_artifact_stays_usable_by_a_running_query`, `lowest_heat_per_byte_is_demoted_first`, `a_namespace_over_its_share_is_demoted_before_others`, `an_oversized_pin_reports_over_budget`), Task 6 (`a_replaced_artifact_is_deleted_after_its_last_view`).

**Semantics:**
1. **Candidates** (every source in this plan that scans collections works this way): one `Local` read of every collection with its pointer version. A collection is proposed when its pointer version differs from the last one this source checked, or the last check is older than `poll_interval`. With `merge == false` there are no candidates. A run does at most one `MergePlan` and returns `MoreWork` if more remain, else `Idle`.
2. **`plan_merges`:**
   1. Group `manifest.splits` by `schema_version`.
   2. For each group, map each split to `SplitMetadata { split_id: SplitId(ulid.to_string().into()), num_docs: doc_count − deleted_count, time_range: None, create_timestamp: created_at_ms / 1000, num_merge_ops: merge_ops, footer_offsets: footer_range, maturity: policy.split_maturity(num_docs, merge_ops) }` and call `StableLogMergePolicy::new(config.merge_policy, config.split_num_docs_target).operations(&mut metas)`. Each operation is `MergePlan { inputs: its split ids parsed back to `Ulid`, sorted, purge: false }`.
   3. Every split not in an operation with `deleted_count >= purge_min_deleted` and `deleted_count * 1_000_000 >= purge_deleted_ppm * doc_count` is `MergePlan { inputs: [ulid], purge: true }`.
   4. Plans are ordered by their smallest input ulid.
3. **Build** (plan *M* on the live manifest *P*, `Linearizable`):
   1. `started = meta.now_ms()`.
   2. Open each input with `snapshot.open_split`; all inputs must have equal Tantivy schemas (else `Corrupt`); `schema = schema_for_split(collection.schema, that schema)` with `dynamic = Ignore`.
   3. `rows` = for each input, the row ids of its `row_id_ranges` minus the row ids of its deleted docs (doc id *d* → the range containing *d* by running doc base), unioned and sorted ascending.
   4. In batches of `take_batch_rows`: `snapshot.take_rows(batch)`. A `None` is `Corrupt("row <id> of split <ulid> is not in lance version <v>")`. Each row becomes `Document { pk, source, vectors, sparse_vectors }` (the sparse vectors from `_sparse_<j>`, so the merged split re-indexes their postings and weights, B11), then `check_document(&schema, &doc)` (a rejection is `Corrupt`), then `to_tantivy_doc(&tantivy_layout(&schema), &schema, &doc, &extracted, row_id)`.
   5. If `rows` is empty, there is no merged split (the inputs are only removed). Otherwise `build_split(layout.schema, docs)`, `put_if_absent(split_path(ns, cid, ulid))` with `ulid = Ulid::from_parts(started, random)`, and `SplitRef { ulid, doc_count: rows.len(), deleted_count: 0, size_bytes, footer_range, row_id_ranges: row_id_runs(&rows), delete_bitmap: None, schema_version: inputs' schema_version, created_at_ms: started, merge_ops: max(input merge_ops) + 1 }`. Then `failpoint!("merge.after_split_put")` and hook `AfterSplitPut`.
4. **Commit** on parent *P* (version *v*): manifest *v+1* = *P* with the inputs removed and the merged split inserted at the index of the first input, `kind = Maintenance`, `parent_version = v`, `parent_manifest = P's path`, `created_at_ms = started`, `pk_delta = None`, `dead_letters = None`; every other field is *P*'s (`live_doc_count` does not change: only deleted docs are dropped). `put_if_absent(manifest_path(v+1, ulid))`, `failpoint!("merge.after_manifest_put")`, hook `AfterManifestPut`. If `meta.now_ms() − started > commit_delay`: `Blocked` (nothing is CAS'd). `cas_pointer(PointerCas { namespace: ns, key: "collection/<cid>", expected: Some(v), value: path, fence: Some(fence), fresh: Some(Freshness { created_at_ms: started, max_age_ms: commit_delay }) }).into_result()`, with M1.1 Task 10 rule 3.12's outcome mapping (lost-ack recognition, `StaleObject` → `log_stale_object` + `Blocked`, `CollectionNotFound` → `NotFound`). Then `failpoint!("merge.after_cas")` and hook `AfterCas`.
5. **Rebase on `Conflict`** (at most `max_rebases`): reload *P′* (`Linearizable`).
   - If any input ulid is not in *P′*: abandon, return `MoreWork` (the merged split is GC's).
   - Else, for each input, `newly_deleted` = its deleted docs in *P′* minus those in *P*, as row ids. Their positions in `rows` (binary search) are doc ids of the merged split. If any: write `encode_delete_bitmap(ulid, doc_count, docs)` to `delete_bitmap_path(ns, cid, ulid, ulid2)` and set `deleted_count` and `delete_bitmap`; if `deleted_count == doc_count`, drop the merged split.

**Semantics:**
1. **`live_rows`:** for each split of the manifest, add every row id of its `row_id_ranges`, then remove, for each doc id *d* of `deleted_docs(split)`, the row id `range.start + (d − doc_base)` of the range containing *d* (running doc bases over the ranges in doc-id order).
2. **Delta index.** One per loaded artifact and column, in `dir/delta/<ns>/<cid>/<column>/<ulid>/`, created with `engine.appendable(&descriptor.spec, ..)` (the artifact's engine, by `engine_by_name(descriptor.engine)`). For a new live manifest *v*: `new = live(v) − artifact.scanned − delta.scanned` restricted to row ids `>= descriptor.next_row_id`, in ascending order. If `delta.scanned.len() + new.len() > delta_max_rows`, nothing more is appended (the view's `covered` then excludes those rows). Otherwise `snapshot(v).take_rows(new)` (batches of 1 000); rows with the vector are appended (payloads as in Task 5), and every examined row joins `delta.scanned`. When `since_optimize >= delta_optimize_rows`, `optimize` runs on a blocking thread without holding up views (search stays valid meanwhile).
3. **View for *v*** (`ColumnView::new`):
   - `excluded = artifact.scanned − live(v)`; `covered = (live(v) ∩ artifact.scanned) ∪ (live(v) ∩ delta.scanned)`;
   - if `excluded.len() > max_view_exclusions`, no view is published for *v* (`ann` returns `None`);
   - `source_version` = `effective_source_version(currency(v, descriptor.source_version), v, descriptor.source_version)`.
   - **`search(query, k, allow, ef)`** (every engine call on `spawn_blocking`):
     - with `allow = Some(a)`: `only = a ∩ covered`; empty → `[]`; search the artifact with `IdFilter::Only(&(only ∩ artifact.scanned))` and the delta with `IdFilter::Only(&(only ∩ delta.scanned))`, `k` each;
     - with `allow = None`: search the artifact with `IdFilter::Except(&excluded)` and `k`; search the delta with `IdFilter::Except(&(delta.scanned − live(v)))` (kept on the view) and `k + (delta.appended() − delta_len_at_creation)`, because points appended for later manifests are not in `covered`;
     - drop every result not in `covered`, merge both lists by `(score desc, id asc)`, truncate to `k`. `SearchParams { ef, exact: false }`. Engine errors are `HotError::Failed` (B1).
4. **`HotTier` hooks:**
   - `ann(ns, cid, column, mv)`: the published view of `(ns, cid, column)` with version `mv`, else `None`. Counts `ann_served` / `ann_missed`. Always `None` when disabled, not owned (`placement.owner != Local`), or not effectively hot.
   - `split_file` and `record_access`: Task 7 (until then `None` and a no-op).
   - `status`: Task 8 (until then the provided default).
5. **Reconcile** (`reconcile_once`; the loop runs it every `reconcile_interval` and whenever `meta.watch_changes()` completes, at most once per 100 ms):
   1. One `Local` read of every collection, its pointer and `effective_hot` (Task 5 rule 1).
   2. For each collection this node owns (`placement.owner == Local`) with `vectors`: `snapshot = CollectionSnapshot::open(.., Local)`; for each vector column with an `hnsw` artifact in the manifest:
      - if the loaded artifact's prefix differs (or none is loaded) and Task 7's budget admits it: `download` into `dir/hnsw/<ns>/<cid>/<column>/<source_version:020>-<ulid>/` (a partial directory is removed on failure), `engine.open`, and create a fresh delta index; the previous `LoadedArtifact` and delta are dropped from the tier (their directories go when the last view holding them is dropped);
      - extend the delta (rule 2) and publish the view for the manifest version; keep the newest `views_per_column` views.
   3. Collections no longer owned or no longer hot: drop their views, artifacts and deltas.
   4. A failure for one collection is recorded in the report and in the status (Task 8), logged, and retried on the next pass; it never stops the loop.
6. **Loss of the hot directory** only costs latency: `start` removes `dir/hnsw/` and `dir/delta/` (nothing local is trusted across restarts), and a reconcile rebuilds everything from the published artifacts.

**Semantics:**
1. **Pinned splits** (collections owned here with effective `text`):

2. **Fragment prefetch** (collections owned here with effective `fragments`): for each new live `lance_version`, `prefetch_fragments` reads, in `16 × block_size` pieces through `cache.read`, every data file of every fragment, every deletion file, and every object listed under `_indices/<uuid>/` for the dataset's index uuids. 3. **Budgets** (`plan_admission`, `plan_shrink`; pure). Counted structures: loaded artifacts (`nvme_bytes` = their local files; `ram_bytes` = their `covered` and view bitmaps' serialized sizes), deltas (`nvme_bytes` = their directory; `ram_bytes` = their bitmaps), pinned splits (`nvme_bytes` = `size_bytes`). `max_artifacts` bounds the number of `Hnsw` residents.
   - Each namespace's fair share is `budget / n` for each of NVMe and RAM, where *n* is the number of namespaces with a resident or requesting structure.
   - A candidate `X` may evict `Y` iff `Y.class < X.class`, or `Y.class == X.class` and (`Y`'s namespace exceeds its share, or `Y` is in `X`'s namespace) and `hpb(Y) < hpb(X)`, where `hpb = heat / max(1, nvme_bytes + ram_bytes)` and a pinned structure's heat is at least `promote_min_hits`.
   - Evictions are taken in the order `(class asc, over-share first, hpb asc, (namespace, collection, kind, id) asc)` until `X` fits; if it cannot fit, `TierError::OverBudget` (nothing is evicted, and the structure is reported `over_budget`).
   - `plan_shrink` evicts in the same order until the resident set fits.
   - Evicting drops the tier's reference only; a running query that holds a view or a split path keeps working (Arc and the linger rule).
4. **Heat and promotion.** `record_access` records into the sketch; every `heat_window` the sketch decays. With `auto_promote`, on each reconcile pass for each owned collection that is not pinned: `estimate >= promote_min_hits` → promote `{vectors, text, fragments}`: acquire the lease `hot-promote/<cid>` with owner `"<node_id>;vectors,text,fragments"` and TTL `promote_lease_ttl` (renewed when half of it has elapsed); `estimate < demote_below_hits` → release the lease and drop the collection's promoted structures. 5. **`warm`** takes effect only on the owning node (Task 8 forwards it); it never writes the metastore.

1. **Registration.** `register` acquires the lease `node/<id>` with owner `me.encode()` and `ttl` through the `MetaStore`. `LeaseHeld` (an earlier incarnation) is retried every second until `2 × lease_ttl` has passed, then fails. The renew loop runs every `renew_every`; a lost lease is re-acquired (a partitioned node that comes back registers again). The refresh loop calls `leases_with_prefix(Local, "node/")` once, keeps leases held at `meta.now_ms()` whose owner decodes (a malformed owner is skipped with a warning), and publishes them sorted by id.
2. **`owners`:** candidates are live nodes with `roles.query`, ordered by `(rendezvous_score desc, node_id asc)`. Take the first; then, until `replication` owners are chosen, take the best-ranked node whose zone is not yet chosen, or, when every zone is used, the best-ranked remaining node. Golden scores (reference xxHash `xxh3_64` over the 24 big-endian bytes):

   | (ns, cid) | node 1 | node 2 | node 3 | owner of {1,2,3} |
   |---|---|---|---|---|
   | (1, 1) | `0xfdcc645eadfda102` | `0x2a7341371209acbc` | `0xbcd6a95e708d42b3` | 1 |
   | (1, 2) | `0x0b2804e5c63d39ef` | `0xb3bdd0f3688baa5a` | `0x281def79323288c6` | 2 |
   | (7, 42) | `0xa68db0d40775b4b2` | `0xd1f8ac66b948f2a8` | `0x344e5428d4f20577` | 2 |
3. **`Placement::owner`:** suspects whose mark is younger than `suspect_for` are excluded first (if that leaves no owner, they are included again). `Local` if this node is among `owners`, else `Remote { node_id, addr }` of the first. No query node at all → `Local`.
4. **`RemoteReadsImpl`** (B2) sends `POST http://<addr>/internal/v1/reads/<op>`, with the header `operon-forwarded: 1` (M1.2's `FORWARDED_HEADER`) and JSON `{"ns": "<namespace name>", "hot": bool, "args": {…the method's arguments by name…}}` and expects `200 {"ok": <result>, "hot_used": ["hnsw" | "splits", …]}` or `200 {"err": WireError}`. `hot` is `operon_query::hot::current()`'s `enabled` (the server default when absent), and the returned `hot_used` kinds are recorded into `current().used`, so `Operon-Hot-Used` on the gateway reports what the owner used (B2). A connect failure, timeout, non-200 status or undecodable body → `mark_unreachable(node)`, `fallbacks_signalled += 1`, and `ServiceError::Unavailable("owner <id> unreachable: <reason>")`, which makes the service run the read locally (B3). A decoded `err` is returned as that `ServiceError`.
5. **`serve_forwarded`** decodes the body (malformed → `400` with a `WireError { variant: "InvalidArgument" }`), counts `forwarded_in`, and runs `hot::scope(RequestHot { enabled: hot, used }, service.<op>_local(..))` on the node's one `CollectionService`, returning `used.kinds()` as `hot_used`. The `*_local` methods never forward, so **a forwarded read is never forwarded again** (Global Constraints). The receiver does not check that it owns the collection: after ownership churn it serves the read cold.
6. **`WireError`** carries the `ServiceError` variant name and its fields; `NotFound.kind` maps back to the `&'static str` among the kinds M1.2 uses (Task 0 lists them), else `"object"`.
