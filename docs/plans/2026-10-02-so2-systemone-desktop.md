**Goal:** Put SystemOne in Loams Desktop (the owner's request of 2026-10-02: "add this to our desktop app"):
- a **Swift Core ML sidecar** (`loams-coreml`) for Apple silicon, built on FluidInference's Apache-2.0 `FluidUse` library;
- **`loams-systemone-link`** in `loams-link`: host detection, the registry, model management and sidecar supervision inside the app, with the instance's `SystemOneService` as a second source;
- a **Decisions** settings panel and a **Model Manager** (download, verify, keep resident, delete, self-test, calibration status, the opt-in Cloud section);
- **Loams Bot** using decisions for routing, urgency, needs-person and an LLM pre-filter, shown on the thread card;
- a read-only **`systemone_decide`** tool injected beside `zeron mcp`;
- optionally, the **browser** plugin (a cordis plugin running `laya-ts` in a plain Web Worker), Windows and Linux CPU paths, and the MLX adapter.

**Architecture:**
- **`loams-desktop/sidecars/coreml/`** (SwiftPM executable `loams-coreml`, Swift 6, macOS 14+): depends on `FluidInference/FluidUse` pinned by revision (or the Laya files vendored, Task 0); serves `POST /v1/systemone` and `GET /health` of `laya-serve`'s shape over a Unix domain socket (mode 0600) with a per-launch bearer key. Loads buckets from paths our model manager provides.
- **`loams-desktop/crates/loams-systemone-link/`** (no GPUI): depends on `loams-systemone` (SO1) as a library; owns `CoremlSidecarBackend` (a `LayaServeBackend` over a Unix socket), `RemoteBackend` (Connect client to the instance), the supervisor wiring, and a small state model the UI reads.
- **`loams-desktop/crates/loams-panels/src/decisions/`** (GPUI): the Decisions panel and Model Manager.
- **Loams Bot:** in `loams-link`'s bot ACP shim (`zeron loams bot-acp`) and the `loams-harness-bot` cards; decisions travel as A2A message metadata.
- **`ostrium-labs/loams`: `web/plugins/systemone-local/`** (`@loams/plugin-systemone-local`): optional.

**Tech Stack:** Rust 1.97.1 (the app's workspace), GPUI as zeron pins it; Swift 6 with SwiftPM and Xcode on a Mac only; `FluidUse` (Apache-2.0) and `FluidAudio` pulled transitively; `loams-systemone`; Connect clients generated by `buf`; macOS code signing and notarisation as AP1n Task 10 sets up. Browser plugin: TypeScript, cordis v4, `laya-ts` (Apache-2.0) and `onnxruntime-web` (MIT).

## Global Constraints

- **Local first; cloud only by explicit opt-in.** The Cloud section is off by default; the Jev key lives in the OS keychain, never in a file or the config; a decision shows where it ran.
- **No TCP port for the Core ML sidecar.** A Unix socket in `$LOAMS_HOME/run/` at mode 0600 and a per-launch bearer key. A non-loopback address is refused for every other sidecar.
- **The sidecar never downloads.** Models arrive through the model manager (verified, pinned, consented). `LayaManager.load()`'s own download path is not used.
- **A decision is advisory (D537).** Loams Bot's use never approves, merges, deploys or answers an approval; a SystemOne route is a hint that a person or a gated agent can override.
- **No telemetry from the app.** The app sends no usage data to Loams or anyone else; the decision log is local, opt-in and off by default. When signed in, A2A trace metadata (`systemone.backend`, `systemone.latency_ms`, no content) goes to the operator's own collector like every other span (§39 D-SF-11), and the instance's own `io.loams.dev.systemone.decided.v1` event is the operator's.
- **Credentials:** no Loams token is passed to the sidecar, the browser plugin or an agent subprocess (§37 D489). The injected MCP tool carries chat identity only.
- **Names:** `loams-*` crates, `LOAMS_*` env vars, `loams.systemone.v1`. The zeron data directory names stay (§37 Q489).
- **The build machine.** Rust builds one at a time on Linux for everything but the Swift sidecar and macOS-only tests; Swift builds and notarisation only on the Mac runner; the GPUI app builds are slow, so run `cargo check -p <crate>` and the crate's tests, not the whole app, until the last task.
- **Commit areas:** `systemone`, `coreml`, `panels`, `bot`, `plugin`, `ci`, `docs`.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **The Core ML sidecar speaks `laya-serve`'s JSON on a Unix socket**, so the Rust side is one `LayaServeBackend` with two transports | One client, one fixture set, one self-test | A little HTTP framing overhead (microseconds) |
| 2 | **Models are loaded from paths we manage; the sidecar never fetches** | Integrity and consent belong to one place (SO1 Task 9) | Needs `LayaManager` to accept paths (Task 0 checks; vendoring is the fallback) |
| 3 | **On Apple silicon, English text uses the multilingual checkpoint in v1** | Core ML ships only that; MLX is optional (Q522) | English accuracy 0.657 against 0.783 (upstream MASSIVE) until fine-tuned |
| 4 | **Default Core ML buckets 128 and 512**, others on demand | What `LayaManager.load()` loads; about 614 MB per fp16 bucket (int8-embedding variants smaller if accuracy matches) | A 700-token state truncates on the 512 bucket until 1024 is pulled; the UI says so |
| 5 | **Lazy residency with idle stop is the default; "keep resident" is a setting** | Memory on 8 GB laptops | First decision after idle is slower (bucket load) |
| 6 | **Loams Bot's default `min_confidence` is 0.6** until a calibration table exists | Raw confidences are over-confident, so 0.6 is conservative, not calibrated | Some obvious routes fall through to the LLM; harmless |
| 7 | **The browser plugin is optional and not in the first release** | The server route covers the browser; COOP/COEP conflicts with framed apps (Q530) | None |

### Task 1: The Core ML sidecar

**Files:** `loams-desktop/sidecars/coreml/*`, `.github/workflows/coreml-sidecar.yml` (macOS runner).

**Produces:** the `loams-coreml` executable with `--socket <path> --key-fd <fd> --models <dir>`; `POST /v1/systemone` and `GET /health` per design §7.3.

**Semantics:**
- The key arrives on an inherited file descriptor (never argv or the environment); the socket is created at mode 0600 in a 0700 directory and removed on exit; no TCP.
- Loads the buckets present in `--models` (128 and 512 by default), picks the smallest that fits and truncates on the right in the largest, and reports `usage.truncated`, `state_tokens`, `state_tokens_dropped`.
- A `choice` over 32 options answers `422` with detail `options_over_32`; more than 64 questions, 32 levels, or a body over 2 MiB follow `laya-serve`'s codes (`413`, `422`).
- `noul` native with a `choice_ab` mode on request (a hidden `noul_mode` field); `score` and `choice` as in the fixtures.
- Answers carry `confidence` and `answer_confidence` computed as `laya-serve` does; `action.act_probability` is **not** emitted.
- `/health` answers `{"status":"ok"}` to everyone and the full payload (loaded buckets, compute units, revisions) only with the key.
- Exits on a closed key fd (the parent died).

**Tests:** XCTest and a script: `choice_matches_golden_fixture` (the SO1 Task 2 fixtures where applicable, probabilities within 0.02 of the PyTorch reference rows recorded in Task 0); `score_and_noul_shapes`; `over_32_options_is_422`; `truncation_reported`; `bucket_selection_smallest_fit`; `wrong_key_is_401`; `socket_mode_0600`; `no_tcp_listener` (`lsof`-style check); `exits_when_parent_dies`; `act_probability_absent`; `health_without_key_is_status_only`. CI on a macOS 14+ Apple silicon runner; skipped (not failed) with a notice where the runner is unavailable.

**Commit:** `coreml: Core ML sidecar for Laya on Apple silicon`.

### Task 2: `loams-systemone-link`

**Files:** `loams-desktop/crates/loams-systemone-link/*`.

**Produces:** `LocalSystemOne` (owns a `Registry` from SO1; registers `CoremlSidecarBackend` on macOS aarch64, `LayaServeBackend` supervisors on NVIDIA/CPU hosts when installed, `RemoteBackend` when signed in, `JevBackend` only when enabled) with a `watch::Receiver<SystemOneState>` the UI reads (backends, statuses, active route reason, residency, memory).

**Semantics:**
- `CoremlSidecarBackend` = SO1's `LayaServeBackend` over a Unix socket: spawn `loams-coreml` from the app bundle, pass the key by fd, health-gate, restart policy as `loams-link`'s stack supervisor (backoff 1 s to 30 s, five tries in ten minutes), kill on app exit.
- `RemoteBackend`: SO1's Connect `SystemOneService` client using `loams-link`'s transport and token source (AP1n Task 4); locality is the instance's (reported as `remote`); it is used when no local backend is ready or when the setting says "prefer the instance".
- Residency: `lazy` (default; start on first use, stop after `idle_minutes`, default 10) or `resident`.
- `decide()` is the one entry point for the app: it builds the `DecideRequest`, calls the registry and returns the response with `loams.*` provenance.

**Tests:** `macos_arm64_registers_coreml`; `nvidia_registers_torch_when_installed`; `signed_out_has_no_remote_backend`; `remote_used_when_no_local_ready`; `local_preferred_when_ready`; `lazy_start_and_idle_stop` (`idle_stop_releases_sidecar`, fake sidecar, paused clock); `resident_mode_keeps_running`; `sidecar_crash_restarts_then_fails_closed`; `state_stream_updates_on_status_change`; `decide_returns_provenance`. Platform-specific tests are `cfg`-gated.

**Commit:** `systemone: link the registry, sidecars and the instance into the app`.

### Task 3: The Model Manager

**Files:** `loams-desktop/crates/loams-panels/src/decisions/model_manager.rs`, `loams-systemone-link/src/models.rs` glue.

**Produces:** a panel listing every artefact in SO1's lock for this host (Core ML buckets, `laya-serve` checkpoints), with size, licence, status (not installed, downloading with progress and resume, verifying, installed, corrupt), actions (download, verify, delete), total disk used, and a first-run prompt on the first decision attempt that needs a model ("Download 1.2 GB of models for local decisions?").

**Semantics:** uses SO1 Task 9's `ModelManager` (consent callback = this dialog); a download runs in the background and survives closing the panel; closing the app pauses it and resumes on launch; errors name the file and the fix, not the URL's query; `LOAMS_OFFLINE=1` hides the download actions.

**Tests:** `no_network_without_consent`; `progress_and_resume_reflect_manager_state`; `corrupt_file_shown_and_redownloadable`; `delete_removes_revision_dir`; `first_run_prompt_shows_total_size`; `offline_hides_downloads`; a GPUI snapshot test of the list for each status (the AP1n harness).

**Commit:** `panels: Model Manager for local decisions`.

### Task 4: The Decisions settings and the Cloud section

**Files:** `loams-panels/src/decisions/{settings,cloud,selftest}.rs`, `loams-systemone-link/src/keychain.rs`.

**Produces:** Settings, "Decisions": active backend and the `route_reason`; a backend table with status and the one-line fix; residency and idle minutes; log decisions (off/local) and `log_state`; **Run self-test** (result per case id, no state shown); calibration status per type with the table id and "calibrate from my corrections" (starts SO1's `calibrate`); **Cloud decisions**: off by default, a Jev key field stored in the OS keychain (`loams-systemone/jev`), the consent text (design §10: what is sent, TypeSafe's published no-training statement, that no API terms were found, that the model is closed), a separate switch "allow cloud fallback", and the instance policy line when the org forbids it.

**Semantics:** enabling Cloud requires typing the key and ticking the consent; the key is validated with a single minimal request (a one-question `noul` on a fixed neutral string) only after consent; disabling deletes nothing but turns the backend inert; org policy from `GetInstance` can force-disable.

**Tests:** `cloud_off_by_default`; `key_only_in_keychain` (nothing in config files, logs or the UI state dump); `consent_required_before_validation_request`; `org_policy_disables_cloud`; `self_test_result_has_no_state`; `route_reason_displayed`; `calibration_status_per_type`; snapshot tests of each section.

**Commit:** `panels: Decisions settings, self-test and opt-in Cloud section`.

### Task 5: Loams Bot uses decisions

**Files:** `loams-link/src/bot/decisions.rs`, the bot ACP shim, `loams-harness-bot` cards (SF3 Task 5), the A2A message metadata builder.

**Produces:** three decisions available to the shim and the cards, with fixed question definitions in code (versioned, so fine-tunes bind to them):
- `route.agent` (`choice`: `zulip`, `plane`, `forgejo`, `glitchtip`, `analytics`, `none`; descriptions from each agent's Agent Card);
- `urgency` (`score`: `routine`, `soon`, `now`, `critical`);
- `needs_person` (`noul`: does this need a person's attention before any action);
- `needs_llm` (`noul`: does this message need a language model at all; false for acknowledgements and thanks).

**Semantics:** before each `SendMessage`, the shim asks `LocalSystemOne::decide` with `min_confidence = 0.6` (Ruling 6) and `locality = LOCAL_ONLY`. A confident route sets the A2A `to` hint and the thread card shows "routed to forgejo, 0.91, local"; a `low_confidence` or absent decision sends the message unrouted for Loams Bot to decide, as today. `needs_person` raises the notification priority only (never auto-answers). `needs_llm = false` with confidence above 0.9 may short-circuit to a canned acknowledgement only if the user enabled "quick replies" (off by default) **and** an independent rule-based check agrees (the message is under 40 characters, is not a question and has no `?`, and matches a per-language allowlist of thanks and acknowledgements); otherwise the message goes on to the LLM. The decision, backend, calibrated confidence and latency go into A2A metadata (`systemone.*`, no content). **No decision can create, approve or answer an approval, a question or a destructive skill.** If SystemOne is unavailable the shim behaves exactly as before.

**Tests:** `confident_route_sets_hint_and_card`; `low_confidence_sends_unrouted`; `unavailable_behaves_as_today`; `decision_cannot_approve` (the approval path is unreachable from `decisions.rs`; checked by a compile-time module-visibility test plus a runtime test that the shim rejects a decision-sourced approval); `needs_person_only_raises_priority`; `quick_replies_off_by_default`; `canned_reply_needs_independent_check` (a model-confident `needs_llm = false` on a question still goes to the LLM); `metadata_has_no_content`; `questions_are_versioned` (a snapshot of the four definitions).

**Commit:** `bot: route, urgency, needs-person and pre-filter decisions`.

### Task 7: The browser plugin (optional; owner go-ahead, Q530)

**Files (in `ostrium-labs/loams`):** `web/plugins/systemone-local/*`.

**Semantics:** a cordis plugin `@loams/plugin-systemone-local` that provides the `systemone` service with a `LayaWasmBackend` in a plain Web Worker running `laya-ts` (Apache-2.0) on `onnxruntime-web` (WebGPU, then single-threaded WASM, about 6x slower); weights from the pinned mirror with SHA-256 checks in the worker before use; **no cross-origin isolation is requested** (an isolated iframe cannot live in a non-isolated console, and `require-corp` would block the framed app UIs), so threaded WASM is not offered; Task 7 also measures the real size of the pinned `laya-ts` export; the plugin is `trusted-first-party`, off by default, with a size warning (524 MB int8) and a consent prompt; falls back to the instance route.

**Tests:** `worker_never_runs_on_main_thread`; `console_headers_unchanged` (no COEP or COOP on the console document); `no_threaded_wasm_requested`; `weights_verified_before_use`; `consent_before_download`; `falls_back_to_server_when_declined`; `answers_match_server_within_0_02` (Playwright, needs the weights; `ignore` in CI without them).

**Commit:** `plugin: opt-in local decisions in the browser`.
