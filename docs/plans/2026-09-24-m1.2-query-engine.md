# M1.2 — Query Engine and Native API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, formats, constants), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Planned** (2026-09-24).

**Goal:** Ship `operon-query`, the read side of collections and the one facade every gateway uses. It contains:
- the search IR of overview §6.6 with every auxiliary type, and its exact JSON form;
- read snapshots per `ReadConsistency` (strong reads through a linearizable high-watermark read, `AtLeast`, `Eventual`, and `Pinned` reads without a metastore hold);
- the in-memory **tail index** (H3), which makes a write visible to strong reads before the link applies it;
- DataFusion 54.1 operators for BM25 search with global statistics, filter bitmaps, ANN over Lance, fusion, document fetch and tail merge;
- aggregations, highlighting, sorting and paging;
- `CollectionService`;
- a DataFusion catalog with the `vector_search`, `text_search` and `hybrid_search` table functions;
- the native REST collection, document, query and SQL endpoints;
- an Arrow Flight SQL service.

The hot tier (M1.3) and affinity routing plug in through two fixed hook traits. Results with the hot tier off equal results with it on for every exact path, and a property test proves that the tail merge returns exactly what a full rebuild of the durable state returns.

**Architecture:**
- **Reads resolve one `ReadView` per request:** a durable `CollectionSnapshot` at one manifest, plus a `TailSnapshot` relative to that manifest, plus the effective hot tier.
  - `Strong` reads the implicit stream's high watermarks with one linearizable metastore read, then waits until the tail covers them.
  - `AtLeast` waits for the token's offsets.
  - `Eventual` takes whatever the tail holds.
  - `Pinned` opens a retained manifest and a *range tail* built over exactly `(applied, token]`.
- **The tail is one per collection on the query node.** It follows the implicit stream from the live manifest's `applied` offsets, decodes `DocOp`s, and folds them per key over the durable state. It keeps a RAM Tantivy index with the splits' mapping and analyzers, and flat vectors. A tail entry overrides the durable row of its key iff the entry's offset is at or above the manifest's `applied` offset for its partition (Ruling 1). The durable rows it supersedes form the snapshot's *shadow* set, kept exact across manifest commits through the commits' PK deltas.
- **Every operator works in one row-id space.** Durable rows use their Lance stable row ids; tail docs use ids at or above `TAIL_ROWID_BASE = 2^63` (Ruling 7).
  - Deleted split docs and shadowed rows are masked inside every operator, before any top-k cut.
  - `TailMergeExec` merges durable and tail streams in primary-key order, for scans, scroll and SQL.
- **Text:** `TantivySearchExec` searches every split plus the tail with block-max WAND. It uses *global, live-only* BM25 statistics through Tantivy's `Bm25StatisticsProvider` (R6, Ruling 2). `FilterBitmapExec` turns a `Query` into a row-id set.
- **Vectors:** `AnnExec` runs Lance `nearest` with allow or block masks, brute force for exact and small candidate sets, and tail brute force. It rescores every returned score with Operon's own deterministic kernel (R12, Ruling 3).
- **Fusion and assembly:** `FusionExec` implements RRF, DBSF and weighted sums exactly as §6.6 defines them (DBSF with Qdrant's unclamped formula, Ruling 4). `DocFetchExec` fetches the final hits with one coalesced Lance take.
- **`CollectionService`** implements overview §6.7:
  - writes through M1.1's `CollectionWriter`, with existence reporting, atomic validation and dynamic mapping;
  - schema updates, aliases, versions and pins;
  - forwarding of reads to their owner through the `Placement`/`RemoteReads` hooks;
  - a per-request hot switch carried by a task-local scope (Ruling 11).
- **SQL and REST:** a DataFusion catalog maps namespace → `collections` schema → `CollectionProvider`. The native REST API and an Arrow Flight SQL server run in the `operon` binary.

## Global Constraints

Same as the M1 overview §8, plus:
- **One ordering everywhere:** the effective sort keys, then canonical PK bytes ascending (R10). Every path gives equal hits in the same order: splits and tail, one split or many, hot on or off, local or forwarded. No result may depend on `HashMap` iteration order, task completion order or split open order. Intermediate results are merged in manifest split order, then the tail.
- **The tail is never a source of truth.** Dropping every tail at any moment changes only latency. Nothing the tail holds is persisted.
- **Scores are exact** wherever this plan says so. Every vector score returned is computed by `vector::score` (Task 6). No returned score comes from Lance's distance column or from a `HotAnn`.
- **Serde forms are wire formats.** Every IR and service type has exactly the JSON form of Task 1. `SearchRequest` → JSON → `SearchRequest` is the identity after `normalized()`, because M1.3 forwards reads with it and the SDKs (M1.6) speak it. JSON never carries a non-finite number: validation rejects them on input, and no path produces one on output.
- `CollectionService` is the only code in `operon-query` that calls `MetaClient` write commands. Gateways call nothing below it (overview §8).
- **SQL is read-only on every served surface** (REST `…/sql`, Flight SQL): `SQLOptions::new().with_allow_ddl(false).with_allow_dml(false).with_allow_statements(false)`. `sql_context` never enables URL tables.
- Commit areas used here: `query`, `collection`, `log`, `operon`, `docs`.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **Tail overlay rule.** A tail entry for key *k* in partition *p* (the latest op on *k* the tail has folded, at offset *o*) overrides the durable state iff `o >= manifest.applied[p]`. Entries below `applied` are *covered*: the manifest already reflects them, so they are ignored and later dropped. One live tail therefore serves every manifest at or after its base. Reads that need an upper bound below the tail's head (`Pinned`) or that the live tail cannot serve (overflow) use a *range tail*: a tail built from the log over exactly `(applied, upper]` | Latest-by-key state cannot answer "state at offset *T*" for a *T* below its head. The `applied` comparison makes the overlay correct for any manifest the tail has adopted, with no rebuild per commit | A range tail costs one log read of the range per distinct `(manifest, upper)` pair, cached (Task 4) |
| 2 | **BM25 statistics are global and live-only** (R6). Over all splits of the manifest plus the tail:<ul><li>`total_num_docs` = live, unshadowed durable rows + live tail docs;</li><li>`doc_freq(term)` = postings minus deleted and shadowed docs;</li><li>`total_num_tokens(field)` = Σ over the same docs of the *midpoint* of each doc's quantized fieldnorm bucket (Task 5).</li></ul> | Lucene counts deleted docs until a merge. That would make scores depend on where a document's history lives (splits with delete bitmaps, or the tail), and the tail-merge property test could never pass. Fieldnorms are the only per-doc length Tantivy keeps, and the bucket midpoint is an unbiased estimate of the exact token count Lucene averages | `avgdl` differs from Lucene's by the quantization error of long documents (bucket width ≤ 1/8 of the length). M1.7's BEIR gate measures the effect |
| 3 | **Operon's own kernel scores every vector result** (`vector::score`: f64 accumulation in index order, then rounded to f32). Exact search (`AnnParams.exact`, a metric override, or a candidate set under the brute-force threshold) never uses an index, Lance's distance kernels or a `HotAnn`. It is Operon's brute force over the live rows | R12 needs bit-identical exact results with the hot tier on and off, and a SIMD kernel's summation order differs between libraries. R12 also requires every approximate score to be exact | One extra vector read for Lance-index hits (the vector column is projected in the same scan, not taken again) |
| 4 | **DBSF is Qdrant's `distr_norm` exactly:** f32 Welford mean and sample variance, `(s − (μ − 3σ)) / 6σ`, **not clamped**. A list of one hit scores 0.5, and so does a list with σ = 0 (`qdrant-edge-0.8.0/src/segment/common/score_fusion.rs:113-162`). The overview's comment says "clamped to [0, 1]" (requires overview amendment A19) | M1.4's contract test S2 compares against the Qdrant formula. Qdrant does not clamp, and scores outside 3σ are ordinary | Callers that assumed [0, 1] see values slightly outside it |
| 5 | **Fusion arithmetic is f32**, summed in retriever order:<ul><li>RRF `Σ 1/(k + rank)`, with ranks 1-based within each list;</li><li>WeightedSum `Σ wᵢ·sᵢ`;</li><li>DBSF as in Ruling 4.</li></ul>A doc is identified across lists by its row id | Qdrant computes RRF in f32 (`reciprocal_rank_fusion.rs:32-39`), so M1.4's `k + 1` mapping reproduces it bit for bit | — |
| 6 | **Two ranking modes.** *Score mode* (`sort` empty, or its first key is `Score`): candidates are the retrievers' top-k lists, fused. *Field mode* (the first key is `Field` or `Pk`): at most one retriever, which must be `Text`. The candidates are **all** docs matching `Text ∧ filter` (the retriever's `k` is ignored), ordered by the sort keys, as ES sorts every match. Aggregation domain: the matches of `Text ∧ filter` when the only retriever is `Text`; the fused candidate set when any retriever is not `Text`; the filter's matches when there is no retriever | ES semantics for `query` + `sort` and for aggregations with `knn` | A vector retriever combined with a field sort is refused (`InvalidArgument`) |
| 7 | **Tail row ids are `TAIL_ROWID_BASE (1 << 63) + seq`.** `seq` is a per-tail counter that is never reused within a process. Lance stable row ids are below 2^63 | One `RoaringTreemap` space for masks, bitmaps, fusion and fetch | A Lance dataset with 2^63 rows |
| 8 | **Table functions take positional arguments.** DataFusion 54 refuses named arguments of a table function in `FROM` (`datafusion-sql-54.1.0/src/relation/mod.rs:156-170` accepts only `FunctionArg::Unnamed`). So §05 §4's `vector => (…)` form becomes, for example, `hybrid_search('memories', 'embedding', [0.12, …], 'body', 'refund policy', 100)` (Task 10) | The planner path is not ours to change | §05 §4 is amended in Task 14 |
| 9 | **JSON forms:**<ul><li>integers are `I64` when they fit, else `U64`;</li><li>a UUID sort value or primary key is `{"uuid": "8-4-4-4-12"}`;</li><li>a date field value is `{"date": "<RFC 3339, µs, Z>"}`;</li><li>a bare RFC 3339 string is `Str` and is coerced by the field's kind;</li><li>the PK tie-break sort value is the key's own JSON (`SortValue::as_pk`).</li></ul>No `Pk(PrimaryKey)` sort value exists | Every value round-trips exactly through JSON (M1.3 forwarding, SDKs), and an SDK sees plain scalars. M1.5 assumed `SortValue::Pk` and M1.6 "any JSON scalar"; this satisfies M1.6 and gives M1.5 `as_pk()` | — |
| 10 | **Service write types:**<ul><li>`OpResult` is the enum `{Created, Updated, Deleted, NotFound, Noop, Accepted, Rejected(ServiceError)}` (M1.5's shape, extended), with `existed()` for M1.4;</li><li>`WriteOptions` is `{report_existence, atomic}` (`Default`);</li><li>`WriteResult` carries `positions` (partition, `seq_no`) per op.</li></ul>A patch of a missing key without `upsert` is `NotFound`, not `Noop`: `Noop` means "present and unchanged" | M1.4 and M1.5 assumed incompatible shapes (a struct with `existed` against an enum). The enum carries more, and `existed()` recovers M1.4's view. ES answers `document_missing_exception` for an `_update` of a missing id, which is exactly `NotFound` | M1.4 and M1.5 adapt in their Task 0 |
| 11 | **The hot switch is a task-local scope** (`hot::scope`, set by `HotLayer` from the `Operon-Hot` header or `operon-hot` gRPC metadata). `CollectionService` reads it once at method entry and uses `NoHotTier` when it is off. The structures used are recorded in the scope and in `SearchResponse.hot_used`, and `HotLayer` writes `Operon-Hot-Used` | The §6.7 method signatures stay verbatim for every gateway, and the switch reaches forwarded reads through the `RemoteReads` implementation | Work spawned without the scope sees the server default; the service captures the scope before spawning (Task 9) |
| 12 | `SourceFilter` is `{All, None, Paths { include, exclude }}` (M1.4's name, M1.5's shape). Path patterns are ES `_source` filters (Task 7) | One type serves both gateways; M1.4 uses only `All` and `None` | — |
| 13 | `CollectionInfo.created_at_ms` comes from the annotation `operon.created_at_ms`, which `create_collection` writes. Retry-safety compares schemas ignoring that annotation | The M1.1 catalog record has no creation time, and adding one to the Raft state is not worth a snapshot format bump | Collections created below the service report 0 |
| 14 | **Pins hold nothing** (amendment A6). `pin()` returns `PinnedRead { collection, name, manifest_version, token }`, taken with one linearizable read. A pinned read of a manifest that is no longer retained, or of a token for another stream, fails with `NotFound { kind: "pin" }`. Manifest version 0 (before the first commit) is served by a range tail from offset 0 while the log still starts at 0 | M1.5's PIT and M1.4's snapshot reads need a stable view, and A6 replaced the metastore hold | A PIT can expire before its keep-alive if the manifest is superseded more than `keep_manifests` times and ages past retention (proposed A6 amendment: retain a manifest for the retention period after it is *superseded*, not after it is created) |
| 15 | **Scroll walks the `_pk` term dictionaries** of the splits in a k-way merge with the tail's key order, through a per-split PK dictionary cache. A filter whose durable matches are ≤ `scroll_sort_threshold` (100 000) instead sorts those matches' keys | Pages cost O(page × splits × log) instead of a full scan per page. The term dictionary of the raw `_pk` field is already in canonical PK order | Cached `_pk` dictionaries use memory, bounded by weight |
| 16 | **Native REST writes are atomic:** the service validates every op first and writes nothing if any op fails (`WriteOptions.atomic`). Gateways choose per-item results (`atomic: false`) | An SDK caller expects one request to succeed or fail as a whole; ES `_bulk` needs per-item errors | Validation runs twice (service and writer) |
| 17 | **HTTP error fixes** (overview §9, as-built row):<ul><li>`VersionMismatch`, `Fenced`, `LeaseHeld`, `LeaseLost` and `SchemaVersionMismatch` → 409 `conflict`;</li><li>`StaleObject`, `StaleCommit` and `IndexMismatch` → 503 `unavailable` with `Retry-After: 1`;</li><li>every 503 carries `Retry-After: 1`.</li></ul>A record produced to an implicit stream (`_collection.*`) must have a key that decodes as a `PrimaryKey` with `partition_of(pk) == partition`, else 400 | A conflict is the caller's to resolve and must not look like a server bug; the other three succeed on retry. A misrouted record would break per-key order | M1.1's `SchemaVersionMismatch → 409 already_exists` becomes `conflict` (M1.1 Task 3 item 13) |
| 18 | `CollectionService` owns the dynamic-mapping step (R17) for `DynamicMapping::Map`: before appending, it proposes the missing fields with M1.1's `propose_dynamic_fields` and CASes the schema, retrying `SchemaVersionMismatch` up to 5 times | Every surface gets ES dynamic mapping without duplicating it; a gateway that maps first finds nothing left to add | — |
| 19 | **The live tail indexes with the *current* schema.** A schema version change rebuilds the tail's Tantivy index. The link writes each split with the schema current at its commit, so tail and splits index the same doc with the same schema once it is applied | A4 says old *splits* are not backfilled; docs still in the tail are re-indexed when their split is written anyway | A tail rebuild per schema change (rare) |
| 20 | **Collections default to 4 partitions** (`ServiceConfig.default_partitions`) | Four parallel append streams, and one link task per collection (R9) | — |

## Review Focus

1. **A write that lands while a manifest commit lands.** Cases: one key's ops split across the commit; a patch whose durable base the commit just replaced; a tail delete of a key the commit re-created. A read must never see two versions of a key, a resurrected delete or a lost patch. Tests: Task 3 (`the_tail_drops_covered_entries_when_a_manifest_lands`, `shadowed_rows_follow_pk_deltas`, `a_patch_across_a_manifest_boundary_folds_once`, `in_flight_snapshots_survive_a_manifest_adoption`), Task 13 (`tail_merge_equals_full_rebuild`, `strong_reads_during_link_apply_never_miss_or_duplicate`).
2. **BM25 statistics with superseded documents and old-schema splits.** A document updated three times must count once. A split written before a field existed must add nothing for that field. The tail's docs must count exactly as they will once in a split. Tests: Task 5 (`global_statistics_equal_a_single_split`, `superseded_versions_do_not_count_in_statistics`, `a_split_without_the_field_contributes_no_tokens`, `bm25_matches_a_reference_implementation`), Task 13.
3. **Ties at every boundary.** Cases: equal scores at the k-th place inside a WAND-pruned split; mixed `U64`/`Uuid`/`Str` keys; equal fused scores; `search_after` with equal sort values; hot on and off. Tests: Task 5 (`ties_at_the_kth_score_are_kept_and_ordered_by_pk`, `top_k_equals_exhaustive_scoring`), Task 7 (`equal_scores_order_by_pk_on_every_path`, `search_after_prefix_skips_equal_values`), Task 13 (`results_are_identical_across_placements_and_hot_modes`).
4. **Pinned reads and tokens that do not fit the snapshot.** Cases: a token of another collection; a manifest leaving retention while a PIT pages; a pin before the first commit; a pinned read after a drop and re-create of the name. Tests: Task 4 (`a_pinned_token_of_another_collection_is_not_found`, `a_pin_before_the_first_commit_reads_from_offset_zero`, `a_pinned_read_after_drop_and_recreate_is_not_found`), Task 13 (`pinned_reads_are_stable_under_writes_commits_and_gc`).
5. **Filtered vector search at the selectivity extremes.** Cases: a filter that matches nothing; one that matches only tail docs; one that matches only shadowed rows; one that matches everything; exact against approximate scores; a wrong dimension; a zero vector. Tests: Task 6 (`a_filter_matching_nothing_returns_nothing`, `a_filter_matching_only_tail_docs_uses_the_tail`, `shadowed_rows_are_never_returned`, `a_broad_filter_postfilters_and_retries`, `ann_scores_are_exact`, `zero_vector_cosine_scores_zero`).

**Semantics:**
1. **Serde shapes** (everything the native API, M1.3 forwarding and the SDKs exchange):
   - Structs are JSON objects with the Rust field names. Enums are externally tagged in `snake_case`: a unit variant is a string (`"match_all"`, `"dbsf"`), a newtype or struct variant a one-key object (`{"ids": [5]}`, `{"rrf": {"k": 60}}`). `Option::None` serializes as `null` and a missing key reads as the default.
   - `Retriever::Rescore.input` is a nested object. `MultiMatch.fields` is `[[name, boost], …]`.
   - `TrackTotalHits` is `"none" | "exact" | {"up_to": n}`. `TotalHits` is `{"value": n, "relation": "eq" | "gte"}`. `ReadConsistency` is `"strong" | "eventual" | {"at_least": "<token>"} | {"pinned": {"manifest_version": n, "token": "<token>"}}`.
   - A `ConsistencyToken` is always its text form (`v1:s7/p3@918274`).
   - `SearchResponse.hot_used` and `Hit.fields` are omitted when empty (`skip_serializing_if`). JSON is the only format these types are encoded in, so skipping is safe; postcard never sees them.
2. **Hand-written forms:**
   - `PrimaryKey`: an integer in `0..=2^64−1` is `U64`, a string is `Str`, and `{"uuid": "<canonical 8-4-4-4-12, any case>"}` is `Uuid`; output is lowercase hyphenated. `true`, `1.5`, `-1`, `null` and other objects are errors (A12).
   - `FieldValue`: a string is `Str`, a bool is `Bool`, an integer is `I64` (or `U64` above `i64::MAX`), a number with a fraction or exponent is `F64`, and `{"date": "<RFC 3339>"}` is `Date` (µs; output `YYYY-MM-DDTHH:MM:SS.ffffffZ`, always 6 fraction digits).
   - `SortValue`: `null`, bool, integers as for `FieldValue`, float, string, and `{"uuid": …}`.
   - `Fuzziness`: `"auto"` or an integer 0–2.
   - `SourceFilter`: `"all"`, `"none"` or `{"include": [..], "exclude": [..]}` (either list may be missing).
   - `normalized()` turns `U64(n ≤ i64::MAX)` into `I64(n)`. Every value the service emits is normalized, so emitted JSON round-trips exactly.
   - `SortValue::as_pk` maps `I64(n ≥ 0)` and `U64` to `U64`, `Str` to `Str` and `Uuid` to `Uuid`, else `None`. `from_pk` is its inverse (normalized).
3. **Non-finite numbers:** deserialization of the IR accepts them only where serde_json can produce them, which it cannot. `validate_request` rejects any non-finite `f32`/`f64` (vectors, boosts, weights, thresholds, `FieldValue::F64`, `tie_breaker`, `oversampling`).
4. **`validate_request`** returns `InvalidArgument` with exactly these messages, checked in this order:
   1. `"collection must not be empty"`.
   2. `"at most {max_retrievers} retrievers"` — counted over nested inputs too.

5. **Schema JSON** (the DTOs behind `json::schema`):

7. **Hot scope:**

8. **§05 §4 hybrid body** (`json::hybrid::parse_query_body`). A body is the hybrid form iff it has the key `from` or `retrieve`; otherwise it is a `SearchRequest`. The hybrid form:
   - `from`: `"collections.<name>"` or `"<name>"` → `collection`.
   - `consistency`: `"strong"`, `"eventual"` or `{"token": "<token>"}` (→ `AtLeast`). The token prefix must be `v1:`; §05's example `c1:` is refused.

   - `filter`: F, where F is one of:
     - `{"and": [F]}`, `{"or": [F]}`, `{"not": F}` → `Bool` must / should / must_not;
     - `{"term": {field: value}}`, `{"terms": {field: [values]}}`;
     - `{"range": {field: {"gt"|"gte"|"lt"|"lte": value}}}`;
     - `{"exists": field}`, `{"ids": [Id]}`, `{"match": {field: text}}`.

     A value is a JSON scalar, or a date-math string `now`, `now-<n><u>` or `now+<n><u>` with `u ∈ {s, m, h, d}`, which becomes `FieldValue::Date((now_ms ± n·unit) × 1000)`.
   - `fuse`: `{"method": "rrf", "k"?: 60}`, `{"method": "dbsf"}` or `{"method": "weighted", "weights": [f32]}`.

     - `"_source"` → `SourceFilter::All`;

**Semantics:**
1. **Field resolution.** Resolution is by name, against both the collection schema (for the kind) and the split's own Tantivy schema (for the `Field`; M1.1 names Tantivy fields after `FieldSpec.name`).
   - A name that equals a `FieldSpec.name` is `Plain`. Otherwise, the longest `Json` field name `n` with `name` starting `n + "."` gives `JsonPath { path: name[n.len()+1..] }`. Otherwise `Unknown`.
   - The reserved name `_id` means the primary key: `Term`/`Terms` on `_id` compile like `Ids`.
   - A `Plain` or `JsonPath` field that the split's schema lacks (a split written before the field was added, A4) compiles to `EmptyQuery` for that split. So does an `Unknown` field.
   - `Exists` on such a field is empty and `IsEmpty` matches all. This is the ES "unmapped field matches nothing" rule.
2. **Scores.**
   - `MatchAll` scores 1.0.
   - `Term` on text, keyword and JSON string fields scores BM25 (a `TermQuery` with frequencies).
   - `Terms`, `Range`, `Exists`, `IsNull`, `IsEmpty`, `ValuesCount`, `Prefix`, `Wildcard`, `Fuzzy`, `Ids` and numeric, bool or date `Term`s score a constant 1.0 (`ConstScoreQuery(q, 1.0)`).
   - `Boost` multiplies. `ConstantScore` replaces the score.
   - In `CompileMode::Filter` every leaf is wrapped in `ConstScoreQuery(q, 0.0)`, and scoring is disabled when the query runs (Task 5).
3. **Per variant:**
   - **`Match`** on a `Text` field:
     1. Analyze `text` with `analyzer` if given, else the field's analyzer; no tokens → `EmptyQuery`.
     2. One `TermQuery` per token (`WithFreqs`), or a `FuzzyTermQuery::new(term, fuzziness_edits(f, token), true)` when `fuzziness` is set.
     3. Combine them: `Or` → all `Should`, with `minimum_should_match` applied through `parse_minimum_should_match(msm, n)`; `And` → all `Must`.

     On `Keyword`/`Uuid`: one term, the exact text (UUID text parsed and lowercased). On a numeric, bool or date field: as `Term` with `FieldValue::Str(text)`. On a JSON path: analyze with `standard` into the `_text.<n>` companion at `path`.
   - **`MatchPhrase`:** tokens with their positions (stop-word gaps kept). One token → `TermQuery`; several → `PhraseQuery::new_with_offset_and_slop(terms, slop)`. A `Text` field indexed without positions → `InvalidArgument("field {f} was indexed without positions")`. A JSON path uses `_text.<n>`.
   - **`MultiMatch`:** per field `f` with boost `b`, `q_f` = `Match` (or `MatchPhrase` for `Phrase`, or phrase-prefix for `PhrasePrefix`) wrapped in `BoostQuery(q_f, b)`.
     - `BestFields`, `Phrase` and `PhrasePrefix`: `DisjunctionMaxQuery::with_tie_breaker(q_f…, tie_breaker or 0.0)`.
     - `MostFields`: all `Should` (a sum).
     - `CrossFields`: term-centric. Each field's analyzer yields its token list. For every distinct token `t`, a `DisjunctionMaxQuery` over `BoostQuery(Term(f, t), b)` for the fields that produced `t`, with `tie_breaker`. The per-token queries combine by `operator` (`Or` = Should, `And` = Must). IDF is not blended across fields.
     - `PhrasePrefix` of a single token is a prefix term query (rule on `Prefix`) with the last token as prefix, capped at 50 expansions (`PhrasePrefixQuery::new_with_offset` with `set_max_expansions(50)` for several tokens).
   - **`Term`/`Terms`** on a `Plain` field: `coerce_term`. `Never` → `EmptyQuery`. `Terms` → `TermSetQuery` over the non-`Never` values.
     - On a JSON path `n.path`: type-strict terms on the main field `n` at `path` (S4):
       - `Str` → the raw string term;
       - `I64` → the i64 JSON term only; `U64 > i64::MAX` → the u64 JSON term only; `F64` → the f64 JSON term only;
       - `Bool` → the bool term;
       - `Date` → the `_date.<n>` companion's date term, at ms precision (`EmptyQuery` unless `µs % 1000 == 0`).
   - **`Range`:** each present bound goes through `coerce_bound` into `RangeQuery` bounds on the field's term type.
     - `Text`/`Keyword` compare terms bytewise.
     - A bound that is `Never` on the lower side makes the query empty; on the upper side, likewise.
     - On a JSON path, numeric bounds give `Should[range over i64 terms (bounds rounded as for I64 fields), range over f64 terms, range over u64 terms when a bound exceeds i64::MAX]`. Date bounds use `_date.<n>`; string bounds use raw string terms.
   - **`Exists`:**
     - `Plain` → the vendored `FieldPresence` query for the field (`QueryAst::FieldPresence` through `build_query`), the term M1.1 writes for every non-Json field with a value;
     - `JsonPath` → `ExistsQuery::new(format!("{n}.{path}"), true)`;
     - the whole Json field (`name == n`) → `ExistsQuery::new(n, true)`.
   - **`IsNull`:** JSON paths only, as the term `path` in `_null.<n>`. On a `Plain` field it is `InvalidArgument("is_null is supported on JSON field paths only")`.
   - **`IsEmpty`:** `Bool { must: [AllQuery], must_not: [Exists] }`.
   - **`ValuesCount`:** JSON paths only; else `InvalidArgument("values_count is supported on JSON field paths only")`. It is a u64 range on `_count.<n>` at `path`, OR-ed with `IsEmpty` when the range admits 0.
   - **`Prefix`:** `RegexQuery::from_pattern(escape(value) + ".*", field)`, where `escape` backslash-escapes every regex metacharacter `\.+*?()|[]{}^$#&-~"`. On a `Text` field the value is lowercased when the analyzer lowercases (`standard`, `english`, `simple`). On a JSON path it applies to the main field's raw strings.
   - **`Wildcard`:** the regex is built by escaping everything except `*` → `.*` and `?` → `.`, with the same lowercasing rule as `Prefix`.
   - **`Fuzzy`:** `FuzzyTermQuery::new(term(value), fuzziness_edits(f, value), true)` (transpositions count 1, as ES's default).
   - **`Ids`:** `TermSetQuery` of `Term::from_field_bytes(_pk, canonical)`.
   - **`QueryString`:** Tantivy `QueryParser::new(split_schema, default_fields resolved (Unknown ones dropped; none left → EmptyQuery), tokenizers)`, with `set_conjunction_by_default()` when `default_operator == And`. A parse error is `InvalidArgument("query_string: {error}")`.
   - **`Bool`:**
     - `must` → `Must`; `should` → `Should`; `must_not` → `MustNot`; `filter` → `Must(ConstScoreQuery(q, 0.0))`.
     - With no `must`, `should` or `filter` but some `must_not`, add `Must(ConstScoreQuery(AllQuery, 0.0))`, so a pure `must_not` matches the rest with score 0.
     - An empty `Bool` is `AllQuery`.
     - `minimum_should_match` → `set_minimum_number_should_match(parse(msm, should.len()))`. Without it, the ES default is 1 when there is no `must` and no `filter`, else 0.
   - **`Boost`:** `BoostQuery`. **`ConstantScore`:** `ConstScoreQuery`. **`MatchNone`:** `EmptyQuery`.
4. **`coerce_term(kind, value)`** (M1.5 C15: values follow the field kind):

   | kind | `Str(s)` | `I64(n)`/`U64(n)` | `F64(x)` | `Bool(b)` | `Date(us)` |
   |---|---|---|---|---|---|
   | Text, Keyword | `Str(s)` | `Str(n.to_string())` | `Str(x.to_string())` (Rust shortest form) | `Str("true"/"false")` | `Str(format_date_us(us))` |
   | Uuid | parse → lowercase hyphenated; unparsable → `Never` | `Never` | `Never` | `Never` | `Never` |
   | I64 | parse i64, else parse f64 then as `F64`, else error `"cannot use {s:?} on long field {f}"` | `I64` (`U64 > i64::MAX` → `Never`) | integral and in range → `I64`, else `Never` | error | error |
   | F64 | parse f64 (finite), else error | `F64(n as f64)` | `F64(x)` | error | error |
   | Bool | `"true"`/`"false"` → `Bool`, else error | error | error | `Bool(b)` | error |
   | Date | `parse_date(Value::String(s))` → `DateMs`, else error | `DateMs(n)` (epoch ms, ES) | error | error | `DateMs(us / 1000)` if `us % 1000 == 0`, else `Never` |
   | Json (the whole field) | error `"use a path inside JSON field {f}"` | same | same | same | same |

   Errors are `InvalidArgument` with the quoted message; "error" cells read `"cannot use a {type} value on {kind} field {f}"`.
5. **`coerce_bound(kind, op, value)`:**
   - For `I64` with an `F64(x)` bound:
     - `Gte` → `Included(ceil(x))`;
     - `Gt` → `Excluded(floor(x))`;
     - `Lte` → `Included(floor(x))`;
     - `Lt` → `Excluded(ceil(x))`.

     Values beyond `i64` saturate to "match none" (a lower bound above `i64::MAX`) or "no bound" (a lower bound below `i64::MIN`), and symmetrically for upper bounds.
   - For `Date` with `Date(us)`, `date_bound_ms`:
     - `Gte` → `Included(ceil_div(us, 1000))`;
     - `Gt` → `Excluded(floor_div(us, 1000))`;
     - `Lte` → `Included(floor_div(us, 1000))`;
     - `Lt` → `Excluded(ceil_div(us, 1000))`.

     Here `floor_div` is `div_euclid` and `ceil_div(a, b) = -((-a).div_euclid(b))`. So a µs bound compares exactly against ms-precision values.
   - Other cells follow rule 4, with `Never` replaced by the saturation above.
6. **`parse_minimum_should_match(spec, n)`** (ES syntax):
   - `"3"` → min(3, n); `"-1"` → n − 1;
   - `"75%"` → floor(n × 0.75); `"-25%"` → n − floor(n × 0.25);
   - results are clamped to `0..=n`;
   - anything else, including the `"3<90%"` combination form, is `InvalidArgument("unsupported minimum_should_match {spec}")`.
7. **`fuzziness_edits`:** `Edits(e)` → `min(e, 2)`. `Auto` → 0 for fewer than 3 chars, 1 for 3–5 chars, 2 above (ES `AUTO:3,6`).
8. **Warmup.** `CompiledQuery.warmup` records everything the query reads, so that the vendored `warmup(searcher, &info)` makes a synchronous search possible over the async split directory:
   - the term-dictionary fields of every term, prefix, wildcard, fuzzy and range leaf;
   - every term with `needs_positions` for phrases;
   - the range and automaton leaves;
   - the fast fields used: `_rowid`, `_pk`, and the fast fields behind `Exists` on JSON paths;
   - `field_norms = true` unless `constant_score`.

   The vendored `build_query` result for `FieldPresence` contributes its own `WarmupInfo`, merged in.
9. **`highlight_terms`:** walk the query. For every `Match`, `MatchPhrase`, `MultiMatch` or `Term` leaf on a `Text` field (or on a JSON path through `_text.<n>`), emit `(field name, token text)` for each analyzed token. `must_not` subtrees are skipped.

**Tests** (`tests/compile.rs`, over one split built with M1.1's `build_split` from 12 fixed documents with fields `title` Text english, `tag` Keyword fast, `n` I64 fast, `x` F64 fast, `b` Bool fast, `d` Date fast, `u` Uuid, and `payload` Json with `source_path ""`):
- `every_variant_matches_the_expected_docs`: a table of 60 rows `(Query JSON, expected set of doc pks)`, at least two per variant and field kind, including every row of the coercion table.

**Semantics:**
1. **State**, one tail per collection with per-partition offsets:
   - `manifest` (path and `Arc<CollectionManifest>`, M_T) and `applied = M_T.applied` (absent partition = 0), plus `head[p]`: every record of partition *p* below `head[p]` is folded in.
   - A *generation*: an append-only `Vec<TailDoc>` (chunked, so appends never move earlier docs), a RAM Tantivy index built with `tantivy_layout(current schema)`, `set_tokenizers(tokenizer_manager())` and one writer thread with `writer_memory`, and `seq_next`.
   - Writer-side maps:
     - `latest: BTreeMap<PrimaryKey, u32>`, the index of each overlay key's latest entry, shared with snapshots behind an `RwLock`;
     - `prev: Vec<Option<u32>>`, per entry the index of the previous entry for the same key;
     - `shadow_of: HashMap<PrimaryKey, Option<u64>>`, per overlay key the durable row id of the key in M_T.
   - The bitmaps `live_now` and `shadow_now`.
   - The invariant: every overlay key's latest entry has `offset >= applied[p]`.
2. **Snapshots.** After each applied batch or adoption the writer:
   1. commits the Tantivy writer (skipped when nothing was added or deleted);
   2. reloads its reader;
   3. publishes `TailSnapshot { manifest, head (clone), searcher, docs (Arc of the generation + len), latest (Arc), live (clone of live_now), shadow (clone of shadow_now), live_count, schema_version, bytes }`.

   Readers take `current()` (one `Arc` clone). A snapshot's `get(pk)`:
   1. `i = latest[pk]` (read lock);
   2. follow `prev` from `i` until an entry with index `< len`;
   3. if found and the entry is not covered (`offset >= manifest.applied[p]`), it is `Present` or `Deleted` by its `doc`; otherwise `Absent`.

   `keys_after` iterates the `latest` map's range after `after`, applies `get` to each key, and skips `Absent`. Tantivy's snapshot isolation keeps an old searcher valid while the writer goes on (Review Focus 1).
3. **Applying one record** (`apply.rs`), partition *p*, offset *o*:
   1. `codec::decode`. An error means the link dead-letters it too: skip it; `head[p] = o + 1`.
   2. `k = op.pk()`. `before` = the overlay state if `k` has an overlay entry (`Present` → `Some(doc)`, `Deleted` → `None`); otherwise the durable state of `k` in M_T (rule 4), `None` when absent.
   3. `after = fold(before, [op])` (M1.1 `fold`, so a patch of a missing key without `upsert` leaves it absent).
   4. If `after` is `Some(d)` and `check_document(schema with dynamic = Ignore, d)` fails, skip the op: the link dead-letters it (M1.1 Task 10 rule 3.5). The state stays `before`.
   5. If `after == before` (equal `pk`, `source` and `vectors`): nothing changes, and no entry is appended. The link writes no row for an unchanged key either, so `seq_no` stays that of the last change.
   6. Otherwise:
      - append `TailDoc { row_id: TAIL_ROWID_BASE + seq_next, pk: k, partition: p, offset: o, doc: after }` with `prev = latest.get(k)`, and set `latest[k]`;
      - `live_now`: remove the previous entry's row id if it was present, and add the new row id if `after` is `Some`;
      - Tantivy: `delete_term(Term::from_field_bytes(_pk, k.canonical()))`, then `add_document(to_tantivy_doc(layout, schema, &d, &extracted, row_id))` if present;
      - if `k` was not in the overlay: `shadow_of[k] = durable row id of k in M_T` (rule 4), inserted into `shadow_now` when `Some`.
   7. `head[p] = o + 1`.
4. **Durable resolution.**
   - Before applying a fetched batch, collect the keys of its ops that have no overlay entry. Resolve them in chunks of `resolve_batch` with `CollectionSnapshot::get_by_pk` on M_T's snapshot (`CollectionSnapshot::at`, Task 4, cached per manifest version). That gives `(row_id, Document)` per key.
   - M_T with `lance_version == 0` has no rows.
   - Resolution is exact for M_T by construction. It needs no PK index and no watermark.
5. **Follower loop** (`follower.rs`), one tokio task per tail. Each iteration:
   1. Wait for the first of: a `notify()`, a change of `ctx.meta.watch_applied()`, or `follow_interval`.
   2. A `Local` read gives the collection record (schema version, drop), the pointer `collection/<cid>` and every partition's high watermark. A dropped collection stops the tail (`Stopped`).
   3. **Schema change** (Ruling 19): if the collection's schema version differs from the generation's, compact (rule 7) with the new layout first.
   4. **Adoption:** if the pointer's manifest version exceeds M_T's, adopt the new manifest (rule 6).
   5. **Fetch:** unless the state is `Overflow`, for each partition with `head[p] < hwm[p]`, `fetch(FetchRequest { stream, partition: p, offset: head[p], max_bytes: fetch_bytes, max_wait: ZERO })`. Apply the records (rule 3), then publish (rule 2).
      - `OffsetOutOfRange` with `requested < log_start_offset` is `Trimmed`: the tail resets (rule 9).
      - Other errors are logged. The iteration ends, the state stays `Following`, and the next iteration retries.
   6. **Memory:** `bytes` is Σ over the generation's entries of (`source` JSON length + 4 × vector floats + 96), plus `searcher.space_usage().total()`. The budget adds `bytes` for every tail. When `bytes > max_bytes` or the budget exceeds `total_max_bytes`, the state becomes `Overflow { head }` and fetching stops (§09 §7). Adoption goes on. Once an adoption and compaction bring `bytes < max_bytes / 2` (and the budget allows), the state returns to `Following`, fetching again from `head`.
6. **Adopting manifest M′** (version V′ > V_T):
   1. Collect the chain from M′ back through `parent_manifest` to V_T (exclusive), through `ManifestCache`. A missing link is a *gap*.
   2. **Drop covered entries:** every overlay key whose latest entry has `offset < M′.applied[p]` leaves the overlay (Ruling 1):
      - `latest` loses it (the entries stay in the generation as garbage);
      - its row id leaves `live_now`, its shadow row leaves `shadow_now`, and `shadow_of` loses it;
      - Tantivy `delete_term(_pk)`.
   3. **Update shadows:** for the remaining overlay keys, apply the PK deltas of the chain from oldest to newest (`decode_pk_delta` of each manifest's `pk_delta`; `None` = no key changed). A key in a delta gets `shadow_of[k] = delta value` and `shadow_now` is updated to match.
   4. On a gap, or a delta object that is `NotFound`: re-resolve the shadow rows of every remaining overlay key against M′ (rule 4).
   5. M_T := M′. Publish.

   The folded states of the remaining entries stay correct: `fold(durable_M, ops(A, e]) = fold(durable_M′, ops(A′, e])`, because the link folds the same ops with the same rules.
7. **Compaction** (a new generation). It runs when:
   - garbage entries (covered or superseded) ≥ `compact_garbage_ratio` × entries and entries ≥ `compact_min_entries`, or
   - the schema version changed.

   Under the writer lock:
   1. Create a new generation with the current layout.
   2. Re-append the overlay keys' latest entries in `latest` order, with fresh row ids, re-adding present docs to the new Tantivy index. `shadow_of` and `shadow_now` are unchanged.
   3. Commit, publish, and drop the old generation when its last snapshot is dropped.
8. **`sync(targets, deadline)`:**
   - Return `current()` once `head[p] >= targets[p]` for every partition in `targets`; otherwise `notify()` and wait on each publish.
   - In `Overflow`, when some target exceeds `head`: `Err(Overflow { head })`. Past `deadline`: `Err(Timeout)`. `Failed` → `Err(Log/Collection)` with the failure.
   - `sync` and `current` update `last_read`.
9. **Start, reset and restart:**
   - `start` loads the live manifest (`Local`; none → `CollectionManifest::empty`), sets `head = applied`, and publishes an empty snapshot before the first fetch.
   - A reset (`Trimmed`, or a manifest chain that cannot be walked twice in a row) discards the generation and starts again the same way.
   - Nothing is persisted: after a process restart the first read starts the tail again (§04 §6 rule 3).
10. **`build_range_tail`:** the same apply rules with no follower and no adoption.
    - Start from `durable.manifest()` with `head = applied`, and fetch each partition up to exactly `upper[p]`.
    - The last fetch's records at or beyond `upper[p]` are discarded.
    - Commit once and return the snapshot. `bytes > max_bytes` → `Overflow`. `OffsetOutOfRange` below the log start → `Trimmed`.
11. **Ranged WAL fetches** (carried in: M0 known limitation).
    - `LogReader` gains a moka cache `chunk_batches: (object path, byte_range.start) → Arc<Vec<(u64 /* base offset */, Range<u64> /* bytes within the object */)>>` with 100 000 entries.
    - `read_wal` records a chunk's batch boundaries whenever it reads the whole chunk.
    - When the boundaries of an entry are cached and `gather.offset > entry.base_offset`, it reads only `[start of the batch holding gather.offset, chunk end)`.
    - The tail fetches sequentially from `head`, so after its first fetch every fetch starts at a batch it has seen.

**Semantics:**
1. **`CollectionSnapshot::at`** does what `open` does after its metastore read: it opens the Lance dataset at `manifest.lance_version` (skipped when 0) and builds the `RowLocator`. `Reads` caches snapshots by `(cid, manifest version)` (moka, `snapshot_cache_entries`, 5 min time-to-idle), so a manifest's Lance dataset opens once per node.
2. **The tail registry.**
   - `TailRegistry` maps `CollectionId → Arc<Tail>`, and starts a tail on first use.
   - A background sweep every 60 s stops tails whose `last_read` is older than `idle_ttl`.
   - `stop_collection` stops and removes a tail; the service calls it on drop.
   - A tail whose collection record no longer exists stops itself (Task 3 rule 5.2).
3. **`view` per consistency.** Every branch first computes `targets` (partition → offset).
   - **`Strong`:**
     1. One `Linearizable` read: the collection record, which must still have the same id (else `NotFound { kind: "collection" }`), and `hwm[p]` for every partition of its stream. `targets = hwm`.
     2. `tail.sync(targets, now + consistency_wait)`.
     3. The snapshot is `at(tail snapshot's manifest)`, and `read_token` = `(stream, p, tail.head[p])` for every partition.
   - **`AtLeast(token)`:** `targets[p] = token.offset(stream, p).unwrap_or(0)`. Entries of other streams are ignored (a token may carry several objects, §6.5). Then as `Strong` from step 2; `read_token` as in `Strong`.
   - **`Eventual`:** if a tail is running, its `current()` and that snapshot's manifest; otherwise the live manifest (`Local`) with an empty `TailSnapshot`, and the tail is started in the background. `read_token` = `max(applied[p], head[p])`.
   - **`Pinned { manifest_version: v, token }`:**
     1. The token must name the collection's stream for every partition and no other stream. Otherwise `NotFound { kind: "pin", name: "<collection>@<v>" }`, which also covers a name dropped and re-created with a new stream.
     2. `v == 0`: the durable snapshot is `CollectionManifest::empty`. Valid only while every partition's `log_start_offset` is 0; otherwise `NotFound(pin)`.
     3. `v > 0`: `CollectionSnapshot::open_version(v)`; `ManifestGone(v)` → `NotFound(pin)`. `token[p] < manifest.applied[p]` for some *p* → `InvalidArgument("the pinned token is older than manifest {v}")`.
     4. The tail is `build_range_tail(…, upper = token)`, cached in `pinned_tail_entries` by `(cid, v, token text)`. `Trimmed` → `NotFound(pin)`.
     5. `read_token = token`.
4. **Overflow fallback** (§09 §7, Ruling 1). When `sync` returns `Overflow`:
   1. Take the durable snapshot of the live manifest (`Local`).
   2. Build a range tail over `(applied, targets]` with `range_tail_max_bytes`.
   3. `Overflow` again → `Unavailable("collection {c}: {lag} records are not yet applied; retry after the link catches up")`.

   Range tails for overflow are not cached: `targets` differ per read.
5. **Error mapping:**
   - `TailError::Timeout` → `ServiceError::Timeout`;
   - `Log` and `Collection` errors that are retryable (`StoreError::is_retryable`, `LogError::{Backpressure, Store, Cache}`, `CollectionError::is_retryable`) → `Unavailable`; other errors → `Internal`;
   - `Stopped` → `NotFound { kind: "collection" }`.
6. **Hot:** `view` records `hot_tier.record_access(ns, cid)` once, and stores `hot_tier` and `hot.used` in the view. The service passes `NoHotTier` when `!hot.enabled` (Task 9).
7. **`pin`:**
   1. One `Linearizable` read: the pointer version (0 when absent) and the stream's high watermarks.
   2. Start the tail, so a pinned read soon after finds the range in the log.
   3. Return `(version, token of the high watermarks)`.

**Semantics:**
1. **Effective sort** (Ruling 6).
   - Score mode: `sort` empty → `[Score desc]`.
   - Field mode: `sort` empty with no retrievers → `[Pk asc]`.
   - A trailing `Pk asc` is appended unless the last key is `Pk`.
   - `compare` orders key by key:
     - `Score` by `f32::total_cmp`;
     - `Pk` by canonical bytes;
     - `Field` by its value: `Null` first or last per `missing`; `Bool` false < true; numbers numerically (`I64`/`U64` exactly through `i128`, and `F64` against integers through `f64::total_cmp` after converting the integer); `Str` and `Uuid` bytewise.
   - `desc` reverses a key's order, except where `missing` places `Null`.
   - A multi-valued field sorts by its minimum for `asc` and its maximum for `desc` (ES's default mode).
   - `is_after(hit, v)`: compare the first `v.len()` keys of the hit with `v`. The hit is after iff the result is `Greater`. Equal prefixes are *not* after, so ES's `search_after` without a tie-breaker skips equal values, and a full tuple including the PK pages exactly.
   - A `search_after` value at a `Pk` position is read with `SortValue::as_pk`; at a date field position, `I64` is epoch ms.
2. **Opening splits.** For each `SplitRef` of the view's manifest, in manifest order:
   1. If `view.hot.split_file(ns, cid, ulid)` is `Some(path)`, open it with M1.1's `open_split` over `LocalSplitStorage { path }` (`get_slice` = a positional read in `spawn_blocking`, `get_all` = the whole file, `file_num_bytes` = file length; every other `Storage` method is `StorageErrorKind::Internal("read-only local split")`), and record `HotKind::Splits` in `view.hot_used`.
   2. Otherwise use `CollectionSnapshot::open_split` (one ranged GET through the range cache).
   3. Compute the query's `WarmupInfo` against the split's schema and run the vendored `warmup`.
   4. `mask.deleted` = `deleted_docs(split)`.
   5. `mask.shadowed` = the doc ids of `view.tail.shadow()` rows located in this split: `locate_row(row) → (split index, doc)`.

   Splits open once per request; the range cache and the hot file provide the cross-request caching. Splits are opened and searched concurrently, `parallelism` (8) at a time, with the CPU work in `spawn_blocking`.
3. **Global statistics** (R6, Ruling 2), for the fields and terms the compiled query scores:
   - `num_docs = view.live_rows()`.
   - `tokens(field)`: Σ over splits and the tail of `½ · Σ_{docs d not masked} norm_mid2(fieldnorm_id(d, field))`. The sum is computed in u64 halves and divided once at the end, which makes it order-independent. A split without the field adds 0.
     - Per split, the sum over not-deleted docs is cached in `StatsCache` under `(split ulid, delete-bitmap path or "", field)`.
     - The shadowed docs are subtracted per request.
   - `doc_freq(field, term)`: per split, `|postings(term) ∖ deleted|`, cached under `(ulid, bitmap, field, term bytes)`, minus the shadowed docs whose postings contain the term (checked with `seek` per shadowed doc). For the tail, the postings of live docs only.
   - `provider(schema)` implements `Bm25StatisticsProvider` for one split's schema: `Field` → name through `schema.get_field_name`; `Term` → `(name, term.serialized_value_bytes())`. Terms the query did not declare answer `doc_freq = 0`.
4. **`TantivySearchExec`, score mode**, per split (and the tail, whose "split" is its RAM searcher, with a mask of non-live docs by `_rowid`):
   1. `weight = compiled.query.weight(EnableScoring::enabled_from_statistics_provider(&provider, searcher))`.
   2. `weight.for_each_pruning(f32::MIN, reader, callback)`. The callback drops masked docs by returning the current threshold. Otherwise it pushes `(score, doc)` into a buffer holding every candidate with `score >= s_k`, where `s_k` is the k-th best score so far (ties at the boundary are kept). It returns `s_k.next_down()` once k candidates exist, else `f32::MIN`. Returning the next float below `s_k` keeps docs *equal* to the k-th score in play, so PK tie-breaks stay exact (Review Focus 3).
   3. Read `_pk` and `_rowid` for the buffered candidates, sort by the effective order, and truncate to k.
   4. Across splits and the tail, merge by the effective order and truncate to k.

   A `compiled.constant_score` query has every score equal, so its buffer holds every match; Task 7 rule 11 replaces this path by a walk in PK order.
5. **`TantivySearchExec`, field mode**, per split:
   1. Iterate `weight.for_each_no_score` (or `for_each` when a `Score` key is present).
   2. Skip masked docs.
   3. Read the sort keys' fast-field values (the collection field must be `fast`, else `InvalidArgument("sort field {f} is not a fast field")`; JSON paths → `InvalidArgument("sorting on JSON paths is not supported in M1")`).
   4. Apply `search_after` as a filter.
   5. Keep a bounded heap of the best `k = offset + limit` by the effective order. The `_pk` fast field is read for each doc admitted to the heap.
   6. Merge as in score mode.

   `Hit.score` is the BM25 score when a `Score` key is present, else `0.0`.
6. **`count`:** Σ over splits of `|matches ∖ mask|` (a `for_each_no_score` count), plus the tail's live matches. A `MatchAll` with no filter is `view.live_rows()` without searching.
7. **`FilterBitmapExec`:**
   - Compile with `CompileMode::Filter` and run with scoring disabled.
   - Per split, collect the unmasked doc ids, map them to row ids through the `_rowid` fast field, and add them to a `RoaringTreemap`. Add the tail's matching live row ids.
   - `MatchAll` without clauses returns `RowSet::All`.
   - The operator emits the row ids in ascending order in batches of 8 192.
8. **Operator protocol.** Every operator of Tasks 5–7:
   - produces its rows in its own `execute` from an async block, through `RecordBatchStreamAdapter`, with one output partition;
   - reports `name()` and `DisplayAs` with its parameters;
   - keeps metrics: `ExecutionPlanMetricsSet` with `output_rows`, `elapsed_compute`, and a counter `splits_searched`.
   - `with_new_children` accepts only its own children.

**Tests** (`tests/text.rs`):

**Semantics:**
1. **Kernel** (`score`), with all arithmetic in f64:
   - `Dot` = `Σ qᵢ·vᵢ`.
   - `Cosine` = `dot / (√Σqᵢ² · √Σvᵢ²)`, and `0.0` when either norm is 0 (M1.4 S9).
   - `Euclid` = `−√Σ(qᵢ−vᵢ)²` (the distance, not its square, as M1.5 assumed).
   - `Manhattan` = `−Σ|qᵢ−vᵢ|`.

   Larger is better on every metric (§6.6).
2. **Validation:**
   - the field must be a `VectorSpec` of the schema (else `InvalidArgument("unknown vector {f}")`);
   - `query.len() == dim` (else `InvalidArgument("vector {f} has {dim} dimensions, the query has {n}")`);
   - the metric is `params.distance` when set (exact only, validated in Task 1), else the spec's.
3. **Candidate rows.** `allow` is the `FilterBitmapExec` of `request.filter ∧ retriever.filter`, or `None`. Split it into its durable part `A_d` (ids < 2^63) and tail part `A_t`. `N_d = view.live_rows() − tail.live_count()`.
4. **Strategy**, first match wins:
   1. **`Exact`:** `params.exact`, or `params.distance.is_some()`, or the spec is `Manhattan`, or the vector has no `VectorIndexRef` in the manifest. The durable part is a Lance scan of `[_pk, _vector_i]` with `with_row_id()`:
      - with `with_row_addr_prefilter(RowAddrMask::from_allowed(A_d ∖ shadow))` when a filter is present;
      - else with `from_block(shadow)`;
      - and `use_index(false)`.

      Every row with a non-null vector is scored and a heap keeps the best k by (score, pk).
   2. **`BruteForceAllowed`:** a filter is present and `|A_d| <= threshold`, where `threshold = max(brute_force_min_rows, full_scan_threshold_kb · 1024 / (4 · dim))` (Qdrant's full-scan rule on the spec's HNSW parameters). The scan is the same as `Exact`, restricted to `A_d ∖ shadow`. An empty `A_d` reads nothing.
   3. **`Hot`:** `view.hot.ann(ns, cid, "_vector_i", manifest.version)` is `Some(h)`. Rule 6.
   4. **`Prefilter`:** a filter is present and `|A_d| / N_d <= prefilter_max_selectivity`. A Lance `nearest("_vector_i", q, k)` with:
      - `with_row_addr_prefilter(from_allowed(A_d ∖ shadow))` and `prefilter(true)`;
      - `nprobes(params.nprobes or default)`, `refine(params.refine_factor or default_refine_factor)` and `ef(params.ef)` when set;
      - `distance_metric` (Cosine → `Cosine`, Dot → `Dot`, Euclid → `L2`);
      - `project(&["_pk", "_vector_i"])` and `with_row_id()`.

      Lance searches the indexed fragments through the index and the rest through its flat branch, so rows newer than the index are found.
   5. **`Postfilter`:** a filter is present and the selectivity is above the bound.
      1. Run `nearest` with `from_block(shadow)` and `k₁ = min(N_d, ceil(k · postfilter_oversample / s))`, where `s = |A_d| / N_d`.
      2. Keep the candidates in `A_d`.
      3. If fewer than k remain and Lance returned `k₁` rows, retry with `k₁ · 4` (`postfilter_retries` times).
      4. If still short, run `Prefilter`.

      With no filter, run `nearest` with `from_block(shadow)` and k.
5. **Rescoring and the tail.**
   - Every durable candidate is rescored with `score(metric, q, vector)` from the projected `_vector_i`. Lance's `_distance` is never returned (R12). Candidates with a null vector are dropped.
   - The tail part: brute force over `tail.live_docs()` that have the vector and are in `A_t` (or all when there is no filter).
   - Merge, then sort by (score desc, pk asc) and truncate to k.
   - Record the strategy.
6. **`Hot` (`HotAnn` h):**
   1. `k₂ = k · hot_overfetch + 16`.
   2. `h.search(q, k₂, allow = A_d when a filter is present, params.ef)`.
   3. Drop every returned row that is not live in the view: `locate_row` fails, the doc is deleted in its split, or the row is in `shadow`.
   4. The uncovered rows (not in `h.covered()`) are searched on the durable path (steps 4.4–4.5 above) with `block = shadow ∪ covered`.
   5. Rescore every candidate exactly, taking vectors with one Lance `take_rows` of `[_pk, _vector_i]` for the hot rows, then merge with the uncovered results and the tail.
   6. If fewer than k live hot candidates remain and h returned `k₂`, retry with `k₂ · 4` up to `hot_retries` times, then fall back to the durable path for the whole search.
   7. `HotError` → log it and use the durable path.
   8. Record `HotKind::Hnsw` when h's results are used.

   With `Operon-Hot: off`, `view.hot` is `NoHotTier`, so `ann` is never called (Task 9).
7. **Defaults:** `nprobes = max(min_nprobes, ceil(num_partitions / nprobes_divisor))`. `num_partitions` is read from the Lance index metadata of the `vec_<i>` segments (`load_indices()`). The largest segment's value is used when segments differ.

**Semantics:**
1. **Planning a search** (`SearchPlanner::search`):
   1. `validate_request`; `EffectiveSort::of`.
   2. Build `R(r)` for each top-level retriever:
      - `Vector` → `AnnExec` with `allow = FilterBitmapExec(request.filter ∧ r.filter)`, or none when both are absent;
      - `Text` → `TantivySearchExec(query, request.filter, k)`;
      - `Fused` → `FusionExec` of its inputs' plans;
      - `Rescore` → the input's plan, then rule 3.
   3. Candidates:
      - score mode with one retriever and no fusion → that plan;
      - several retrievers, or a present `fusion` → `FusionExec(plans, fusion, window)` with `window = max over retrievers of k`;
      - field mode → one `TantivySearchExec` in field mode (the Text retriever's query, or `MatchAll`) with `k = offset + limit` and `search_after`;
      - no retrievers in score mode is refused by validation.
   4. Execute with `datafusion::physical_plan::collect(plan, SessionContext::new().task_ctx())`, then convert to `Ranked`.
   5. Score mode: keep `score >= score_threshold` when set, then `search_after`, then sort by the effective order. The `_sort` column carries the field values of field mode.
   6. `groups` (rule 5) replace `hits` when `group_by` is set. Otherwise skip `offset` and take `limit`.
   7. Fetch the page: `DocFetchExec` over the page's rows with `FetchColumns { source: select.source != None || !select.fields.is_empty() || highlight.is_some(), vectors: select.vectors resolved }`. An unknown vector name is `InvalidArgument`.
   8. Hits:
      - `score`, and `sort_values = EffectiveSort::sort_values`;
      - `source = filter_source(source, &select.source)`;
      - `vectors` = exactly the requested names the doc has (S10);
      - `fields = field_values(...)`;
      - `highlight` from Task 8.
   9. Totals and aggregations: `total` (rule 4); `aggregations` (Task 8); `read_token = view.read_token`; `hot_used = view.hot_used.kinds()`.
2. **Fusion** (`fuse`, Rulings 4–5). Each input list is already in (score desc, pk asc) order, and its rank is its 1-based position. Documents are keyed by row id, and fused scores are summed in input order:
   - `Rrf { k }`: `s(d) = Σ 1.0f32 / (k as f32 + rank as f32)`.
   - `Dbsf`: per list, Qdrant's `distr_norm` in f32:
     - a list of 1 → 0.5;
     - else Welford (`mean += δ/k; agg += δ_old·δ_new`), `var = agg / (n − 1)`, `σ = √var`, `lo = mean − 3σ`, `hi = mean + 3σ`;
     - `lo == hi` → 0.5; else `(s − lo) / (hi − lo)`, **not clamped**.

     Then sum.
   - `WeightedSum { weights }`: `Σ wᵢ · sᵢ` over the lists containing *d*.

   The fused list is sorted by (fused score desc, pk asc) and truncated to k.
3. **`Rescore { input, field, query, k }`:** take the input's candidates (at most its k) and fetch `_vector_i` with one `fetch_rows`. Candidates without the vector are dropped. Score with `vector::score` (S9) and keep the best k by (score desc, pk asc).
4. **Totals:**
   - `None` → `total: None`.
   - `Exact`:
     - with only a `Text` retriever, or field mode → `TantivySearchExec::count` (every match of `Text ∧ filter`);
     - with no retrievers → the filter's match count;
     - otherwise → the number of distinct candidates after `score_threshold`.

     Relation `Eq`.
   - `UpTo(n)`: the same count c; `c <= n` → `{c, Eq}`, else `{n, Gte}`.
5. **`group_by { field, group_size, limit }`:**
   1. Walk the candidates in order and fetch their sources in pages of 256.
   2. The group keys of a hit are its values at the field's `source_path` (or the JSON path), through `extract` and `coerce` for typed fields, and as the JSON scalar for JSON paths (strings, integers and bools only). A hit joins every group of its keys.
   3. Groups are ordered by their first hit. A group keeps at most `group_size` hits, and collection stops once `limit` groups are full or the candidates run out.
   4. `HitGroup.key` is the key as a `FieldValue`.
6. **Scroll** (Ruling 15), `after` exclusive and PK order (S8):
   1. The durable side:
      - no filter, or a filter with `|A_d| > scroll_sort_threshold`: a k-way merge over every split's `PkCursor` (live and unshadowed only; checked against `A_d` when a filter is present);
      - otherwise: the pks of `A_d` read from `_pk` fast fields, sorted, and cut at `after`.
   2. The tail side: `tail.keys_after(after, ∞)`, with `Present` docs kept when their row id is in the filter's tail part, and `Deleted` entries emitted as tombstones.
   3. `TailMergeExec` merges both streams by pk:
      - a durable key whose tail entry exists is dropped (it is already shadowed; the check is defensive);
      - tombstones are dropped;
      - output stops at `limit`.
   4. `fetch_rows` gives the documents. `next = Some(last pk)` when `limit` docs were returned and more remain (known by fetching `limit + 1`), else `None`.
7. **Get:**
   1. For each pk in request order, `tail.get(pk)`: `Present` → the tail doc; `Deleted` → `None`.
   2. The keys left go to `snapshot.get_by_pk` in one call (they cannot be shadowed: a shadowed key has a tail entry).
   3. Project, and return one entry per requested key, misses as `None` (S8).
8. **Count:** `FilterBitmapExec` cardinality over durable ∪ tail. No filter → `view.live_rows()`.
9. **`DocFetchExec` / `fetch_rows`:**
   - Durable row ids: one `dataset.take_rows(ids, ProjectionRequest::from_columns(["_pk", "_source" if needed, "_ingest_partition", "_ingest_offset", "_vector_i"…], dataset.schema()))`. Lance coalesces the reads. Columns absent from an older Lance schema (a vector added later) read as absent.
   - Tail row ids: from `tail.doc(row_id)`.
   - Output keeps the input order. A durable row id missing from the version is `Internal("row {id} is not in lance version {v}")`, since ids come from the same view.
10. **`filter_source`:**
    - `All` → the source; `None` → `None`.
    - `Paths { include, exclude }`, ES semantics: a pattern is a dotted path where `*` matches any run of characters, dots included. A key path *P* is included iff `include` is empty or some pattern matches *P* or a dotted prefix of *P*. Then *P* is excluded iff some `exclude` pattern matches *P* or a prefix of *P*.
    - Arrays are transparent: their elements are filtered by the same path. Objects left empty by `include` are removed.

11. **Constant-score text retrievers.** When a `Text` retriever's compiled query is `constant_score` and the effective sort is score-only, every match ties. The planner then computes its top k as the k smallest matching PKs: a k-way merge of `PkDictCache` cursors (rule 6's durable walk, checked against the query's `FilterBitmapExec` rows) with the tail's `keys_after`. It does not use `TantivySearchExec`. Scores are the constant; results equal the scoring path.

2. **Request rewrite.** The JSON is walked recursively. For every node `{"top_hits": {…}}`:
   1. Read its `_source` option (`true`/absent → `All`, `false` → `None`, a list of includes, or `{"includes", "excludes"}` → `Paths`) and remove it.

3. **Execution.** For each split in manifest order, then the tail, run `DistributedAggregationCollector` inside `MaskedCollector`, whose mask is:
   - the split's `SplitMask`, or the tail's non-live docs;
   - for `Rows`, also every doc whose `_rowid` is not in the set.

   - `{"_id": <pk JSON>, "_score": null, "_source": filter_source(source, remembered _source option)}` (omitted for `None`);
   - `"sort": <tantivy's sort values>`;
   - `"fields": {name: [values]}` for the remembered `docvalue_fields`, from the source through `field_values`.

   M1.5 relies on `_id`, `_score` and `_source` being present. Tantivy's `top_hits` sorts only by fast fields; hits that tie on every sort key come back in split then doc order (a documented limitation).

   3. Build `SnippetGenerator::new(terms, analyzer of the field, field, max_num_chars = fragment_size)`.
   4. Generate a snippet for each value of the field in the doc's source (`extract` at `source_path`).
   5. Render the snippet from `fragment()` and `highlighted()`: insert `pre_tag`/`post_tag` around each highlighted range, without HTML escaping (ES's default encoder). Values without a highlighted range are skipped.

**Semantics:**

   2. Resolve the namespace name and the collection (name or alias) with a `Local` read. An unknown namespace or collection → `NotFound { kind: "collection", name }` (S7: an absent namespace behaves like an empty one).
   3. `placement.owner(ns, cid)`: `Remote` → call the matching `RemoteReads` method with the *resolved collection name* and return its result. The implementation must forward `Operon-Hot` from `hot.enabled` and record the remote's `Operon-Hot-Used` into `hot.used` (documented on the trait).
   4. `Local` → the `*_local` path: `reads.view(…, hot_tier = if hot.enabled { current hot tier } else { Arc::new(NoHotTier) })`, then the planner.

   Validation (`validate_request`, `max_get_keys`, `max_scroll_limit`) runs before forwarding, so both sides reject the same requests.
2. **`ensure_namespace`:** validate the name (M0 `validate_name` rules, else `InvalidArgument`), then `create_namespace`. `NamespaceExists` is success.
3. **`create_collection`:**
   1. `ensure_namespace`.
   2. `schema.version = 1`; `schema.annotations[CREATED_AT_ANNOTATION] = meta.now_ms()`.

4. **`drop_collection`:** `reads.stop_collection(cid)` (when resolvable), then `MetaClient::drop_collection` → `Some` → `true`, `None` → `false`.
5. **`get_collection` / `list_collections`:**

     - `hot = current hot tier.status(ns, cid)`.
   - `list_collections` sorts by name. An absent namespace → `[]`.
6. **`add_fields`**, looping at most `schema_retries` times:
   1. Read the collection (`Linearizable`).
   2. `next = schema + fields + vectors`, with `annotations` merged in (a new key overwrites). A field or vector whose name exists with an *identical* spec is skipped, so retries are idempotent; with a different spec it is `AlreadyExists("field {name}")`.
   3. `check_additive` → `IncompatibleSchema` becomes `InvalidArgument`.
   4. `update_collection_schema(cid, schema.version, next)`. `SchemaVersionMismatch` → retry.

   After the retries: `Unavailable("schema update raced {n} times")`. On success, `reads.notify(cid)`. No backfill (A4).
7. **`update_aliases`:** `MetaClient::update_aliases`:

8. **`write`** (`write.rs`):
   1. Resolve the collection (aliases allowed); `ops.len() > 10_000` → `InvalidArgument`.
   2. **Dynamic mapping** (Ruling 18): with `DynamicMapping::Map`, collect the unmapped paths of every Upsert document, Patch source and Patch `upsert` document (`unmapped_paths`).    3. **`atomic`:** validate every op against the schema read in step 2 (`PrimaryKey::validate`, `check_document`, `check_patch`). The first failure fails the whole request with nothing written:
      - `SchemaViolation { field, message: "op {i}: {message}" }` for violations;
      - `InvalidArgument("op {i}: {message}")` for key and `delete_keys` errors.
   4. **`report_existence`:** read the current documents of the distinct keys with `get_local(…, Projection { source: All, vectors: every vector name, fields: [] }, Strong)`. Then simulate the ops in request order over that state *S* (Ruling 10):
      - `Upsert(d)`: `Created` if `S(k)` is `None`; `Noop` if `S(k) == d`; else `Updated`. Then `S(k) = d`.
      - `Delete`: `Deleted` if present, else `NotFound`. Then `S(k) = None`.
      - `Patch`:
        - absent with `upsert` → `Created`, `S = upsert`;
        - absent without → `NotFound`;
        - present → `n = apply_patch(Some(cur), op)`: `Noop` if `n == cur`, else `Updated`; `S = n`.
   5. `CollectionWriter::write(ns, cid, ops)`.
   6. Map op *i*:
      - `Written { partition, offset }` → `positions[i] = Some(OpPosition { partition, seq_no: offset })`, and `results[i]` = the simulated result (or `Accepted` without `report_existence`);
      - `Rejected(e)` → `Rejected(ServiceError)` with `OpError::InvalidArgument(m)` → `InvalidArgument(m)`, `SchemaViolation` → `SchemaViolation`, `DynamicMappingRequired { paths }` → `SchemaViolation { field: paths[0], message: "dynamic mapping required for {paths:?}" }`; `positions[i] = None`. A rejected op leaves *S* unchanged for later ops.

      Each partition's accepted ops are consecutive records in request order (one `append_many` batch per partition, M1.1), which M1.5 relies on for `_seq_no`.
   7. `reads.notify(cid)`.
   8. Return `WriteResult { token: outcome.token, results, positions }`.
9. **Error mapping** (Task 11 reuses it through `ServiceError`):
   - `WriteError::CollectionNotFound` → `NotFound { kind: "collection" }`; `TooManyOps` → `InvalidArgument`.
   - `LogError::{Backpressure, CommitUnknown, Closed, Store, Cache}` → `Unavailable`. The message for `CommitUnknown` says the outcome is unknown and that retrying keyed ops is safe. `LogError::InvalidArgument` → `InvalidArgument`; other `LogError`s → `Internal`.
   - `MetaError::{NotLeader, Timeout, Unavailable, ClockSkew}` → `Unavailable`.
   - `Rejected(ApplyError)`:
     - `InvalidArgument` and `IncompatibleSchema` → `InvalidArgument`;
     - `CollectionExists` and `NameTaken` → `AlreadyExists`;
     - `CollectionNotFound`, `UnknownCollection` and `NamespaceNotFound` → `NotFound { kind: "collection" }`;
     - `SchemaVersionMismatch` → `Unavailable` (callers retry);
     - anything else → `Internal`.
   - `CollectionError`: retryable → `Unavailable`, `ManifestGone` → `NotFound { kind: "pin" }`, `NotFound` → `NotFound { kind: "collection" }`, others → `Internal`.
10. **`versions`:**
    1. `live_manifest(Linearizable)`; no pointer → `[]`.
    2. `retained_chain(store, cache, live, config.keep_manifests, config.time_travel_retention, clock)`, with `clock` from a `Linearizable` `clock_ms` read.
    3. Map each manifest to `ManifestInfo { version, created_at_ms, size_bytes: Σ split size_bytes, live_doc_count, lance_version }`, in ascending version order.
11. **`pin`:** resolve the collection; `reads.pin(collection)` → `PinnedRead { collection: id, name, manifest_version, token }`.
12. **`shutdown`:** stop every tail and the catalog cache task.

### Task 13: Correctness gates — tail merge against a full rebuild, strong and pinned reads, determinism and the hot hooks

**Files:** `crates/operon-query/tests/{tail_vs_rebuild.rs,strong_reads.rs,pinned.rs,determinism.rs,hot_hooks.rs}`, `crates/operon-query/tests/common/mod.rs`, `.github/workflows/ci.yml` (the nightly step).

**Consumes:** everything above; M1.1's link source (applied on demand with `operon_worker::run_once`), GC (`GcSource::with_roots` with `CollectionGcRoots`) and trim sources.

**Semantics:**
1. **The query battery** `battery(collection) -> Vec<Probe>`, fixed and seeded. It holds 40 probes:
   - `search`: BM25 `Match`/`MatchPhrase`/`MultiMatch`/`Bool`; filtered text; field sorts with `search_after`; exact vector search in every metric; RRF and DBSF fusion; `track_total_hits` exact; `group_by`; highlight.
   - `get` of every key of the key space, including absent ones.
   - `count` with 6 filters.
   - `scroll` of the whole collection in pages of 7, with and without a filter.
   - `aggregations` over integer fields: `terms`, `stats`, `histogram`, `range`, `cardinality`.

   `run(probe)` returns its full JSON result, with `read_token` removed and every score as `f32::to_bits`.
2. **`tail_merge_equals_full_rebuild`** (proptest, `TAIL_PROP_CASES` cases, default 24; nightly 256). A history is a random sequence of 20–120 valid `DocOp`s over 24 keys of mixed types:
   - Upserts carry `title` (text from a 40-word vocabulary), `tag` (keyword from 5 values), `n` (an integer 0–9, possibly an array) and vector `v` (dim 4, or absent).
   - Patches cover all three modes, with and without `upsert`, and delete keys and vectors.
   - Deletes, 15 %.

   With 3 partitions, each case builds four fixtures of the same collection:
   - **tail:** every op written and never applied.
   - **durable:** every op written and applied through the link, in 1–4 commits at random cut points (the link is run after each cut). The tail is empty after `settle`.
   - **split:** a random prefix written and applied, the rest written and not applied.
   - **rebuild:** `fold` of the history gives the final documents. A fresh collection receives one `Upsert` per live key, applied in one commit.

   Every probe gives identical results on all four, except `seq_no`/`partition` fields, which differ only in *rebuild*: they are compared across the first three. On a failure the case prints the history and the diff.
3. **`strong_reads_during_link_apply_never_miss_or_duplicate`** (the ES-style write→read cycle, R11). A `Worker` applies the link continuously (batch interval 0), and one writer runs 300 iterations of "write doc *i* (`Upsert`, or every 5th an update of an earlier key), then immediately `search` for a term only doc *i* has, `get` it, and `count`". Every read sees exactly the acknowledged state, with no read token passed. There are never two hits for one key, and counts equal the model. Manifests land during the run (asserted: `manifest_version` ≥ 10 at the end).
4. **`pinned_reads_are_stable_under_writes_commits_and_gc`:**
   1. Pin, then record every probe's result.
   2. Write 200 more ops and apply them in 6 commits, with the tail compacting in between (`compact_min_entries` 10).
   3. Run GC (`keep_manifests` 10, retention 1 h): every probe under `Pinned` still equals the recorded results.
   4. Set `keep_manifests` 1 and retention 0, commit 3 more times and run GC and trim: every pinned probe is `NotFound { kind: "pin" }`.
5. **`results_are_identical_across_placements_and_hot_modes`:** one history in the four fixtures of item 2, each also run with a fake hot tier (item 6) on and off. All exact probes are equal across the eight runs. Mixed PK types, and duplicated documents that force score ties, are part of the history.
6. **`the_hot_hooks_never_change_exact_results`** (`hot_hooks.rs`). `FakeHot`:
   - `split_file` copies every split to a temp directory;
   - `ann` returns a `HotAnn` over the rows at manifest version *m* − 1, with scores perturbed by +0.05;
   - it counts every call.

   Checks:
   - every exact probe equals its `NoHotTier` result;
   - every approximate probe returns exact scores;
   - `hot_used` contains `splits` and `hnsw` with the hot tier on and is empty with `RequestHot { enabled: false }`, when `FakeHot`'s counters do not move.

**Tests:** the five named tests above (one file each; `determinism.rs` holds item 5). `cargo test -p operon-query` runs them with the default case counts; `TAIL_PROP_CASES=256 cargo test -p operon-query --release --test tail_vs_rebuild` runs in the nightly CI job `sim`, as a new step.
