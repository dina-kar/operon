# SF2 — The A2A Host and the Zulip, Plane and Forgejo Agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, headers, state names, error reasons), use them verbatim. The code is not pre-written in this plan; the tests are the specification.

> **Status: Planned** (2026-10-02). **Slot: track SF, second plan** (proposed; D-SF-6–D-SF-12). Branches `sf2-t<N>`, stacked; PRs target `main`. Depends on SF1 Tasks 1, 3 and 4 (`loams.collab.v1`, the broker, the adapters) and on D1's embedded Resonate (§21) for task state; the unified auth plan (D111, Q30) and MT1 (Authentik) gate Tasks 4 and 9's non-loopback parts, so until then every listener is **loopback only** and tokens are the dev issuer's. Tasks 0–3 and 6–8 can be built against loopback.

**Goal:** A2A 1.0 hosting in Loams and three agents on it:
- **`loams-a2a`**: a server host (cards, tasks, streaming, push) and a client (for Loams Bot, SF3), on the official Rust SDK, with the **task-to-operation mapping**, **signed Agent Cards**, **Authentik-rooted token exchange**, and **tracing**.
- **The `zulip`, `plane` and `forgejo` agents** (phase 1) with the skills of design §5.5, each its own principal, each risk-tagged, each reaching its app only through the credential broker.
- Conformance with the A2A project's own tooling, and security tests for prompt injection and secret leakage.

**Architecture:**
- **`crates/operon-a2a`**: `A2aServer<A: Agent>` (axum routes for JSON-RPC and HTTP+JSON, SSE streaming, push webhooks), the `Agent` trait (below), `AgentCardBuilder`, `CardSigner`/`CardVerifier` (JWS over RFC 8785 canonical JSON), `TaskStore` over §21 operations, `A2aClient` (discovery, verify, send, stream, resubscribe, cancel, push config), `PushReceiver`.
- **`crates/operon-agent-{zulip,plane,forgejo}`**: each a small crate: skills as functions, a card, an `Agent` implementation that runs an LLM tool loop (harness-style) over its own skills. Each builds into a binary `loams-agent-<name>` and as a library mounted in-process by `loams dev`.
- **Where they run:** `loams dev`: in-process on loopback ports; Kubernetes: Knative services (§38) behind the gateway at `agents.<domain>/<name>/`.
- **State:** task state is the §21 operation; the agent's conversation is its durable execution; nothing else is stored.

**Tech Stack:** Rust 1.97.1, edition 2024. The official A2A Rust SDK (`a2a-lf`, `a2a-client-lf`, Apache-2.0; `a2aproject/a2a-rs`, v1; **Task 0 pins the exact versions and checks them against `deny.toml`**), axum 0.8, `jsonwebtoken` or `josekit` (Task 0 picks; RFC 7515 and RFC 8785 canonicalisation via `serde_json_canonicalizer`), `loams-durable` (Resonate Rust SDK), the AI gateway client (aisix, OTLP GenAI spans), `opentelemetry` + `tracing-opentelemetry`, `wiremock`. Test tooling: `a2aproject/a2a-inspector` and the A2A technology compatibility kit `a2a-tck` for single-agent conformance, and `a2a-itk` (the integration testing kit: multi-hop agent clusters and transport scenarios) only for Task 10's cluster scenario, restricted to JSON-RPC and HTTP+JSON (Apache-2.0; Task 0 checks that each exists and what it runs), a Python A2A client (`a2a-python`) in CI for cross-language checks. **No tonic dependency is added** (gRPC is not served, design §5.2).

**Spec:**
- [`docs/design/39-software-factory-and-loams-bot.md`](../design/39-software-factory-and-loams-bot.md): §5 (all), §6, §8, §9, §11; D-SF-6–D-SF-12.
- [`docs/design/19-console-identity-and-agents.md`](../design/19-console-identity-and-agents.md) §5 (principals, tokens, revocation); [`21-durable-execution.md`](../design/21-durable-execution.md) §6.5–§6.7; [`37-desktop-and-mobile-apps.md`](../design/37-desktop-and-mobile-apps.md) §7.3 (approvals); [`30-loam-cli.md`](../design/30-loams-cli.md) D288 (secrets), §12 (MCP).

## Global Constraints

- **Loopback only until the unified auth plan** (D111). Any other bind fails startup with `a2a listen on <addr>: only loopback addresses are served until the unified auth plan (D111)`. With the dev issuer, tokens are real JWTs from `loams dev`'s test key; production issuers arrive with MT1.
- **No gRPC, no tonic** (design §5.2). HTTP+JSON and JSON-RPC with SSE.
- **A2A fields exactly as 1.0.0:** `SCREAMING_SNAKE_CASE` enums, wrapped stream events, no `kind` or `final`, `A2A-Version: 1.0` required (empty header treated as 0.3 and answered with `VersionNotSupportedError` for any method we do not serve at 0.3; we serve **1.0 only**).
- **No app secret in an agent.** Agents hold `CallPermit`s only (SF1 Task 3). The canary test covers each agent's binary output.
- **Untrusted text is data.** App content enters the model as quoted `untrusted` data parts (design §8 item 5).
- **Risk tags are mandatory:** an agent whose card has a skill without `read`, `write` or `destructive` fails to start.
- **Dedupe on `messageId`.** A resent message with a known id returns the first result.
- **The build machine.** One cargo build at a time, shared target. `CARGO_BUILD_JOBS=4 CARGO_INCREMENTAL=0` for size and time measurements.
- **Commit areas:** `a2a`, `agent-zulip`, `agent-plane`, `agent-forgejo`, `auth`, `docs`.

## Rulings made while writing this plan

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| 1 | **Build on the official `a2a-lf` crates** for types and bindings; own the task store, auth, signing and tracing | Types and wire shapes are the part that must match the LF spec; our storage and identity are Loams-specific | If the crate is not usable (Task 0), we generate types from the spec's `a2a.proto` with buffa and serve the two bindings ourselves; the tests are the same |
| 2 | **JSON-RPC and HTTP+JSON on one axum router**, one handler per operation, shared by both bindings | The spec requires functional equivalence | Differences found by Task 1's equivalence test are bugs in the shim, not in the handlers |
| 3 | **Task id = operation id** (design §5.3) | `GetTask` and the console's operation views stay one thing | A2A task ids must be opaque strings, which operation ids satisfy |
| 4 | **Agents are stateless between tasks**; context lives in the Loams Bot thread | Simpler restarts; the harness session is the durable store | An agent that wants memory writes it to a Loams collection through its own policy |
| 5 | **Push notifications are webhooks from agent to Loams Bot's receiver**, authenticated by the registered per-task credential of A2A's push configuration | A2A's mechanism; Loams Bot already has a public receiver for phones' wake-ups | Agents behind NAT cannot reach it; they run in the same cluster, so not an issue |
| 6 | **The coding session is the Forgejo agent's skill `propose_patch`** (D-SF-18) | One fewer public agent; the sandbox is existing machinery (§15) | Q-level: promote to its own agent later without changing the loop (the loop calls a skill by name) |

### Task 1: The server host and the two bindings

**Files:** `crates/operon-a2a/src/{lib.rs,server.rs,agent.rs,errors.rs}`, `tests/{main.rs,bindings.rs,conformance.rs}`, `scripts/a2a/*`.

**Produces:**

```rust
#[async_trait]
pub trait Agent: Send + Sync + 'static {
    fn card(&self, cx: &CardCtx) -> AgentCard;                       // base card (public) ; extended after auth
    fn extended_card(&self, cx: &Ctx) -> Option<AgentCard> { None }
    /// Runs one task. `tx` emits status and artifact updates; returning ends the task.
    async fn handle(&self, cx: &Ctx, task: TaskHandle, input: Message, tx: UpdateSink) -> Result<TaskOutcome, AgentError>;
    /// Called on `CancelTask`; must stop work and settle quickly.
    async fn cancel(&self, cx: &Ctx, task: &TaskId) -> Result<(), AgentError>;
}
pub struct A2aServer { /* axum Router */ }
impl A2aServer {
    pub fn new<A: Agent>(agent: A, cfg: A2aConfig, tasks: Arc<dyn TaskStore>, verifier: Arc<dyn TokenVerifier>) -> Self;
    pub fn router(&self) -> axum::Router;      // /.well-known/agent-card.json, /a2a (JSON-RPC), /a2a/rest/v1/* (HTTP+JSON)
}
pub const A2A_VERSION: &str = "1.0";
```

**Semantics:** all 11 operations of design §5.1 (Send, SendStreaming, Get, List with cursor pagination, Cancel, Subscribe, push config create/get/list/delete, GetExtendedAgentCard). `A2A-Version` is required; a missing or unsupported value answers `VersionNotSupportedError` (`-32009` on JSON-RPC, `400` with the `google.rpc.Status` body on HTTP+JSON, **verify the codes against the spec at Task 0**). SSE for streaming with the wrapped events (`statusUpdate`, `artifactUpdate`), a heartbeat comment every 15 s, and `Last-Event-ID` resume where the spec allows. `PushNotificationNotSupportedError` only if the card says `pushNotifications: false`. Loopback bind check as in the global constraints.

**Tests:** `tests/bindings.rs`: `send_message_roundtrip_jsonrpc`, `send_message_roundtrip_rest`, `bindings_are_equivalent` (the same request through both yields the same task, field for field after normalisation), `streaming_emits_wrapped_events_without_kind_or_final`, `unsupported_version_is_refused`, `missing_version_header_is_refused`, `list_tasks_paginates_by_cursor`, `unknown_task_is_task_not_found`, `non_loopback_is_refused`. `tests/conformance.rs` (CI, needs Docker or Python): `inspector_conformance` (`scripts/a2a/inspector.sh` runs the A2A inspector and `a2a-tck` against an echo agent), `python_client_roundtrip` (`a2a-python` sends, streams and cancels).

### Task 2: Tasks are operations

**Files:** `crates/operon-a2a/src/tasks.rs`, `tests/tasks.rs`.

**Produces:**

```rust
#[async_trait]
pub trait TaskStore: Send + Sync {
    async fn create(&self, cx: &Ctx, ctx_id: ContextId, msg: &Message, idem: &IdempotencyKey) -> Result<Task, TaskError>;
    async fn get(&self, cx: &Ctx, id: &TaskId) -> Result<Task, TaskError>;
    async fn list(&self, cx: &Ctx, filter: TaskFilter, page: Page) -> Result<(Vec<Task>, Option<Cursor>), TaskError>;
    async fn transition(&self, cx: &Ctx, id: &TaskId, to: TaskState, status_msg: Option<Message>) -> Result<(), TaskError>;
    async fn add_artifact(&self, cx: &Ctx, id: &TaskId, a: Artifact, append: bool) -> Result<(), TaskError>;
    async fn subscribe(&self, cx: &Ctx, id: &TaskId, from: Option<Cursor>) -> BoxStream<'static, TaskEvent>;
}
// DurableTaskStore implements it over loams-durable operations (design §5.3 table).
```

**Semantics:** the mapping of design §5.3: `SUBMITTED`/`WORKING` to `pending`/`running`; `INPUT_REQUIRED` to `awaiting_input` or `awaiting_approval` (the status message carries `data: { approval_id, revision }`); `AUTH_REQUIRED` to `awaiting_auth`; `COMPLETED`, `FAILED`, `REJECTED`, `CANCELED` to `succeeded`, `failed`, `rejected`, `canceled`. Terminal states are final; a transition out of one is `TaskNotCancelable`/an internal error as the spec says for each case. The task id is `op-` + the first 26 hex characters of SHA-256(namespace ‖ agent ‖ messageId) (D146), so a resent message is the same task; a repeated `messageId` with different parameters answers `409`-equivalent `InvalidParams` with reason `idempotency_key_reused`. Tenancy: the `tenant` field and the token's `org` must agree.

**Tests:** `resend_same_message_is_same_task`; `reused_message_id_with_other_params_is_refused`; `state_map_is_exact` (a table test over all eight states in both directions); `terminal_is_final`; `cancel_after_complete_is_not_cancelable`; `artifact_append_chunks_concatenate`; `subscribe_resumes_from_cursor`; `task_visible_as_operation_in_console_api` (the same id through `GetOperation`); `tenant_mismatch_is_refused`; `crash_resumes_task` (a failpoint kills the agent mid-task; the restarted agent resumes the durable function and the client's `SubscribeToTask` continues).

**Commit:** `a2a: tasks as durable operations`.

### Task 3: Signed Agent Cards

**Files:** `crates/operon-a2a/src/{card.rs,sign.rs}`, `tests/card.rs`.

**Produces:** `AgentCardBuilder` (name, description, version, interfaces with `protocolVersion: "1.0"`, capabilities, `securitySchemes` and `security`, default modes, skills with mandatory risk tags, the `https://loams.dev/a2a/ext/risk/v1` extension), `CardSigner` (EdDSA JWS; the signing input removes `signatures` **and every property that equals its A2A 1.0 default value** before RFC 8785 canonicalisation, as the specification requires, so external verifiers compute the same bytes; protected header with `kid` = the instance key id and `typ: "a2a-card+jws"` **(verify the spec's header requirements)**, payload the RFC 8785 canonical card without `signatures`), `CardVerifier` (fetches `/.well-known/jwks.json` of the card's issuer, caches with the JWKS cache headers).

### Task 4: Authentication and token exchange

**Files:** `crates/operon-a2a/src/auth.rs`, `crates/operon-a2a/tests/auth.rs`, `crates/operon-collab/src/broker.rs` (audience check).

**Produces:**

```rust
pub trait TokenVerifier: Send + Sync { /* `None` skips only the `aud` check (other Loams tokens); agent calls always pass `Some` */ fn verify(&self, bearer: &str, expect_aud: Option<&str>, expect_env: &str) -> Result<Principal, AuthError>; }
```

**Semantics (design §6.2):** the server verifies locally: signature against the instance JWKS, `exp`, `aud` equal to this agent's card interface URL (§19 §5.3 defines `env` as the audience and no `aud`; this task **amends §19 §5.3**: the gateway adds an `aud` claim to agent tokens, `env` stays the environment audience, and a verifier requires both for agent-to-agent calls and only `env` for other Loams tokens), `env` equal to the request's environment, `scp` covering the skill's scope (`<app>:read`, `<app>:write`, `<app>:destructive`). The 15-minute TTL cap applies. Until MT1 the issuer is `loams dev`'s test key; the code path is the same.

**Tests:** `valid_token_accepted`; `wrong_audience_refused` (a token for the Plane agent against the Forgejo agent); `expired_refused`; `wrong_env_refused`; `scope_too_narrow_refused`; `act_chain_must_include_loam_bot_for_user_calls`; `revoked_jti_refused_within_change_feed_latency`; `suspended_agent_refused`; `exchange_cannot_widen`; `ttl_is_capped_at_15_minutes`; `no_token_is_401_with_www_authenticate` (resource metadata per RFC 9728, as §19 §5.2).

### Task 5: The client, streaming and the push receiver

**Files:** `crates/operon-a2a/src/{client.rs,push.rs}`, `tests/{client.rs,push.rs}`.

**Produces:**

```rust
pub struct A2aClient { /* http client, CardVerifier, token provider */ }
impl A2aClient {
    pub async fn discover(&self, base: &Url) -> Result<VerifiedCard, ClientError>;       // fetch, verify, cache
    pub async fn send(&self, agent: &VerifiedCard, msg: Message, opts: SendOpts) -> Result<SendOutcome, ClientError>;
    pub fn stream(&self, agent: &VerifiedCard, msg: Message, opts: SendOpts) -> BoxStream<'static, Result<StreamResponse, ClientError>>;
    pub fn resubscribe(&self, agent: &VerifiedCard, task: &TaskId, from: Option<Cursor>) -> BoxStream<'static, Result<StreamResponse, ClientError>>;
    pub async fn cancel(&self, agent: &VerifiedCard, task: &TaskId) -> Result<Task, ClientError>;
    pub async fn register_push(&self, agent: &VerifiedCard, task: &TaskId, hook: PushHook) -> Result<(), ClientError>;
}
pub struct PushReceiver { /* axum route, verifies the registered per-task credential and (agent, task) binding, emits TaskUpdated events */ }
```

**Push contract (A2A's, plus one Loams extension).** `register_push` sets `TaskPushNotificationConfig.authentication` to scheme `Bearer` with credentials equal to a random per-task secret; the agent sends it as the `Authorization` header of every webhook; `PushReceiver` stores only its hash against the registered `(agent, task)` pair, compares in constant time, and rejects any webhook whose agent, task or secret does not match. A Loams-only JWS of the body in `X-Loams-Signature` (the agent's card key) is an optional extension, excluded from conformance claims.

**Semantics:** `send` and `stream` choose the binding from the card (JSON-RPC by default); they set `A2A-Version`, the bearer, `traceparent`/`tracestate`, and a deterministic `messageId` when the caller supplies a step key. A dropped stream is resubscribed from the last cursor with backoff; after `max_resubscribe` (default 5) the client falls back to polling `GetTask` every 2 s with jitter. The `PushReceiver` accepts a webhook only with the registered per-task credential (above), deduplicates by event id, and publishes `io.loams.dev.bot.task.updated.v1` CloudEvents.

**Tests:** `discover_verifies_signature`; `stream_resubscribes_from_cursor_after_drop`; `falls_back_to_polling`; `send_is_idempotent_on_message_id`; `cancel_propagates`; `traceparent_is_forwarded`; `push_with_bad_credential_is_refused`; `push_credential_bound_to_agent_and_task`; `push_from_other_agent_for_same_task_is_refused`; `push_for_unknown_task_is_dropped`; `push_duplicate_event_is_ignored`; `push_becomes_cloudevent`; `python_agent_interop` (the client against an `a2a-python` agent).

**Commit:** `a2a: client, resubscribe and the push receiver`.

### Task 8: The Forgejo agent and `propose_patch`

**Files:** `crates/operon-agent-forgejo/**` (`patch.rs`).

**Skills:** `repos.search`, `prs.get`, `ci.status`, `ci.logs_tail` (read); `branches.create` (name must be exactly `factory/<run>`, the same branch for every attempt), `prs.open`, `prs.comment`, `propose_patch` (write); `prs.merge` (destructive, approval in every environment), `branches.delete_protected` (destructive).

**Semantics:** `propose_patch(repo, base, instructions, context)` starts a **sandboxed coding session** (§15 D24: a session on a workspace branch of Loams Git, §36, with the repository checked out, no network except the model route and a package mirror, a wall-time and token budget from the task's budget) and returns a patch artifact (a diff, a summary, the tests it ran). The Forgejo agent applies it as a commit on `factory/<run>-<n>` and opens or updates the PR. `ci.status` aggregates Forgejo commit statuses and Actions runs; the **CI result is delivered to the loop by Forgejo's webhook**, not polled by the agent. `prs.merge` never calls Forgejo directly: it creates an approval and the broker releases the merge permit only for a settled approval whose hash covers repo, PR number, head SHA and base branch (so a pushed commit after approval invalidates it).

**Tests:** `branch_name_must_be_factory_run`; `propose_patch_runs_in_sandbox_without_network` (the sandbox fake records egress attempts: only the model route and mirror); `patch_artifact_has_summary_and_tests`; `pr_open_is_create_if_absent_per_branch`; `merge_requires_approval_in_every_environment`; `approval_invalid_after_new_head_commit`; `ci_logs_tail_is_untrusted_and_capped`; `agent_cannot_push_to_protected_branch`; `agent_cannot_touch_unlisted_repo`.
