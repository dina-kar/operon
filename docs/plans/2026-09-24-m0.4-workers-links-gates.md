# M0.4 — Workers, Links, PK Index, GC and the M0 Exit Gates Implementation Plan

> **For agentic workers:** execute task by task, test first. Each task lists the interfaces it must produce and the tests that must exist and pass before it is done. Where this plan gives exact values (names, paths, formats, constants), use them verbatim. The code is not pre-written in this plan (M0.3 Ruling 1).

> **Status: Done** (2026-09-24). Tasks 1–8 are committed on `m0.4-workers-links-gates`, and every item in "Carried in" is closed with a test. The M0 exit gates pass: see the [M0 exit report](m0-exit-report.md).

**Goal:** Finish milestone M0. Ship:
- the worker task framework (leases, priorities, fair share), moving the M0.3 segmenter and retention onto it;
- the link framework with exactly-once apply, proven against a toy target;
- `PkIndex` on SlateDB;
- garbage collection of retired and orphan objects;
- the M0 exit gates: kill -9 at every step of the write, commit, segment, link and GC paths; the object-store fault matrix; linearizability checks of the sequencer and manifest-pointer CAS; a seeded simulation harness that runs on every PR.

**Architecture:**
- `operon-worker`: generic scheduler over meta leases. Task sources propose task keys; a worker acquires `task/<key>` leases, runs tasks with a fence and a cancellation signal, renews and releases.
- `operon-link`: link catalog (in meta), the `LinkTarget` trait, and the link-apply task. It reads a stream through `LogReader`, applies to a target, and commits data together with applied offsets under optimistic concurrency and a lease fence.
- `operon-pk`: `PkIndex` wrapper over SlateDB, one fenced writer per index.
- `operon-log::gc`: the GC task.
- `operon-sim` (test-only, `publish = false`): seeded in-process cluster simulation, history recording and a Wing–Gong–Lowe linearizability checker.
- Failpoints (`fail` crate) behind a `failpoints` cargo feature. The crash harness runs the `operon` binary as a child process and aborts it at each failpoint.

**Tech Stack:** Rust 1.97.1; new: `slatedb` 0.16 (object_store 0.14 + foyer 0.22, same as the workspace), `fail` 0.5 (Apache-2.0), `rand` / `rand_chacha` (seeded schedules), `tokio-util` (`CancellationToken`).

## Global Constraints

Same as M0.3's Global Constraints, plus:
- A fenced (stale-epoch) task must never change durable state: every commit it attempts is rejected by a fence or by optimistic concurrency.
- GC must never delete an object that is referenced by meta (offset index, pointer, retired-but-within-grace), and deletes only objects older than `gc.grace` (default 1 h; ≥ the longest read).
- Failpoints compile to nothing unless the `failpoints` feature is on; release builds never contain them.
- Commit areas: `worker`, `link`, `pk`, `log`, `store`, `meta`, `sim`, `operon`, `ci`, `docs`.

## Review Focus

1. **A task whose lease expires mid-run while it is still running (GC pause, slow I/O).** A new holder takes over; the old holder's commit must be rejected and must not corrupt the target. Tests: Tasks 1, 3, 7.
2. **GC racing a reader, the segmenter or a link.** An object read or referenced moments before must never disappear under a successful read. Tests: Task 4, Task 7.
3. **Crash between a target's data PUT and its pointer CAS, and between the CAS and the task noticing.** Restart must apply each source record exactly once. Tests: Tasks 3, 5.
4. **A SlateDB writer that is fenced by a newer writer.** Its writes must fail, never silently land. Tests: Task 2.
5. **An indeterminate (timed-out) write in the linearizability histories.** The checker must treat it as "maybe applied", or it will report false violations or hide real ones. Tests: Task 6.

### Task 1: `operon-worker` — task framework; segmenter and retention move onto it

**Produces:**

```rust
#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Debug)]
pub enum Priority { LinkApply, Segmenting, Compaction, HotBuild, Maintenance, Gc }   // highest first (§09 §6)
pub struct TaskKey { pub namespace: Option<NamespaceId>, pub key: String }            // lease key = "task/" + key
pub struct TaskContext { pub key: TaskKey, pub fence: Fence, pub cancel: CancellationToken, pub meta: MetaClient }
#[async_trait] pub trait Task: Send + Sync { async fn run(&self, ctx: TaskContext) -> Result<TaskOutcome, TaskError>; }
pub enum TaskOutcome { Done, MoreWork /* reschedule immediately */, Idle /* wait for the next poll */ }
#[async_trait] pub trait TaskSource: Send + Sync {
    fn priority(&self) -> Priority;
    async fn candidates(&self, meta: &MetaClient) -> Result<Vec<(TaskKey, Arc<dyn Task>)>, TaskError>;
}
pub struct WorkerConfig { pub owner: String, pub poll_interval: Duration /* 1 s */, pub lease_ttl: Duration /* 30 s */,
                          pub max_concurrent: usize /* 16 */, pub max_per_namespace: usize /* 4 */ }
pub struct Worker;  // new(meta, config); add_source(Arc<dyn TaskSource>); start() -> WorkerHandle
pub struct WorkerHandle; // stop().await: cancel tasks, wait, release leases
```

**Semantics:** each poll collects candidates from all sources, orders them by priority, then round-robin across namespaces within a priority, and skips keys already running locally. Up to the concurrency caps, it acquires `task/<key>` with `lease_ttl` (`LeaseHeld` → skip) and spawns `run` with `fence = { lease: "task/<key>", epoch }`. Leases are renewed every `ttl / 3`; a failed renew (`LeaseLost`) cancels the token. On finish it releases the lease. A task must stop promptly on cancel and must pass `ctx.fence` to every meta commit it makes.

The M0.3 `Segmenter` and `Retention` loops become `SegmenterSource` (one task per partition needing work, `Priority::Segmenting`) and `RetentionSource` (singleton key `retention`, `Priority::Maintenance`). They use the context fence instead of their own leases. The M0.3 background loops are removed, and the `operon` server now runs a `Worker` with these sources.

**Tests:**
- Two workers never run the same key concurrently (instrumented task with an overlap detector, many iterations).
- A task whose lease is taken over (inject a paused renew, then a second worker acquires it) is cancelled, and its fenced commit is rejected.
- Priorities: with a concurrency cap of 1, higher-priority tasks run first.
- Fair share: a namespace with 100 candidates does not starve one with 1.
- Worker drop → lease expiry → the other worker runs the task.
- The segmenter and retention tests from M0.3 still pass through the framework.

Commit: `worker: add the lease-based task framework`; `log: run the segmenter and retention as worker tasks`.

### Task 3: `operon-link` — link catalog, `LinkTarget`, link apply, `CounterTable`

**Meta additions (in `operon-meta`):**

```rust
Command::CreateLink { namespace: NamespaceId, name: String, source: StreamId, target: TargetRef, options: BTreeMap<String, String> }
    // -> Reply::LinkCreated(LinkId); names unique per namespace; retry returns LinkExists(id)
pub struct LinkId(pub u64);  pub struct TargetRef { pub kind: String, pub name: String }
pub struct Link { pub id: LinkId, pub namespace: NamespaceId, pub name: String, pub source: StreamId, pub target: TargetRef, pub options: BTreeMap<String,String> }
// MetaState: link(id), links(namespace); MetaClient: create_link(..)
```

**Produces (`operon-link`):**

```rust
pub struct TargetState { pub version: u64, pub applied: BTreeMap<u32, u64> /* partition -> next offset to apply */ }
pub struct ApplyBatch { pub records: Vec<(u32, OffsetRecord)>, pub applied_after: BTreeMap<u32, u64> }
pub enum CommitError { Conflict /* target version moved */, Fenced, Other(..) }
#[async_trait] pub trait LinkTarget: Send + Sync {
    async fn load(&self) -> Result<TargetState, LinkError>;
    async fn commit(&self, expected_version: u64, batch: ApplyBatch, fence: &Fence) -> Result<u64 /* new version */, CommitError>;
}
pub struct LinkApplySource;  // TaskSource: one task per link (Ruling 3), Priority::LinkApply
pub struct LinkConfig { pub batch_records: usize /* 10_000 */, pub batch_interval: Duration /* 2 s */, pub max_batch_bytes: usize /* 64 MiB */ }
pub struct CounterTable;     // LinkTarget + read API: open(meta, store, ns, name); get(counter) -> i64; applied() -> BTreeMap<u32,u64>
```

**Apply loop (exact):**
1. `load()` → `(version, applied)`.
2. For each partition, `fetch` from `applied[p]` (0 if absent) up to the batch limits.
3. If there are no records, return `Idle`.
4. `commit(version, batch with applied_after = last offset + 1 per partition, fence)`.
5. `Conflict` → reload and retry from 1. `Fenced` → return.

A commit carries data and applied offsets atomically, so a crash anywhere re-reads `applied` and re-applies only what was not committed.

**`CounterTable` storage (exact):**
- Data: `ns/<ns>/links/<link_id>/data/<ulid>.cnt` — postcard `BTreeMap<String, i64>` of the batch's deltas, `put_if_absent`.
- Manifest: `ns/<ns>/links/<link_id>/manifests/<version:020>.man` — postcard `{ version, parent, data: Vec<String>, applied: BTreeMap<u32,u64> }`, `put_if_absent`.
- Commit: `cas_pointer(ns, "link/<link_id>", expected = Some(version) or None for version 0, value = manifest path, fence = Some(fence))`. `VersionMismatch` maps to `Conflict` and `Fenced` to `Fenced`.
- Reads: the pointer → the manifest → sum all data files. Values that do not parse as i64 are dead-lettered: counted in `skipped` in the manifest and not applied.

**Tests:**
- Exactly-once under crashes: for each step boundary (after data PUT, after manifest PUT, after CAS), abort the task there (in-process: drop the task future at the failpoint; the Task 5 harness does the real process abort). Restart; the final sums equal the model computed from the stream, and `applied` equals the high watermarks.
- Zombie: two tasks with different epochs race (the old epoch continues after takeover). Sums still equal the model.
- Conflict retry path.
- Link over a stream being segmented and trimmed concurrently.
- `CreateLink` retry returns the same id.

Commit: `meta: add the link catalog`; `link: add exactly-once link apply and the CounterTable target`.

### Task 4: Garbage collection

**Produces:** `operon-log::gc::{GcSource, GcConfig { grace: Duration /* 1 h */, interval: Duration /* 60 s */, list_page: usize }}`, a singleton task `gc` at `Priority::Gc`.

**Semantics (exact):** each run performs three passes.
1. **Retired objects.** Objects in `MetaState::retired()` with `retired_at_ms + grace <= now` are deleted (`NotFound` counts as deleted). Then `forget_objects(deleted)` is called, fenced by the task lease.
2. **Orphan WAL objects.** List `wal/`. Delete objects whose ULID time plus `2 * WAL_COMMIT_WINDOW_MS + grace` is `<= now`, that are absent from `wal_live_chunks`, and that are not in `retired`.
3. **Orphan segments and link objects.** List `ns/<ns>/streams/` and `ns/<ns>/links/` for every namespace. Delete segment objects not referenced by any index entry and not retired, and link data/manifest files not reachable from the live manifest or its last `keep_manifests` (default 10) ancestors. In both cases only objects older than `grace` (by ULID or LastModified) are deleted.

**Tests:**
- Property test: GC running continuously alongside writers, readers, the segmenter, retention and a link, with `grace` small but longer than the reads. Every acknowledged record stays readable, `CounterTable` sums stay correct, and orphans are eventually deleted.
- A crash between delete and forget re-runs cleanly.
- An object younger than `grace` is never deleted.

Commit: `log: add garbage collection of retired and orphan objects`.

### Task 6: `operon-sim` — seeded simulation and linearizability checks

**Produces (crate `crates/operon-sim`, `publish = false`, test-only consumers):**

```rust
pub mod linearizability {
    pub enum Outcome<R> { Ok(R), Indeterminate }                  // Indeterminate = timed out / unknown
    pub struct Op<I, R> { pub client: u32, pub invoke: u64, pub complete: u64 /* u64::MAX if indeterminate */, pub input: I, pub outcome: Outcome<R> }
    pub trait Model: Clone { type Input; type Output; fn step(&self, input: &Self::Input) -> (Self, Self::Output); }
    pub fn check<M: Model>(initial: M, history: &[Op<M::Input, M::Output>]) -> Result<(), Violation>;  // WGL with memoisation
    pub struct SequencerModel;   // per-partition: commit(object, records) -> base_offset (idempotent by object), read_hwm -> u64
    pub struct CasRegisterModel; // cas(expected, value) -> Ok(version) | Mismatch(current), read -> Option<(version, value)>
}
pub struct SimConfig { pub seed: u64, pub steps: u32, pub meta_nodes: u8 /* 3 */, pub writers: u8, pub partitions: u32, pub fault_rates: FaultRates }
pub fn run(config: SimConfig) -> SimReport;   // SimReport { seed, schedule: Vec<Event>, histories, violations }
```

**The simulation** builds an in-process cluster from `SimConfig`: meta nodes over `Router`, `LogWriter`s, a `LogReader`, a `Worker` with the segmenter, retention, link and GC sources, and `FaultyStore::random(seed, rates)`. It drives a seeded workload of appends, fetches, `cas_pointer` from several clients, isolate/heal of meta nodes, worker restarts and store fault bursts, records every client operation with invoke and complete times, and then checks:
1. Linearizability per partition sequencer and per CAS register key.
2. Every acknowledged append is readable.
3. `CounterTable` equals the model.
4. Meta invariants.

On failure it prints the seed and the full schedule.

**Tests:**
- Checker unit tests with hand-written histories: linearizable, non-linearizable (stale read, lost update, duplicate offset), and ones with indeterminate operations that are only linearizable when the operation is taken as applied, and only when it is taken as not applied.
- `tests/sim.rs`: `SIM_SEEDS` (default 32 seeds × 300 steps in CI; `SIM_SEEDS=1000` nightly) must all pass.

**CI:** add a job `sim` running `cargo test -p operon-sim --release --locked` (default seeds).

Commit: `sim: add a linearizability checker`; `sim: add the seeded cluster simulation`; `ci: run the simulation seed sweep`.

## Rulings made during execution

The implementation made these rulings where this plan was silent, ambiguous or did not fit the code. The commit messages and doc comments record them too.

| # | Ruling | Why |
|---|---|---|
| E1 | `TrimPartition`, `PruneWalCommits` and `ForgetObjects` carry an optional `fence`, checked before anything changes. `ReacquireLease` re-takes an expired lease at the same epoch if nobody else took it | A fenced task must never change durable state (Global Constraints). Fences at an unchanged epoch never stopped being valid, so re-taking keeps `AcquireLease`'s semantics (N3) |
| E2 | `MetaNode::shutdown` waits for the redb file to close, not for the last `Arc` to drop | `Arc`'s strong count reaches zero before the database is dropped (N4) |
| E3 | Task keys are `segmenter/<stream>/<partition>`, `retention`, `gc` and `link/<link_id>`, each under the lease `task/<key>`. `Worker` defaults: poll every 1 s, lease TTL 30 s, `max_concurrent` 16, `max_per_namespace` 4. `run_once` runs one deterministic pass through the same lease machinery. `WorkerHandle::pause_renewals` is a test hook | Design §09 §6 gives no numbers; `run_once` keeps the M0.3 `run_once` tests and tools working |
| E4 | `SegmenterConfig` loses `interval` and gains `swap_deadline` (default 10 min): a segment not swapped in within that time of its PUT is abandoned to GC. The segmenter deletes its own segment only when a rejection answered its first swap attempt | A segment must never be swapped in after GC could delete it. Only a first-attempt rejection proves the swap never applied (M7) |
| E5 | `PkIndex` uses slatedb 0.16 with default features off, over the workspace's `object_store` and Operon's cache. `PkReader` is read-only and writes no reader checkpoints | One writer per object (§03 §5). A reader must not write into the index |
| E6 | `ObjectInfo` carries `last_modified_ms` | GC and orphan-manifest adoption need an object's age when its name holds no ULID |
| E7 | Snapshot format version 3 (link catalog), then 4 (incremental byte counts). Older snapshots are rejected | Nothing is deployed yet (M13) |
| E8 | `CounterTable` writes create-only data and manifest objects under `ns/<ns>/links/<link_id>/` and commits with a fenced CAS of the pointer `link/<link_id>`. A commit that finds an orphaned manifest at its version adopts it while the manifest and its data are younger than `max_commit_delay` (default 10 min). Values that do not parse are counted dead letters | Manifest paths are fixed by version, so a crash or a fenced task between the manifest PUT and the CAS leaves an object the next commit must either use or step over |
| E9 | GC's third pass uses a `GcRoots` trait (`operon-log`), and `operon-link` provides `LinkGcRoots`. Without a root for a prefix, nothing under it is deleted. GC confirms its lease with a linearizable read before each batch of deletes | `operon-log` cannot depend on `operon-link`. Object deletes cannot be fenced by the metastore |
| E10 | `MetaState::check_invariants` checks: the index tiling, live-chunk accounting, byte counts, and that no retired object is referenced. The meta property test, the crash gate, the fault matrix and the simulation all use it | One definition of "no torn state" |
