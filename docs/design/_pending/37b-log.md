## Decisions (paste into `docs/design/13-decision-log.md`, Decisions table, after D479)

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D480 | 2026-10-02 | **The Loams desktop is native, on a fork of zeron (`ostrium-labs/loams-desktop`, MIT, public), and it supersedes the Tauri desktop.** The owner's ruling. Zeron is Rust on GPUI with an engine daemon, an ACP and native-protocol harness layer, and a gpui UI. Products: **Loams Desktop** (the app), **Loams Bot** (the one chat that drives the platform agents) and **Loams Software Factory** (the loop, §39). The cordis web console stays in the browser (AP1a); mobile stays native SwiftUI and Compose (D433). Amends D420, D429–D432, D439 (§37 §18) | The owner prefers native over Tauri for desktop, and zeron already is the agent and session surface Loams Bot needs | **Owner ruling** |
| D481 | 2026-10-02 | **Keep, change, add, drop** (§37 §18.2). Keep: the engine, harness drivers, the gpui UI, themes, the local-only profile, the CLI and the updater mechanism. Change: branding, the default edge and WorkOS (both fail closed), the update feed, sign-in. Add: crates `loams-brand` and `loams-link`, the Loams Bot harness, later `loams-panels`. Drop from the product: zeron's Cloudflare edge, landing site, its iOS app and its TestFlight and deploy workflows. Nothing is renamed wholesale | Rebasing stays cheap only if the fork is additive; the rest is unreachable or private to zeron's cloud | Proposed |
| D482 | 2026-10-02 | **The two engines meet through three narrow seams and are never merged.** (1) **Supervise** the `loams` binary through its CLI JSON contract (D283), as AP1 did, for stacks. (2) **Talk Connect** to a running loams server with clients generated by buf for Rust (`loams.instance.v1` today; approvals, operations, collab and bot as AP0 and SF land). (3) **Spawn** Loams Bot as an ACP agent, `zeron loams bot-acp`, from zeron's own engine. The `loams` engine is **not embedded** in the app and zeron's engine is not extended to run stacks | Embedding would put a 950-crate workspace beside GPUI in one link, tie crash and version fate together, and duplicate the CLI's stack supervisor; three seams give isolation and independent releases | Proposed |
| D483 | 2026-10-02 | **Loams Bot is a new harness in zeron's engine, spoken to over ACP.** `HarnessId::LoamsBot` runs `zeron loams bot-acp` (this binary: nothing to install), which turns each prompt into an A2A `SendMessage`, shows each A2A task as an ACP tool call (a card with live status), relays `INPUT_REQUIRED` and never answers it (D468), and maps cancel to `CancelTask`. In production the shim speaks `loams.bot.v1` to Loams Bot (D465: clients never speak A2A to the agents); the A2A stub client is the scaffold's stand-in and a developer escape hatch (`LOAMS_BOT_URL`). Amends D478 for desktop: no ported harness UI, no `@loams/plugin-bot` (§37 §18.4) | Zeron's chat, threads, queue, steering and tool cards come free; one protocol shim is far less code than a conversation UI | Proposed |
| D484 | 2026-10-02 | **App UIs on desktop: native GPUI panels for the loop's objects (from `loams.collab.v1`, SF1), the system browser for full app UIs, an in-app sidebar browser opt-in per platform behind a spike.** Zeron's sidebar browser is a WebKitGTK helper process on Linux (ephemeral data store), WKWebView through `wry` on macOS, and **absent on Windows**. It is a top-level page, not a frame, so the edge changes of D462 (removing `X-Frame-Options`) are not needed for it. D464 (Tauri child webviews) is superseded (§37 §18.5) | The system browser has the person's Authentik session and passkeys on every OS today; the embedded one cannot persist them yet | Proposed |
| D485 | 2026-10-02 | **Plugins: three tiers, none of them cordis.** (1) Now: **MCP servers and ACP agents**, which zeron already configures and injects (its own `zeron mcp` server is injected into every run); (2) first-party **native panels** compiled in behind cargo features; (3) later, third-party **WASM components** on wasmtime with a declarative UI interface (WIT) that the host renders in GPUI, scoped by a permission manifest and the attenuated tokens of D426. Zed's extension host is not adopted. Cordis plugins keep running in the browser console only (§37 §18.6) | Zeron has no extension runtime of its own; MCP and ACP cover tools and agents today; wasmtime is already Loams' choice for functions (§24) and keeps third parties out of the UI process | Proposed |
| D486 | 2026-10-02 | **Sign-in is Authentik OIDC (code + PKCE, system browser, loopback redirect), replacing zeron's WorkOS login.** The refresh token is in the OS keychain, the access token in memory only, the issuer and public client id (`loams-desktop`) come from `GetInstance`. The RFC 8693 exchange at the Loams gateway (D431) waits for the unified auth plan (Q438); until then the Authentik access token is the bearer. Zeron's WorkOS client id is a non-zeron placeholder in the fork (not empty: an empty id selects the Development scope, which `zeron status` reports unhealthy), so its auth code stays compiled but unreachable (§37 §18.7) | D404 and D431 stand; zeron's tenant belongs to zeron's private cloud | Proposed |
| D487 | 2026-10-02 | **Zeron's multi-device sync is not used.** It runs on zeron's Cloudflare Durable Objects with WorkOS; the fork never contacts it (the default edge host cannot resolve). The desktop is local-first on its device. Cross-device continuity is Loams' job: the same Loams Bot thread is visible everywhere because it is a durable execution on the server (D478, §39 §13). Whether the Loro document layer gets a Loams transport is Q483 | A hosted dependency on another company's backend is unacceptable; local-only is zeron's tested default | Proposed |
| D488 | 2026-10-02 | **Stacks: supervise the `loams` CLI, as D429 said, from the native app.** Every stack action is `loams stack <verb> --output json` (D283); `LOAMS_HOME` is shared with the terminal; stacks outlive the app; creation and deletion stay copy-paste commands in the first release. The `keep_running` restart policy (backoff 1 s to 30 s, five in ten minutes) moves into `loams-link`. Windows stays remote-only (Q437). Bundling versus downloading the binary (Q428) carries over. Amends D429 | The CLI already owns the supervisor; only the shell around it changed | Proposed |
| D489 | 2026-10-02 | **Credential rule for a native app.** Tokens live in `loams-link` (memory) and the OS keychain, never in a process the user's agents or a browser can read: agent subprocesses and the sidebar browser never receive a Loams token; the injected `zeron mcp` server carries chat identity only; calls an agent makes to Loams go through the credential broker with an attenuated, audience-bound token (§39 §6). D430's capability allowlist and `net_fetch` bridge are retired: a native app has no webview holding JavaScript to defend against. Supersedes D430 | The Tauri bridge solved a problem native code does not have; the new threat is the agent subprocess | Proposed |
| D490 | 2026-10-02 | **Updates and signing.** Zeron's updater mechanism is kept (versioned managed installs, a manifest with SHA-256 per artifact, relaunch). The fork's feed is **GitHub Releases of `ostrium-labs/loams-desktop`**, later `loams.dev/desktop`. Because zeron's manifest is integrity-checked by TLS and SHA-256 alone, the fork adds a **detached Ed25519 signature over the manifest**, verified in `zeron-update` with a key separate from the CLI's (Q282), and refuses an unsigned manifest. Until then the default feed host cannot resolve, so a Loams build never installs zeron's binaries. macOS: Developer ID and notarization through zeron's packaging script and secrets; Windows: Authenticode on the Inno Setup installer; Linux: the tarball and `install.sh`. Supersedes D432's Tauri updater | Fixes a supply-chain gap and an identity hazard in one place | Proposed |
| D491 | 2026-10-02 | **Upstream-tracking policy.** The fork keeps `upstream` (`zeronsh/zeron`) as a remote and **rebases `main` onto upstream release tags, not upstream `main`**, at least every two weeks (upstream shipped about 30 releases and 670 commits in September). Loams changes are additive crates, marked one-line hooks (`// loams:`) and a patch ledger in `LOAMS.md`; a CI job fails if an inherited file changes without a ledger line. What is generally useful goes **upstream first** as a small PR: a config-driven custom ACP agent, signed manifests, a persistent browser store, the Windows browser. What stays: anything that names Loams (§37 §18.9) | A 180k-line UI that moves daily cannot be merged with; small marked patches rebase mechanically | Proposed |
| D492 | 2026-10-02 | **Licensing and attribution.** `LICENSE` (MIT, Copyright (c) 2026 Wing) stays unmodified; a root `NOTICE` states the fork and the Apache-2.0 licence of the Loams-added crates (D220); `THIRD_PARTY_NOTICES.md` stays upstream's. Zeron's GPUI is `zeronsh/zui`, an Apache-2.0 extraction from Zed with the GPL tracing crates removed, and its README states it uses none of Zed's GPL crates; a `cargo deny` licence job guards that. The product never uses "Zeron" as a name | MIT requires the notice; Apache-2.0 for new code matches D220 | Proposed |
| D493 | 2026-10-02 | **The desktop lives in its own repository, `ostrium-labs/loams-desktop`, not in the monorepo.** It is a fork with upstream history. It vendors the protos it uses by pinned ref (`proto/PIN`, `scripts/loams/sync-protos.sh`) exactly as `loams-mobile` does. The monorepo keeps AP0 (protos, the apps mock), AP1a (the browser console) and the CLI. Amends D439, which put desktop in `web/apps/desktop` | A fork cannot be a directory of another repository without losing its history | Proposed |
| D494 | 2026-10-02 | **Platforms.** Linux x86_64 and aarch64 (Wayland and X11), macOS on Apple silicon, Windows x86_64: the set zeron's release workflow builds. Known gaps are written down, not hidden: no sidebar browser on Windows, no screen-reader support in GPUI (an accessibility risk, §37 §18.10), a GPU (Vulkan, Metal, Direct3D) is required, WebKitGTK 4.1 is needed only for the Linux browser tab | Honest platform promises beat a matrix of checkmarks | Proposed |
| D495 | 2026-10-02 | **Testing.** Loams code is in crates with no GPUI dependency (`loams-brand`, `loams-link`), so unit and protocol tests run in seconds on Linux, Windows and macOS; a built-binary smoke test drives `zeron loams status`, `bot` and `bot-acp` against the in-process mock on Linux and Windows; generated code is checked for drift; upstream's UI, engine and Windows suites run on every change. The Tauri plan's `tauri-driver` e2e is dropped, and with it risk 10 (no WebDriver for WKWebView) | Native code is testable without a browser driver | Proposed |
| D496 | 2026-10-02 | **Mobile is unchanged.** AP2 and AP3 stay native Compose and SwiftUI over Connect (D433). Zeron's own iOS app and its Rust mobile core are not adopted by this decision (Q495 asks whether the core is worth reusing) | The owner's ruling covers desktop; the phone apps are a different contract | Proposed |
| D497 | 2026-10-02 | **Loams Bot never auto-approves.** Zeron's ACP driver answers an agent's permission requests with the preferred allow option because its sessions run unattended. Loams Bot sends none; every approval it relays is a Loams approval decided by a person with a proof (D435, D468), through a native approval panel or the console. For third-party coding agents zeron's behaviour is documented in the app; an "ask" mode for managed installs is Q485 | A prompt-injected agent must not be able to widen its own permissions | Proposed |
| D498 | 2026-10-02 | **No telemetry.** Zeron's Rust crates contain none (checked by search on 2026-10-02); the fork adds none, matching D284 and Q433's default. Crash reports, if ever, are opt-in | Trust, and one less thing to patch on every rebase | Proposed |
| D499 | 2026-10-02 | **Phasing: plan AP1n replaces AP1.** AP1a loses its `desktop` catalog patch and `@loams/platform-tauri`; AP0 is unchanged; SF1's Tauri child-webview tasks become native panels, and SF3's desktop task becomes the harness shim of D483. AP1n Task 0 verifies the scaffold; Tasks 1–10 follow (§37 §18.11 and the plan) | One desktop plan, no stale Tauri tasks | Proposed |
