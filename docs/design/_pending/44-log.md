## Decisions (paste into `docs/design/13-decision-log.md`, Decisions table, after D599)

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D600 | 2026-10-02 | **One API: every application call is a Connect/gRPC RPC in `loams.<service>.v1`, served by the single `loams` binary on one port** (default 8080). Connect serves gRPC, gRPC-Web and the Connect protocol there, plus `grpc.health.v1` and reflection. Prebuilt variants (§30 §9) bundle the dependencies; a service whose engine is not in the variant answers `UNIMPLEMENTED` with `reason=feature_not_in_variant`. `GetInstance` gains `services[]` for feature detection (§44 §4) | The owner's direction: a unified gRPC API in a single `loams`, dependencies prebuilt | Proposed |
| D601 | 2026-10-02 | **gRPC compatibility services are also mounted on the main port** by service name (Flight SQL, Qdrant gRPC) and keep their conventional ports as aliases; REST-shaped compat surfaces (Qdrant REST, Elasticsearch) keep their own ports | One port for firewalled deployments without breaking unmodified clients' defaults | Proposed |
| D602 | 2026-10-02 | **The bespoke REST APIs are removed**: M1.2's native REST under `/v1/namespaces/...`, the console's OpenAPI `/api/v1` and `api/console/openapi.json`, and any other hand-written JSON/HTTP application endpoint. **Kept as protocol endpoints, not application API**: `/health`, `/ready`, OAuth `token` and `authorize` (RFC 6749, 7636, 8693), OIDC redirect start and callback, `/.well-known/*` (RFC 8414, 9728) and JWKS. Migration table in §44 §5. Resolves Q423 (console moves to Connect) | One contract; the RFC and browser endpoints have fixed shapes every OAuth library expects | Proposed |
| D603 | 2026-10-02 | **The compatibility surfaces are kept and unchanged**: Qdrant REST and gRPC, Elasticsearch REST, Postgres wire, the Kafka gateway, Flight SQL, the Resonate HTTP protocol, MySQL through Vitess and WeSQL, Git Smart HTTP, MCP, CloudEvents bindings. They exist so unmodified third-party clients work, and removing them breaks the drop-in promise. They are adapters over the same internal service traits; a compat surface never reaches storage directly | The product's drop-in promise (D48 and the compat decisions) | Proposed |
| D604 | 2026-10-02 | **Supersedes D101 and M1.6 Rulings 1 and 4**: no OpenAPI for a native REST; the Go SDK and every other SDK are generated from the protos. M1.6's REST SDKs (`loams-client`, `@loams/client` over REST) are replaced by Connect SDKs under the names `loams` (PyPI) and `@loams/client` (npm); the fixture-corpus idea survives as the conformance corpus. M1.6's MCP task is unchanged | Pre-release, no external users; one contract instead of two | Proposed |
| D605 | 2026-10-02 | **Deprecation shims for one release**: each removed route answers a JSON "moved" body naming the RPC, with `Deprecation` and `Sunset` headers, behind `--legacy-rest` (off by default), and is deleted the next minor. May be skipped (Q600) | Gentle migration for anyone who tried the M1.2 REST | Proposed |
| D606 | 2026-10-02 | **One SDK shape in every language**: a `Loams` client object with namespaced modules (`vector`, `search`, `sql`, `streams`, `tables`, `graph`, `live`, `durable`, `jobs`, `git`, `systemone`, `bot`, `admin`, ...). The module and method surface is **generated from proto annotations** (`loams/options/v1/options.proto`) by a buf local plugin `protoc-gen-loams-facade` with per-language templates; only the runtime (transport, auth, retry, errors, token store, pagination) and typed builders are hand-written. Fallback: a hand-written facade for one language if the generator is too costly there | Thirteen hand-wrapped surfaces drift; generation is buy-not-build for the repetitive part | Proposed |
| D607 | 2026-10-02 | **Node-to-node HTTP becomes `loams.internal.v1` on the cluster listener**, excluded from public docs and every SDK (a separate buf module) | Internal contracts must not freeze as public ones | Proposed |
| D608 | 2026-10-02 | **SDK auth**: a `TokenSource` abstraction with `ApiKey`, `Static`, `OidcExchange` (RFC 8693 to the instance's token endpoint; a person signs in through Authentik and the gateway exchanges the token, D447/D449), `WorkloadIdentity` (agents, §19 §5.2 flow 1) and `Env`; one refresh and retry on `token_expired`; bearer in the `Authorization` header only | One auth story, as §19 and §38 | Proposed |
| D609 | 2026-10-02 | **Consistency tokens**: returned in the response message and in the header `loams-consistency-token`; accepted as `consistency` (`STRONG` default, `EVENTUAL`, `AT_LEAST{token}`); an optional session token store merges returned tokens and attaches them to later reads | Read-your-writes without threading tokens (§05 §5) | Proposed |
| D610 | 2026-10-02 | **Retries and idempotency**: retry class comes from the proto (`NO_SIDE_EFFECTS` and `IDEMPOTENT` retry on `UNAVAILABLE`, pre-response `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED` with `RetryInfo`); mutations retry only with an `idempotency_key`, which the SDK generates (UUIDv7) once per logical call and reuses on retries; capped exponential backoff with full jitter (100 ms, x2, cap 2 s, 3 retries); streams reconnect with their cursor | Safe retries on flaky networks (D437, AP0 rules) and M1.6 Ruling 5's numbers | Proposed |
| D611 | 2026-10-02 | **Errors**: Connect/gRPC code plus `google.rpc.Status` details and `loams.errors.v1.ErrorInfo.reason` (stable `snake_case`, registered in `docs/api/reasons.md`, never renamed within a major version, enforced by a test); SDKs raise a typed `LoamsError` hierarchy with `code`, `reason`, `metadata`, `hint`, `retry_info`, `field_violations`, `request_id` | Callers branch on reasons, not messages | Proposed |
| D612 | 2026-10-02 | **Languages: every language gRPC officially supports** (13, verified at grpc.io 2026-10-02): TypeScript/JS, Python, Go, Rust, Swift, Kotlin on **Connect**; Java, C#, Ruby, PHP, C++, Objective-C on **gRPC**; Dart on Connect if `connect-dart` is maintained and passes conformance, else gRPC. A Connect library with no release in 12 months or failing conformance falls back to gRPC. **Supersedes the "Java SDKs deferred" ruling for generated clients** | The owner: all languages gRPC supports generating clients for | Proposed |
| D613 | 2026-10-02 | **Ruby and PHP also ship a Connect-unary transport** (HTTP POST of JSON over `Net::HTTP` and PSR-18) for hosts without the gRPC native extension; unary RPCs only; same protos and messages, so it is not a second API | The native gem and extension are the top install failures for these ecosystems | Proposed |
| D614 | 2026-10-02 | **Waves and Objective-C**: wave 1 TypeScript, Python, Go, Rust; wave 2 Swift, Kotlin, Java, C#; wave 3 Dart, Ruby, PHP, C++, Objective-C. Objective-C ships generated sources and a SwiftPM target, **not CocoaPods** (trunk read-only from 2026-12-02) | A priority order, not a gate; avoids a dead distribution channel | Proposed |
| D615 | 2026-10-02 | **Pipeline and publishing**: `buf generate` with pinned remote plugins per language (`sdks/<lang>/buf.gen.yaml`); drift check on committed output; publishing from GitHub Actions on tags `sdk-<lang>-v<semver>` with trusted publishing where the registry has it (crates.io, PyPI, npm, RubyGems, NuGet, pub.dev), token plus GPG for Maven Central, git tags for Go and SwiftPM, a webhook for Packagist; ties into #254 | Reuses the release issue; no long-lived secrets where avoidable | Proposed |
| D616 | 2026-10-02 | **Versioning**: `buf breaking` (`FILE`) against the last release tag for every package not marked `unstable`; breaking changes need a new `vN` package served alongside for one minor; semver per SDK, independent of the server; each SDK records its proto revision and supported `api_versions`, checked by `GetInstance` | Wire stability with independent client cadence | Proposed |
| D617 | 2026-10-02 | **Conformance**: shared fixture corpus (`sdks/fixtures/`) run through each SDK's public facade against `loams dev` (primary) and `loams-apps-mock` (fault injection); `connectrpc/conformance` per release for Connect libraries; a language is publishable only at 100% of required fixtures | The same behaviour in 13 languages is tested, not assumed | Proposed |
| D618 | 2026-10-02 | **Docs**: the API reference is generated from the proto comments (protoc-gen-doc family) and rendered on loams.dev with curl and SDK snippets taken from the tested fixtures; reasons catalogue in `docs/api/reasons.md` | Examples that cannot rot | Proposed |
| D619 | 2026-10-02 | **Mirror repositories** for registries that need a repository root: `ostrium-labs/loams-go` (vanity `loams.dev/go`), `loams-swift`, `loams-php`, written only by an `sdk-mirror` workflow from `sdks/<lang>/`; everything else publishes from this repository | SwiftPM, Packagist and clean Go module paths need root-level manifests | Proposed |
