# Pending log for §41 (Loams Multitenant BYOC Control Plane with GitOps)

Staged 2026-10-02 so the decision log, the READMEs and §12 are not edited from this branch. Paste each block into the file named in its heading at merge, renumbering if D540–D559 or Q540–Q559 were taken meanwhile. D540, D541, D548 and D550 are the owner's own ruling of 2026-10-02 ("in open-core, multi-tenant Knative and GitOps using Argo CD is fully open source, so name it as Multitenant BYOC Control Plane with GitOps, and move the commercial API and metering to private, because they may be used to abuse by agents — integrity is the security principle of Loams"). The other rows apply it with defaults chosen under the owner's "do suggested for all" and are **Proposed** until confirmed.

## Decisions (paste into `docs/design/13-decision-log.md`, Decisions table, after D459 and the pending blocks before it)

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D540 | 2026-10-02 | **The Loams Multitenant BYOC Control Plane with GitOps is open source** (§41): multi-tenancy (orgs, namespaces, isolation, quota enforcement), Knative Serving and Eventing, Argo CD GitOps with Clever Cloud's operator fork and tooling, Authentik identity, and BYOC install and management into a customer's own cluster or cloud. Everything needed to run a multi-tenant BYOC deployment is Apache-2.0 in this repository. Amends D220, D221, D403 and D440 where they kept the multi-tenant control plane private | The owner's ruling: "multi-tenant Knative and GitOps using Argo CD is fully open source, so name it as Multitenant BYOC Control Plane with GitOps" | **Owner ruling** |
| D541 | 2026-10-02 | **Integrity is the security principle** of the boundary: figures that set what a tenant pays, and APIs that spend money, must not have their producers or validators open to manipulation by agents or tenants (forged usage, replayed or under-reported meters, scripted abuse of paid endpoints). The open repository exposes only generic observability (OpenTelemetry metrics, logs and traces) and quota enforcement, never billing-grade metering | The owner: "they may be used to abuse by agents — integrity is the security principle of Loams" | **Owner ruling** |
| D542 | 2026-10-02 | **Scope and shape of the open control plane**: crates `loams-control` (operations and limits APIs, `loams.control.v1`), `loams-byoc-agent`, `loams-meta-remote` (D64) and the existing `loams-operator` (D185); all in this workspace with path-filtered CI jobs and no new dependency in `loams`'s default build; Apache-2.0 | One repository keeps the contracts and the conformance suites together; adoption | Proposed |
| D543 | 2026-10-02 | **BYOC connection**: an outbound-only agent enrolled with a one-time token, a CSR and a 24-hour client certificate scoped to one `cluster_id`; mTLS HTTP/2 heartbeat and command streams; a closed typed command set (`Pause`, `ResumeRollout`, `Report`, `RotateCertificate`, `SetLimits`), never a shell or a `kubectl` passthrough; Argo CD or Flux in the cluster pulls Git; an `observe-only` mode and an air-gapped mode with no agent. The control plane holds no credentials into a customer's cluster. D64's two modes and its data boundary stand (§41 §7) | The customer opens no inbound port; a stolen certificate is bounded | Proposed |
| D544 | 2026-10-02 | **Tenant onboarding is a Git commit** (§41 §6): the control plane records the org in the `ControlStore` with an outbox row; a Git writer renders `tenants/<org>/…` deterministically; an Argo CD `ApplicationSet` (Git directory generator) creates one `Application` per org per placed cluster; `loams-operator` reconciles the Kubernetes namespace, `NetworkPolicy`, `ResourceQuota`, `LimitRange`, Authentik group and OpenFGA tuples and reports status; the directory entry becomes `active` only after the operator reports `Ready`. Namespaces with no Kubernetes footprint are directory records with no file in Git. The control plane never applies objects to a cluster itself | GitOps is the only write path; Argo CD's object count stays O(orgs) | Proposed |
| D545 | 2026-10-02 | **Upgrade waves** (§41 §8): release **channels** `canary`, `early`, `stable`; **rings** across clusters (ring 0 canary, ring 1 `early`, ring 2 `stable` in batches of at most 10%, BYOC inside the customer's maintenance window); promotion by fast-forwarding the next channel branch only after the previous ring's gate passes; a release declares `compatibleWith` and the operator refuses version skew beyond it; expand-then-contract migrations; rollback is a revert; `noDowngrade` markers for stateful components. Rings are distinct from Argo CD sync waves, which order components inside one cluster | Safe, observable rollout across many clusters and BYOC | Proposed |
| D546 | 2026-10-02 | **Quota enforcement without metering** (§41 §9): the limits record (D65, D98, D86, §38 D443) with a **limits API** as the one writer interface; enforcement by in-memory token buckets and semaphores, the operator's `ResourceQuota` and Knative `max-scale`; counters exist only for enforcement and are approximate, non-durable and never shared as usage. **Setting** limits per plan is `loam-platform`'s plan mapping, which writes through the limits API; if it is down, the last limits stay in force | An agent that games an enforcement counter gains a little throughput and cannot lower a bill | Proposed |
| D547 | 2026-10-02 | **What stays open in observability** (§41 §10): the metric families of §27 §3.1, OTel traces and logs, the cgroup layout and pod labels (without the final-read acknowledgement), Envoy access logs and the gateway-set `x-loams-tenant`, quota counters and read-only enforcement state (`limit`, approximate `used`, labelled not billing-grade). The test: could a charge depend on this value, and could a tenant or an agent profit from forging it? D103's rows are exposed as "namespace statistics" | Useful to every operator; none claims to be billing-grade | Proposed |
| D548 | 2026-10-02 | **Billing-grade metering moves to `loam-platform`** (doc 06 there, authoritative): `loams.meter.v1`, per-invocation host reports and the node-local socket, the buffering, resend, dedupe and acknowledgement rules, the `SandboxFinished` final-read guarantee, the usage reporter (RN1 Tasks 1 and 2), the Lambda usage header, cap and `REPORT` parser, the CloudEvents meter form, provider reconciliation and `GET /v1/orgs/{org}/usage`. §27 keeps one-paragraph stubs. Supersedes the parts of D201 and D376 that specify these | Integrity (D541) | **Owner ruling** |
| D549 | 2026-10-02 | **`InvocationObserver`**: a Rust trait in `loams-runner`, called with a plain struct (org, namespace, function, runner kind, wall and CPU as measured, outcome) at the end of every invocation by the supervisor's runner adapter and by `RunnerHost`; no wire format, buffer or persistence. It feeds the open `loams_runner_*` metrics; `loam-platform`'s private implementation plugs in at link time. `KnativeRunner` and the supervisor report through it too, with no usage payload they did not measure | The seam between open and private without a billing format in the open repository | Proposed |
| D550 | 2026-10-02 | **Commercial APIs are private**: the hosted Loams Cloud's paid APIs (signup with a plan, plan changes, entitlements, credits, invoices, billing-grade usage), the marketplace install and billing APIs, and partner and commercial integrations (the protocol gateway, the Cloudflare target). The open operations API has **no endpoint that creates a charge, changes a plan or reads billing-grade usage**, and on the hosted cloud it is never exposed to tenants | Integrity (D541): paid endpoints must not have open, scriptable validators | **Owner ruling** |
| D551 | 2026-10-02 | **The dependency runs one way** (D202 restated): nothing here requires `loam-platform`; the platform consumes the operations API, the limits API, the tenants repository, `InvocationObserver`, OTel, the cgroup layout and pod labels | D202; the boundary | Proposed |
| D552 | 2026-10-02 | **A CI guard**, `scripts/ci/no-metering.sh` (MT4 Task 8): fails if `loams.meter`, `meter.sock`, `HostReport`, `x-loams-usage` or `loams_meter_` appears outside an allowlist (the decision log and design notes that record the move). A second check fails if any crate depends on a path or registry package named `loam-platform*` | The boundary is kept by machine, not memory | Proposed |
| D553 | 2026-10-02 | **Identity features move to the open column**: SCIM provisioning through Authentik's open-source SCIM, enforced org-wide SSO as an Authentik flow policy, and cross-org **operator** admin (a relation on the control plane's own root object, never held by agent principals). Hosted audit UI, long tamper-evident retention and legal hold, SIEM export and compliance packs stay private. Amends D221 | A multi-tenant operator needs them and Authentik's open edition supplies them (§38 §4.2); "no SSO tax" | Proposed |
| D554 | 2026-10-02 | **Hosted-only operations stay private**: predictive pre-warming and capacity management of the hosted fleet, hosted Neon/WeSQL fleet automation, abuse and trust and safety for the paid cloud, the internal admin console, support tooling, runbooks. The mechanisms they use (NetworkPolicy, egress policy, autoscaling via Karpenter and Knative) are open | They exist only to sell and operate the hosted cloud | Proposed |
| D555 | 2026-10-02 | **The open console gains an operator view** of orgs, namespaces, clusters, BYOC enrolments, rollouts, rings and enforcement state. It has no billing pages; the hosted console with billing is `loam-cloud` (private) | An operator needs to see the system they run | Proposed |
| D556 | 2026-10-02 | **RN1 is cut down**: Tasks 1 and 2 (`loams.meter.v1`, `loams-meter`) and Task 5's usage header, cap and `REPORT` parser move to `loam-platform` (doc 06); Task 3 keeps `Runner`, `RunnerHost` and the conformance kit with `InvocationObserver` in place of the reporter and the one-reporter rule; Task 4 keeps `ProcessRunner`; Task 5 keeps `loams-lambda-bootstrap` and `loams-runner-lambda` for deploy and invoke without usage; Q366 passes to `loam-platform` (default: bill Lambda by billed duration). `Usage` in the trait stays as plain measurements for metrics. MT2 Task 4 is amended in step | RN1's usage reporter produced the billing-grade record | Proposed |
| D557 | 2026-10-02 | **The hosted Loams Cloud is the open control plane plus a private commercial layer** (`loam-platform` doc 07, PD69): every tenant-facing request reaches a commercial API that checks identity, plan and entitlement and then calls the open operations API with a service credential | One code path for self-hosters and the hosted cloud; the paid surface is separate | Proposed |
| D558 | 2026-10-02 | **Exit gate for MT4** (§41 §14): on k3d in CI, create an org and namespace and see the commit, the `Application`, the namespace with `NetworkPolicy` and `ResourceQuota`, and the directory entry `active`; enrol a second cluster as BYOC and onboard a tenant there; promote a release through ring 0 and fail a gate on purpose to see promotion stop; exceed a limit and receive 429 with no usage record written; and the guard of D552 passes | Proves the three new mechanisms and the boundary | Proposed |
