| D460 | 2026-10-02 | **Loams Software Factory is the loop; Loams Bot is the single chat that drives it** (§39 §1). The loop: signal (error or analytics anomaly), triage in Zulip, issue in Plane, branch, PR and CI in Forgejo, deploy, observe in GlitchTip, OpenPanel, Langfuse and OpenObserve, back to the start. New track **SF**, plans SF1 to SF5. Phase 1 is Zulip, Plane and Forgejo in full; phase 2 is GlitchTip, OpenPanel, Langfuse 4 and OpenObserve | The owner's direction of 2026-10-02: Slack, Jira, GitHub parts first | Proposed |
| D461 | 2026-10-02 | **Embed rule**: native, API-driven panels (from `loams.collab.v1`: cordis plugins in the browser console, native GPUI panels in the desktop app, SwiftUI and Compose views on phones) for the objects the loop reads and writes, and the app's own web UI for depth: framed unmodified in the browser console, opened in the system browser or an optional in-app sidebar browser on the desktop. Per app: Zulip, Plane, Forgejo, GlitchTip native panels plus the full UI; OpenPanel tiles plus the full UI; Langfuse and OpenObserve the full UI plus links (§39 §3.2). **Mobile does not embed**: native views, sealed push, and deep links that open the system browser | Rebuilding a diff viewer, a chat client or a trace explorer is not buying; the loop only needs the objects | Proposed |
| D462 | 2026-10-02 | **Embedding is edge configuration, never a patch**: apps on sibling subdomains of one domain; the edge removes `X-Frame-Options`, sets `frame-ancestors` to the console origin, leaves cookies and the rest of each CSP alone; the browser console's `frame-src` lists only the instance's app origins (the desktop and phones load apps top-level, so frame headers concern the browser console only); CI asserts each pinned image frames from the console and nowhere else (§39 §3.3) | Keeps AGPL §13 and GPL distribution duties unengaged; D476; cookies stay same-site | Proposed |
| D463 | 2026-10-02 | **SSO through Authentik** (D404): native OIDC for Zulip, Forgejo, GlitchTip and Langfuse (verify); Plane through the Forgejo-chained Gitea provider (§22 §5); OpenPanel and OpenObserve have no free OIDC (OpenObserve's SSO and RBAC are enterprise-only, verified 2026-10-02), so they sit behind Authentik's proxy outpost with one service user per app and no per-person identity in the app. Embeds never receive Loams tokens | Free editions only (D220, D404); honest about the gap | Proposed |
| D464 | 2026-10-02 | **Desktop: native panels first, deep UIs in the system browser, an in-app sidebar browser optional.** Loams Desktop is a fork of zeron (MIT; Rust on GPUI), per the owner's ruling of 2026-10-02 and §37 as amended for a native desktop (D440-series pending), so there is no Tauri webview, CSP or `net_fetch`. App UIs reach the desktop as native GPUI panels over `loams.collab.v1`, and as top-level pages in the system browser (SSO is the person's browser session); an in-app sidebar browser (a wry-based webview in GPUI, per-app data stores, navigation allowlist, no host bridge) ships on an OS only if SF1's spike shows it works there (§39 §3.4) | zeron's workspace has no webview crate; the factory needs only the objects; a top-level page is never framed | Proposed |
| D465 | 2026-10-02 | **A2A 1.0 between Loams Bot and the platform agents; Connect-RPC from the apps to Loams Bot.** A2A 1.0.0 is a Linux Foundation project; official SDKs for Python, JavaScript, Java, .NET, Go and Rust, none official for Kotlin or Swift (verified 2026-10-02), so phones and desktop never speak A2A (D420). Agents serve HTTP+JSON and JSON-RPC with SSE on axum; no gRPC and no tonic. Loams Bot also has an A2A server, disabled by default (route and card exist only with `--bot-a2a`, Q469) | Matches the spec and the SDKs that exist; keeps one client protocol | Proposed |
| D466 | 2026-10-02 | **One agent per platform, each a separate A2A server and its own `agent` principal**: `zulip`, `plane`, `forgejo` (SF2), `glitchtip`, `analytics` (SF5). Each serves a JWS-signed Agent Card (RFC 7515, RFC 8785), runs as a Knative service (in-process in `loams dev`), and holds no app credential: a credential broker injects it per call (§39 §5.4, §5.5, §6) | Least privilege and attribution; the loop can suspend one agent | Proposed |
| D467 | 2026-10-02 | **An A2A task is a §21 operation**: `contextId` is the chat thread or factory run, `taskId` is the operation id (D146), states map one to one, `INPUT_REQUIRED` carries a question or an approval (D435: an approval is a person's decision), `AUTH_REQUIRED` missing or revoked app credentials with an admin link, push-notification configs deliver to Loams Bot's receiver and become D436 sealed pushes, `messageId` is deterministic for idempotent replay (§39 §5.3) | One lifecycle for the console, chat and agents | Proposed |
| D468 | 2026-10-02 | **Approvals reuse §19 and §21 unchanged**: every skill declares `read`, `write` or `destructive`; the org's factory policy maps (agent, skill, environment) to allow, approve or deny; the gate is enforced in the credential broker with a hash-matched settled approval, not in the prompt; Loams Bot has no path to decide an approval or answer a question not marked `answerable_by_orchestrator` (§39 §8) | A prompt-injected agent still cannot get a credential | Proposed |
| D469 | 2026-10-02 | **Identity**: each agent is an `agent` principal (§19 §5.1); Loams Bot exchanges the user's token for an audience-bound, attenuated, actor-chained token per agent (RFC 8693, `act` = user, loams-bot, agent; 15-minute cap); Agent Cards declare OAuth 2.0 with the Loams gateway as authorization server; app identities are provisioned by the §22 sagas and appear as named bot users in each app (§39 §6) | §19 §5.2 flow 3; attribution in both Loams and the apps | Proposed |
| D470 | 2026-10-02 | **Tracing**: OTel GenAI spans from the AI gateway and the durable steps, with `a2a.task_id`, `a2a.context_id`, `factory.run_id`, `resonate.promise_id` and one W3C `traceparent` across A2A hops; one collector sends LLM spans **with content to Langfuse 4** and all signals **without content to OpenObserve** and to Loams's own OTLP ingest (D73, Q43) (§39 §9) | Content in one place with masking; everything else free of prompts | Proposed |
| D471 | 2026-10-02 | **MCP is for tools, A2A for delegation.** Loams Bot talks only A2A to the platform agents and calls no platform tool; agents use REST or MCP inside their own boundary; no MCP tool writes to an app; §30's rule that destructive tools are never MCP tools stands (§39 §5.6) | Stateless calls versus stateful tasks with lifecycles | Proposed |
| D472 | 2026-10-02 | **`factory.run` is a Resonate workflow** on §21, one per `(fingerprint, generation)`: intake, triage, plan, fix, review, deploy, observe, close; each stage a durable step with an idempotency key, a guard check and a gate; waits are promises (a human decision, CI webhook, approval, rollout event) or durable sleeps (§39 §10) | Crash-safe and replayable, using the engine Loams already ships | Proposed |
| D473 | 2026-10-02 | **Safety rails in the engine**: per-run and per-org budgets (tokens, money, wall time, attempts, open PRs, runs) checked before every stage and A2A call and backed by the AI gateway's hard cap; a kill switch by scope (run: Live flag, cancel that run's tasks and workflows, no principal suspension; agent: also suspends that agent's principal; org: suspends all of the org's agent principals); generation cap 2 and a fingerprint cooldown; **no auto-merge and no auto-deploy by default** (every merge and deploy needs an approval unless the policy lists the repository, path or service and the environment is unprotected; never in protected environments); audit events for every command (§39 §11) | Autonomy needs a short leash that does not depend on the model behaving | Proposed |
| D474 | 2026-10-02 | **A factory run is a record**: Live table `factory_runs`, stream `factory_events` (CloudEvents `io.loams.dev.factory.*.v1`), audit events as OTel logs (D100), and console and phone views (runs, run detail with a stage graph, approvals, agents, policy and budgets, kill switch); the record holds links and summaries, never model content (§39 §12) | The owner wants the loop visible and stoppable | Proposed |
| D475 | 2026-10-02 | **Open-core split (D220 stands)**: open here: the A2A host and adapters, the five agents, the cordis plugins, `loams.collab.v1`, the Loams Bot service and clients, and a single-organisation factory installable with Helm (`deploy/factory/`). Commercial in `loam-platform`: the hosted multi-tenant factory, managed agents and model costs, the marketplace and its listing, billing and metering. OSS emits business CloudEvents only (§39 §14) | Adoption plus VC funding: self-host for one org stays open | Proposed |
| D476 | 2026-10-02 | **The apps run unmodified from official images pinned by digest**: Zulip (Apache-2.0), Plane Community Edition (AGPL-3.0, no paid-edition code or keys), Forgejo (GPL-3.0-or-later), GlitchTip (MIT), OpenPanel (AGPL-3.0), Langfuse (MIT, `ee/` never enabled), OpenObserve open-source edition (AGPL-3.0); licences and obligations in §39 §4, enforced by `images.lock` and `LICENSES.md` in CI | Mere aggregation; no AGPL or GPL duty is triggered without modification | Proposed |
| D477 | 2026-10-02 | **Coding is a skill of the Forgejo agent** (`propose_patch`): a sandboxed coding session on a workspace branch (§15 D24, §36), returning a patch the agent turns into a branch and PR; the model is configurable, DeepSeek through the AI gateway by default. Promotable to its own agent without changing the loop | Existing sandbox machinery; one fewer public agent | Proposed |
| D478 | 2026-10-02 | **Loams Bot in the apps**: the server-side loop is the DeepSeek harness core run headless as a supervised child process of the Rust `loams-bot` service (a thread is a durable execution), with a `subagent-a2a` provider patterned on `subagent-acp`. **Desktop: Loams Bot is a new `Harness` in zeron's engine** (`loams-harness-bot` over `loams.bot.v1`), so zeron's conversation, composer, sidebar and trajectory UI show it, plus GPUI cards, approvals and factory views; zeron's own sync is not used. Browser console: `@loams/plugin-bot`, a cordis port of the DeepSeek harness's conversation UI. Phones: native SwiftUI and Compose chat. Deep links `loams://app/…`, `loams://bot/…`, `loams://factory/…` navigate only (§39 §13, SF3) | Buy, not build; the owner's zeron ruling; D420 and D421 | Proposed |
| D479 | 2026-10-02 | **The marketplace is commercial and private** (`loam-platform` doc 05, PD47 onward): Loams Software Factory is listing #1; the open repository ships only the installable package (chart, catalog patch, manifest) so a self-hoster installs the same thing by hand (§39 §14) | D220; the owner's "first in our Cloud marketplace page" | Proposed |
