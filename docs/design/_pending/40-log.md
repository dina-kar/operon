## Decisions (paste into `docs/design/13-decision-log.md`, Decisions table, after D519)

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D520 | 2026-10-02 | **Loams SystemOne is a decision primitive of the platform**, open source: a Rust crate `loams-systemone`, the Connect service `loams.systemone.v1`, the HTTP route `POST /v1/systemone`, a CLI (`loams systemone …`), a read-only MCP tool, and the desktop integration. Models are typed-question encoders that answer in one forward pass with no generated tokens (`choice`, `score`, `noul`); Laya (Apache-2.0 code and weights, verified 2026-10-02) is the model we buy. New track **SO**, plans SO1 and SO2 (§40) | §39's A2A agents need fast local triage, routing and urgency; buy over build | Proposed |
| D521 | 2026-10-02 | **The HTTP wire is a superset of Jev's documented JSON (and `laya-serve`'s)**: same path, request and response fields, so a client that uses only those works by changing a base URL; divergences from `laya-serve` are tabulated in §40 §4.2. It is a separate dialect from ProtoJSON (translated once in `wire.rs`). Option order: the list forms are canonical, map order is preserved as received. Loams adds optional request fields (`backend`, `lang`, `min_confidence`, `locality`, `max_len`, `head_max_len`) and a response block `loams` (backend, checkpoint, revision, device, locality, latency, calibration, warnings, route reason) plus `calibrated_confidence` per answer. Limits equal `laya-serve`'s (2 MiB, 50 000 characters, 64 questions, 100 options, 32 levels, 512 options). `routing`, `action` and `act_probability` are not exposed (§40 §4) | Interoperability without a new client; the verified Laya docs define every field | Proposed |
| D522 | 2026-10-02 | **`noul` and `score` are native on every backend.** The note's "map them onto choices for Jev" is dropped: Jev documents all three primitives (docs.typesafe.ai, 2026-10-02). Laya's `noul` can follow its `false:`/`true:` labels instead of the state (upstream issue 156), so each Laya checkpoint carries `noul_mode = native \| choice_ab`; the self-test detects a stuck checkpoint and switches it to a two-option `choice` with neutral keys `A` (yes) and `B` (no), with a warning | Verified correction; handle the real quirk inside the adapter | Proposed |
| D523 | 2026-10-02 | **One trait, `DecisionBackend`, and a registry** (`BackendId` = `LayaCoreml`, `LayaTorch`, `LayaNative`, `LayaMlx`, `LayaWasm`, `LayaOnnx`, `Jev`) with a `Capabilities` descriptor (locality, question types, option caps, checkpoints, languages, context windows, widenable budget, truncation reporting, batch). Backends do inference only; **calibration, abstention, stripping of `act_probability` and provenance are applied once above the trait** (§40 §5) | No adapter can forget policy | Proposed |
| D524 | 2026-10-02 | **Selection order**: per-request `backend` beats `LOAMS_SYSTEMONE_BACKEND` beats auto-detection by `HostProfile`; `LOAMS_SYSTEMONE_FALLBACK` is tried once, only for retryable errors and only where locality allows. Auto: Apple silicon to Core ML; NVIDIA to `laya-serve` on CUDA; otherwise `laya-native` if SO1's spike passes, else `laya-serve` on CPU; browser to the instance's route. A GPU that silently fell back to CPU is `Degraded`, found from the sidecar's `/health`, not guessed | The note's order, with readiness and locality added | Proposed |
| D525 | 2026-10-02 | **Routing rules** (pure, table-tested): **locality default LOCAL_ONLY**, cloud only on request and instance consent and a key, and a forced cloud backend with local-only data is an error; over 32 options exclude Core ML; over 100 options is rejected at validation for every backend (`laya-serve`'s cap); over about 20 options warn and prefer a widened `head_max_len`/`max_len` (upstream's fix) locally, Jev only if cloud is allowed; an omitted locality (`LOCALITY_UNSPECIFIED`) means local only; **non-English or undecided text goes to the multilingual checkpoint** and English-only backends are excluded for it; a truncated state is reported and never silent (`on_truncate = warn \| widen \| error`) | The verified Laya limits (Banking77 0.425 vs 0.870; Khmer 0.000 at 0.952 confidence) | Proposed |
| D526 | 2026-10-02 | **`laya-serve` is a supervised loopback sidecar with a generated key**: `LAYA_HOST=127.0.0.1`, a held free port, `LAYA_API_KEY` random per launch in the environment only, `LAYA_DEVICE=cuda` on NVIDIA, `LAYA_THREADS` = physical cores, `LAYA_REVISION` and digests pinned from our lock; installed by `uv` into `$LOAMS_HOME/systemone/venv` with hash-pinned requirements, only with consent; the adapter refuses non-loopback addresses (D111). Python is not embedded (no PyO3) | `laya-serve` binds 0.0.0.0 without auth by default (verified); same reasons as §37 §18.3 | Proposed |
| D527 | 2026-10-02 | **In-process Rust is spike-gated.** SO1 Task 0 tries, in order: `kevala` (Apache-2.0; native CPU CLI and WASM; a git dependency pinned to a commit), then `ort` (2.0.0-rc.13 is still a release candidate) with our own port of Laya's request template and head, then nothing (CPU users run the Python sidecar). Gates: parity within 0.02 probability with `laya-serve`, native CPU p50 under 150 ms for a short state, `cargo deny` clean. The `ort` port needs the owner's go-ahead | Buy first; the cost of a port is template parity, not the runtime | Proposed |
| D528 | 2026-10-02 | **macOS: a Swift sidecar, `loams-coreml`, in `loams-desktop/sidecars/coreml/`**, built on `FluidInference/FluidUse` (Apache-2.0; `LayaManager`; macOS 14+) pinned by revision (or the Laya files vendored with their notice, Q525), speaking `laya-serve`'s JSON over a mode-0600 Unix socket with a per-launch key. Models are `FluidInference/laya-coreml` buckets fetched by our model manager. 32 options per question, multilingual only, truncation reported. Signed and notarised with the app | No server ships upstream; this is the one piece of new code | Proposed |
| D529 | 2026-10-02 | **MLX is optional and off in v1.** The code is `mizorewww/laya-mlx` (Apache-2.0, independent, Python; weights `aac6fef/laya-mlx`), not `aac6fef/laya-mlx` on GitHub as the note wrote, and it supports English **and** multilingual checkpoints. Its value is the English checkpoint on a Mac (Core ML has only multilingual). Added in SO2 Task 9 behind a wrapper we own, labelled "unofficial port", only if Q522 says the gap matters | Verified correction | Proposed |
| D530 | 2026-10-02 | **Browser: the server route by default; local inference is an opt-in cordis plugin** (`@loams/plugin-systemone-local`) running official `laya-ts` (Apache-2.0, onnxruntime-web WebGPU, single-threaded WASM fallback) in a plain Web Worker, or kevala. `nvkudva/laya-web` has no licence and is not used. The console never enables COEP (it frames app UIs, §39 D462), so threaded WASM is not offered: an isolated iframe cannot live in a non-isolated page. **cordis is the console's plugin framework (§37 D422), not an inference engine**: the answer to the note's open question 1 | The note's Q1; licence and header facts verified | Proposed |
| D531 | 2026-10-02 | **Jev is an adapter, off by default**, bring your own key; `https` required for non-loopback hosts and no redirect carries the key; **Jev outputs are never used as training, calibration or decision-log labels (TypeSafe's Master Customer Agreement forbids distillation and standalone service offerings)** (OS keychain on desktop, secret store on a server), `locality: ALLOW_CLOUD` per call and an instance switch; never an automatic fallback for private data; sends only `{model, state, questions}`; no body logging; circuit breaker. A Loams-hosted pass-through is not planned (it would be a standalone service under the MCA, 2026-09-28; D539). | Open core (D220); honest about the unknown terms | Proposed |
| D532 | 2026-10-02 | **Calibration is Loams's job**: a temperature per (checkpoint **revision**, question type, option-count bucket 2, 3-4, 5-8, 9-20, 21-32, 33+) fitted by `loams systemone calibrate` on labelled decisions (at least 100 per bucket), applied as `p^(1/T)` renormalised above the trait; versioned tables in `$LOAMS_HOME/systemone/calibration/`; no table ships by default and the response says `calibration: ""` | Upstream: ECE 0.466 to 0.081 after per-(type, options) fits | Proposed |
| D533 | 2026-10-02 | **A 16-case self-test** is embedded and run at backend start and on revision change (structure always; argmax only on an allowlist of cases the base checkpoint gets right; includes the `noul` stuck-label pair, a non-English pair and a truncation case); failure makes the backend `Degraded` and is reported by `/health` and `loams systemone status`; it doubles as the cross-backend parity test in CI | Base checkpoints are below the majority-class baseline on hard tasks, so asserting argmax broadly would fail honestly-working models | Proposed |
| D534 | 2026-10-02 | **Fine-tuning is the product plan; the engine only provides hooks**: an opt-in local decision log (state stored only if `log_state = true`, else a salted hash; 90 days), human-correction labels, `loams systemone export --format laya` for upstream's notebook, and `model add` for custom checkpoints with a digest. Training happens outside. First targets: Loams Bot routing, urgency and needs-person | Zero-shot 0.362 vs majority 0.461; fine-tuned 0.766 (upstream) | Proposed |
| D535 | 2026-10-02 | **Model cache**: immutable `$LOAMS_HOME/models/systemone/<backend>/<checkpoint>/<revision>/`; a compiled `models.lock.toml` with Hugging Face commit SHAs, file SHA-256, sizes, licences and notices, and mirror URLs (our RustFS, Q535); consent before download; resumable ranges to `*.part`; SHA-256 verified **before** the atomic rename and before parsing; no automatic eviction; `LOAMS_OFFLINE=1` never downloads; weights are not bundled in installers | Integrity, offline use, and Hugging Face being a single point of failure | Proposed |
| D536 | 2026-10-02 | **Confidence has one meaning in Loams**: `calibrated_confidence` (max of the calibrated distribution; `max(p, 1-p)` for `noul`). Backend-native `confidence` is returned for compatibility and never compared across backends (Laya: normalised entropy; Jev: `(n*p_max-1)/(n-1)`); `act_probability` is never exposed; `min_confidence` marks `low_confidence` and keeps the answer; **callers that act must pass a threshold** (Loams Bot starts at 0.6) | Upstream: `act_probability` has no signal; the two confidences differ | Proposed |
| D537 | 2026-10-02 | **A decision is advisory.** It may rank, route and prioritise; it **never approves, authorises, merges, deletes, deploys or grants** (§39 D468 stands). State is untrusted text and can steer a classifier. Sidecars are loopback or a 0600 socket with a per-launch key; weights are verified before parsing; no content in spans or telemetry (D470) | Prompt-injection-class risk applies to classifiers too | Proposed |
| D538 | 2026-10-02 | **Desktop integration**: the zeron fork links the small `loams-systemone` client crate through `loams-link` (not the engine, §37 §18.3), runs local first and the instance's `SystemOneService` second, owns the Model Manager and a "Decisions" settings panel (backend and reason, status per backend, sizes, residency, self-test, calibration, the Cloud section with keychain key and consent), and Loams Bot uses it for agent routing, urgency, needs-person and an LLM pre-filter, showing the decision on the thread card. A read-only `systemone_decide` MCP tool is injected like `zeron mcp`. No telemetry | The owner's "add this to our desktop app" | Proposed |
| D539 | 2026-10-02 | **Open-core split (D220)**: open here: the protos, the route, the crate, every adapter including the Jev client, the sidecar and model managers, calibration, self-test, decision log and export, the desktop integration and the cordis plugin. Commercial in `loam-platform`: a Loams-hosted SystemOne API (GPU fleet), metering and billing of decisions (OSS emits `io.loams.dev.systemone.decided.v1` counts only), managed fine-tuning and curated checkpoints, per-plan quotas | D220 | Proposed |
