# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Design documents (`docs/design`) and repository governance files.
- Design: durable execution through the Resonate protocol (§14); `arrow` segment encoding and changelog streams, adapted from Apache Fluss (§02).
- Cargo workspace, CI (fmt, clippy, tests, cargo-deny license policy).
- `operon-store`: object storage access with create-only and compare-and-swap writes, range reads, S3/GCS/Azure/local/in-memory backends from URLs, and `FaultyStore` fault injection.
- `operon-cache`: read-through RAM + NVMe byte-range cache with per-block crc32c verification.
- `operon-common`: namespace and stream id types.
- `operon-meta`: the metastore (namespaces, streams, the stream sequencer and offset index, leases with epochs, fenced pointer compare-and-swap), replicated with openraft, with the Raft log in a local redb database, snapshots in object storage, and in-process multi-node clusters.
- `operon-meta`: segment swaps (`SwapSegment`, lease-fenced), partition trimming and log start offsets (`TrimPartition`), per-stream retention (`SetRetention`), a 15-minute WAL commit window with pruning of commit records (`PruneWalCommits`), deterministic tracking of live WAL chunks and retired objects (`ForgetObjects`), an applied-index watch (`MetaNode::watch_applied`), and `MetaClient`, which follows the leader and retries.
- `operon-log`: the internal log on the `standard` WAL class: Kafka `RecordBatch` v2 records, the WAL object and segment formats (version 1, with the `encoding` field reserved), the leaderless write path (`LogWriter`), fetch with long-poll (`LogReader`), and the segmenter and retention loops.
- `operon` binary: `operon dev` and `operon standalone` run the metastore, the log and a native HTTP/JSON produce/fetch API in one process.
- `operon-worker`: the lease-based task framework: task sources, priorities, round-robin fair share across namespaces, per-task leases `task/<key>` renewed every third of their TTL and re-taken at the same epoch after a late renewal, fences and cancellation, and `run_once` for one deterministic pass.
- `operon-link`: the link framework with exactly-once apply (`LinkTarget`, `LinkApplySource`, one task per link) and the `CounterTable` test target, whose commits carry data and applied offsets under a fenced pointer CAS; `LinkGcRoots` for garbage collection.
- `operon-pk`: `PkIndex`, a fenced single-writer SlateDB per keyed object, and the read-only `PkReader`.
- `operon-log`: garbage collection (`gc::GcSource`) of retired objects, never-committed WAL objects, unreferenced segments and unreachable link objects, after a grace period.
- `operon-meta`: the link catalog (`CreateLink`), `ReacquireLease`, fences on `TrimPartition`, `PruneWalCommits` and `ForgetObjects`, `MetaState::check_invariants`, and `MetaNode::fatal_error`.
- `operon`: link endpoints (`POST /v1/namespaces/{ns}/links`, `GET /v1/namespaces/{ns}/links/{link}`); the server runs link apply and garbage collection; with the `failpoints` feature, `OPERON_FAILPOINTS` / `OPERON_FAILPOINT_HIT` abort the process at named failpoints.
- `operon-sim` (test-only): a seeded in-process cluster simulation and a Wing–Gong–Lowe linearizability checker.
- M0 exit gates: the kill -9 crash gate (`crates/operon/tests/crash.rs`), the object-store fault matrix (`crates/operon/tests/fault_matrix.rs`) and the simulation seed sweep, all in CI.
- `operon-store` / `operon-cache` (M1.1): `Store::get_range_with_info` and `RangeCache::read_with_size` (a known-size read, so a split opens with one GET).
- `operon-common` (M1.1): `CollectionId` and the collection schema types (`schema`).
- `operon-meta` (M1.1): the collection catalog: `CreateCollection` (with its implicit stream and link), `DropCollection` (retires the collection's prefixes), additive `UpdateCollectionSchema`, `UpdateAliases`, and the matching `MetaClient` methods; `ApplyError::CollectionNotFound` and `SchemaVersionMismatch`.
- `operon-log` (M1.1): `LogWriter::append_many`, which commits one request's batches for several partitions in one WAL object and one `CommitWal`.
- `operon-link` (M1.1): the link-target registry (`TargetRegistry`, `LinkTargetFactory`, `CounterTargetFactory`); links of an unregistered kind are reported by `LinkApplySource::unregistered`, never applied.
- `operon-quickwit` (M1.1): Quickwit files vendored file by file from `af0591a3` and adapted to Tantivy 0.26.2 (split bundle and footer trailer, hotcache, async directories and warmup, ES DSL → `QueryAst` → Tantivy, the doc-mapper query builder, aggregation merge glue, `StableLogMergePolicy`), with Quickwit's attribution in `NOTICE`.
- `operon-text` (M1.1): the Lucene-compatible `standard`, `english`, `simple`, `whitespace` and `keyword` analyzers with the original Porter stemmer; Quickwit's `Storage` over `operon-store` and `operon-cache`; splits that open with one ranged GET; the `OPDB` delete-bitmap format.
- `operon-collection` (M1.1): primary keys, `DocOp` and the implicit-stream record codec; value validation and ES dynamic mapping; `CollectionWriter` and `ConsistencyToken`; Lance datasets committed as detached versions over `operon-store`; the Tantivy schema mapping (JSON fields, sparse vectors); the `OPCM` collection manifest and `CollectionSnapshot` (the read API); the `collection` link target with PK-index repair, PK deltas (`OPPD`) and dead letters (`OPDL`); vector (IVF_PQ, IVF_RQ, IVF_HNSW_SQ) and `_pk` BTREE index builds as worker tasks.
- `operon-collection` (M1.1), GC and trimming: `CollectionGcRoots` (Lance reachability, splits, bitmaps, manifests, PK deltas and dead letters of the retained chain), `PkGcRoots`, GC of retired prefixes after the grace period, and `CollectionTrimSource`, which trims implicit streams below the oldest retained manifest.
- `operon` (M1.1): the server runs collection link apply, index builds, trimming and collection GC. `operon dev` gains hidden tuning flags for tests such as the crash gate: `--collection-trim`, `--collection-index-min-rows`, `--collection-index-delta-min-rows`, `--collection-retention-ms` and `--collection-index-poll-interval-ms`.
- Collection coverage in the M0 gates (M1.1): crash-gate rows for every collection commit failpoint (`collection.after_lance_commit`, `.after_split_put`, `.after_manifest_put`, `.after_cas`, `.after_pk_write`) and both index-build failpoints (`collection.index.after_lance_commit`, `.after_cas`); the fault matrix's `CollectionCommit` row; and a collection in the `operon-sim` simulation. Its workload writes upserts, patches (including patches that change nothing) and deletes through `CollectionWriter`, plus schema-invalid records appended directly, which link apply dead-letters. Its model check requires that the committed collection equals `fold_stream` of the implicit stream, that every acknowledged write is in the stream at its offsets, that every upsert and patch is there at most once (and never one of a failed write), and that the live manifest names no missing object. The crash gate starts each server child with core dumps off (`ulimit -c 0` through `sh`), so it needs a POSIX `sh`.
- `trait MetaStore` (M1.2a), in `operon-common`: the semantic metastore trait (D47), covering the whole client surface as named domain operations, implemented for the openraft `MetaClient`.
- `operon-meta-conformance` (M1.2a): the backend-agnostic `MetaStore` conformance suite (catalog, sequencer, leases, pointers, collections, GC, changes, the linearizability checker), run against the openraft single node and the in-process 3-node cluster; `metastore_conformance!` expands it for a backend.
- CI (M1.2a): the `metastore boundary` step, which fails when a downstream crate depends on `operon-meta` directly, `operon-common` gains a dependency, or downstream source names an openraft type.
- `operon-query` (M1.2): the read side of collections and the facade every gateway uses: the search IR and its JSON wire form; read views per consistency level (strong, at-least, eventual and pinned reads without a metastore hold); the in-memory tail index, which makes writes visible to strong reads before the link applies them; DataFusion operators for BM25 search with global live-only statistics, filter bitmaps, ANN over Lance with exact rescoring, exact sparse search, fusion (RRF, DBSF, weighted sum), document fetch and tail merge; aggregations, highlighting, sorting, paging, groups, counts and scroll; the hot-tier and placement hooks; `CollectionService`; a read-only DataFusion catalog with the SQL table functions `vector_search`, `text_search`, `hybrid_search` and `rrf` (`rerank` reserved for M3); an Arrow Flight SQL service; Flight `DoPut` bulk ingest into collections and streams (path descriptors with `PutAck` tokens, and ADBC `adbc_ingest`); scan plans that pin a collection's detached Lance version for external readers (D53).
- `operon` (M1.2): the native collection routes (`…/collections`, `…/fields`, `…/versions`, `/v1/namespaces/{ns}/aliases`), document routes (`…/documents`, `…/documents/get`, `…/documents/scroll`, `…/documents/count`), the hybrid query route (`POST /v1/namespaces/{ns}/query`), the SQL route (`POST /v1/namespaces/{ns}/sql`) and the scan plan route (`POST …/collections/{c}/scan`); the Flight SQL listener with `--flight-sql-listen` and `--no-flight-sql`; `--hot on|off` and the `Operon-Hot` request header.
- `operon-log` (M1.2): ranged WAL fetches: `LogReader` learns each chunk's batch boundaries and reads from the batch that holds the requested offset instead of the whole chunk.
- CI (M1.2): the nightly `sim` job also runs the tail-merge property test with 256 cases.
- Per-collection unapplied-data budget and write backpressure: HTTP 429 / `RESOURCE_EXHAUSTED` with `Retry-After`, `Operon-Unapplied-Records` and `Operon-Unapplied-Bytes` headers, the `Operon-Backpressure: off` override, `--backpressure` and `--max-unapplied-*` flags, `unapplied_bytes` and `backpressure` in `CollectionInfo` (D86).
- `operon-collection` (M1.3): background maintenance: split merges (`SplitMergeSource`, `collection-merge/<cid>`) that re-index live docs from `_source` with each split's own schema under Quickwit's `StableLogMergePolicy`, bounded at 10 M docs and 1 GiB, and Lance compaction (`LanceCompactionSource`, `collection-compact/<cid>`) committed as a detached `Rewrite`; both commit `Maintenance` manifests and rebase on conflict. `CachedObjectStore`, so Lance reads go through the range cache.
- `operon-hnsw` (M1.3): the `HnswEngine`/`HnswBuilder`/`HnswIndex`/`AppendableHnsw` traits, the `qdrant-edge` 0.8 engine (feature `qdrant`) and an exact `FlatEngine`.

Hot artifacts (the `OPHD` descriptor, the `OPHC` covered set, zstd-chunked engine files under `hot/hnsw/<column>/<source_version:020>-<ulid>/`), artifact currency and `HotBuildSource` (`hot-build/<cid>/<i>`); `HotTierImpl`, which loads artifacts on owners and serves per-manifest views with an appendable delta index; pinned splits on NVMe verified by block checksums; fragment prefetch into the range cache; budgets with per-namespace fair share, heat and demotion; lease-based auto-promotion (off by default); the node registry (`node/<id>` leases), rendezvous placement and `RemoteReadsImpl`; the hot on/off differential harness (feature `test-util`).

### Changed
- `operon-meta-conformance` (R1): a `metastore_conformance!(backend; cases = [..])` arm and `Backend::unavailable` (a case skips when its backend is unavailable). `collection_head_reads_pointer_bounds_and_clock` and `collection_roots_lists_prefixes_under_a_path` accept a clock that is not earlier, rather than equal, because a TSO clock advances with time.
- `operon` (R1): `ServerConfig.meta: MetaBackend` (`Raft` by default), and `Server::meta()` returns `Option<&MetaClient>`.
- `operon-meta` (M1.3): a new snapshot format version (the version-5 body followed by the hot configuration), written only while some collection has a hot configuration, so every earlier state still snapshots as version 5; `MetaClientConfig.apply_wait`; a 4xx answer to a metastore POST is a definite failure, and a membership request tries the remaining seeds after one rejects it.
- `operon-collection` (M1.3): `LanceEnv::with_cache`, which the server now uses; `CollectionGcRoots` keeps the hot artifacts of retained and lingering manifests; `PointerCas` and `put_manifest` are public.
- `operon-query` (M1.3): `RemoteReads::{get, count, scroll}` return the owner's read token; `HotTier::quarantine_split`.
- Workspace (M1.3): `serde_json` is built with `preserve_order` (qdrant-edge enables it), so `_source` and payload keys keep insertion order, as Elasticsearch and Qdrant return them (reverses M1.1 Ruling 23).
- `operon` (M1.3): the server runs merges, compaction and an idle hot tier by default; the `hnsw` feature (default on) builds `qdrant-edge`.
- Workspace (M1.1): `serde_json` is built with `float_roundtrip`, so `_source` floats survive exactly.
- `operon-store` (M1.1): `StoreError::is_retryable` (true for `Backend`, `AlreadyExists` and `PreconditionFailed`); `FaultyStore`'s `Precondition` fault on a create-only PUT now writes an absent object before it reports already-exists (a lost acknowledgement, as a real store would show it), and the fault matrix's `LinkCommit` and `CollectionCommit` precondition cells are re-blessed.
- `operon-meta` (M1.1): the snapshot envelope is format version 5 (the collection catalog); version-4 snapshots are rejected. Stream, link, collection and alias names starting with `_` are reserved for implicit objects; `SetRetention` refuses a collection's implicit stream, and `CreateLink` refuses an implicit stream as source and a `collection` target.
- `operon-log` (M1.1): `GcRoots::reachable` returns a `GcKeep` (objects and whole prefixes to keep, from one call), and `GcRoots` gains `object_time_ms` (the root's notion of an object's age); GC deletes everything under a retired prefix once it is older than the grace period.
- `operon-link` (M1.1): `LinkApplySource::new` takes a `TargetRegistry` (replacing the store argument and `with_hook`); `LinkError::Target`; the link endpoint shows `version` and `applied` for every registered kind.
- `operon-pk` (M1.1): a create-only SlateDB manifest write that lost a race is `PkError::Store` (retryable), not `Corrupt`.
- `operon` (M1.1): startup rejects any freshness deadline at or above `gc.grace` (`segmenter.swap_deadline`, `link.max_commit_delay`, `collection.index_commit_delay`) with `ServerError::Config` instead of clamping it; `--gc-grace-ms` also sets every freshness deadline (including the collection commit and index commit delays) to half the grace.
- `operon-log` (M0.4): the segmenter and retention run as worker tasks (`SegmenterSource`, `RetentionSource`); their background loops and `BackgroundTask` are gone. The segmenter deletes a segment it wrote only when its swap was definitely not applied. `SegmenterConfig` loses `interval` and gains `swap_deadline`.
- `operon-meta` (M0.4): the snapshot envelope is format version 4 (link catalog, incremental byte counts); `PartitionState::bytes` is O(1); `max_clock_skew` defaults to 5 min; `MetaNode::shutdown` waits for the database file to close; a snapshot upload is bounded by a total deadline (`MetaConfig::snapshot_io_budget`).
- `operon-store` (M0.4): `ObjectInfo` carries the modification time; `FaultyStore` classifies PUTs by mode, adds `Precondition` and `Delay` faults, random seeded faults (`FaultyStore::random`) and `inject_nth`.
- `operon` (M0.4): `405 Method Not Allowed` uses the JSON error body.
- `operon-meta` (M0.4 review): `SwapSegment` carries the segment's `Freshness`, and `CasPointer` an optional one. The metastore refuses a reference to an object older than its deadline with `ApplyError::StaleObject`. GC ages objects by the metastore clock. `CounterTable` manifests are named `<version:020>-<ulid>.man`, and orphaned manifests are no longer adopted.
- `operon-store`: `file://` stores fsync each written file and its directory before a write returns, so a write that returned survives power loss.
- `operon-meta`: the snapshot envelope is format version 2; version-1 snapshots are rejected. `CommitWal` carries the WAL object's creation time.
- `operon-meta`: the leader refuses commands stamped more than `MetaConfig::max_clock_skew` (default 60 s) ahead of its own clock (`MetaError::ClockSkew`). `CreateStream` carries the stream's retention. `MetaClient::inject_lost_ack` needs the `test-util` feature.
- `operon-log`: a commit rejected after an attempt whose outcome was unknown fails its appends with `CommitUnknown` (they may be committed). `LogWriter::start` validates its config and returns a `Result`. Size retention keeps each partition's newest entry. The segmenter renews its lease before swapping and never deletes a segment the metastore references or retired.
- `operon`: every error, including malformed paths and queries and bodies over 16 MiB (413), uses the JSON error body; fetch `max_bytes` is capped at 16 MiB.
- `operon-meta`: a node with no local state refuses to start when the snapshot store already holds metastore snapshots, since its data directory was most likely lost (override with `MetaConfig::allow_fresh_start_with_existing_snapshots`). Transient object-storage failures while writing or reading a snapshot are retried instead of stopping the node.
- Downstream crates (`operon-worker`, `operon-log`, `operon-link`, `operon-collection`, `operon`) (M1.2a) take `Arc<dyn MetaStore>` instead of the concrete `MetaClient`; `operon-meta` is now a dependency only of the composition roots (`operon`, `operon-sim`).
- The shared metastore types, errors and limits (M1.2a) moved from `operon-meta` to `operon_common::meta`, byte-for-byte the same on disk, and are re-exported at `operon-meta`'s crate root. `MetaError::UnexpectedReply` carries the reply's `Debug` text instead of a `Reply`, with the same `Display` text.
- The linearizability checker (M1.2a) moved from `operon-sim` to `operon-meta-conformance`, re-exported as `operon_sim::linearizability`.
- `operon` (M1.2): metastore conflicts (`VersionMismatch`, `Fenced`, `LeaseHeld`, `LeaseLost`, `SchemaVersionMismatch`) answer 409 `conflict`, and stale objects (`StaleObject`, `StaleCommit`, `IndexMismatch`) 503 `unavailable`; every 503 carries `Retry-After: 1`. A produce onto an implicit stream (`_collection.*`) checks that each record's key decodes as a primary key of its partition (400 otherwise), and the HTTP produce decodes every record before it resolves the stream.
- `operon` (M1.2): server shutdown waits at most 10 s for in-flight Flight SQL calls, then aborts them, and stops `DoPut` ingests before their next chunk.
- Per-crate integration tests are one binary (`tests/it`, module per former file) instead of one binary per file, to cut build time and disk/RAM use; `operon-collection` keeps its named-failpoint tests in a second binary (`tests/it_failpoints`, `required-features = ["failpoints"]`), and `operon`'s kill -9 crash gate (`tests/crash.rs`) and object-store fault matrix (`tests/fault_matrix.rs`) are unchanged, each its own binary.
